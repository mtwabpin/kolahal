The home screen has four parts, from top to bottom: the **header**, the **log**, the
**suggestions**, and the **prompt** (`$`), with the **key bar** below it while you type.
[Parts of the app](/getting-started/parts/) shows each one, numbered on the screen.

## The prompt

Type a command, or any part of an app name, and press Enter.

- **Commands** come first: `help` lists them all, grouped, and `help todo` shows one. See the [command reference](/reference/commands/).
- **Aliases** you defined with `alias m = open maps` expand before anything else.
- **Script commands** are scripts marked [`@command`](/scripting/overview/#command-scripts). They run by name with arguments.
- **Anything else is an app name.** Enter launches the best match, which is the highlighted first
  suggestion chip. More precisely:
  - an exact label match launches;
  - if only one app matches, it launches (`launch.single`);
  - if the top match starts with what you typed, it launches (`launch.top`);
  - otherwise you get a grid of up to 12 matching apps to tap.

  Accents are ignored (`cafe` finds *Café*). If nothing matches, a typo still finds the app: a wrong, missing or extra letter, or two swapped (`mpas` finds *Maps*; two typos once you've typed eight letters). Apps you open often and recently rank first. Each launch adds 1 to a score that halves every week, so an app you stopped using drops down even if you open it once more.
- **Instant launch** (`launch.instant`, default `all`): as soon as only one app matches what you typed, it opens without Enter. With apps *Calculator* and *Calendar*, `calc` opens Calculator
  and `cale` opens Calendar.
  `launch.instant all` also runs commands that take no arguments, and aliases, this way (`setti`
  opens settings; `contacts` waits for Enter so you can still type `contacts bob`), and makes a
  tapped history line run immediately. A line with arguments also runs once it is complete, whether typed, picked from the suggestions or tapped in the log: `torch on`, `dnd off`, `ring silent`, `media pause`. `torch o`, `volume up`
  (a number could go there instead) and `apps work` (`-l` could follow) wait for Enter.
  Sensitive commands never run without Enter: `call`, `sms`,
  `uninstall`, `clear`, `restart`, `lock`, `script`, `config`, `alias`, `work`, `private` and similar.
  Calls open the dialer, where you confirm, so a tap is enough for them: a contact tapped in the
  suggestions for `call`, or a `call` line tapped in the log, opens the dialer at once. `launch.instant-letters` (default 2) is how many
  letters to type first; `launch.instant off` turns it off. The same app in several profiles counts
  as one match (the copy you use most opens), unless two of those profiles are on: with the work
  profile running, `gm` opens nothing and suggests both Gmails (Gmail and Gmail [W]) for you to pick.
- A mistyped command gets a tappable **"did you mean"** that puts the corrected command in the prompt.
- `= <expression>` is a [calculator and unit converter](/guides/web-and-calculator/).

### Suggestions

Suggestions are hidden on an idle home screen and appear while you type (the on-screen keyboard is
open, or there is text in the prompt); `suggestions.auto off` keeps them always visible.

The suggestions above the prompt change as you type:

- **Empty prompt**: your [pinned favourites](/guides/apps/#favourites) first, then your most-used apps, ranked by how often and how recently you opened them (each launch counts as 1, halving every week).
  Off by default; turn it on with `config set suggestions.idle on`.
- **First word**: up to three matching commands, aliases or script commands, plus matching apps.
  When Enter would launch an app, that app is the first, highlighted chip, so Enter, Tab and the highlight always pick the same app. After the apps come commands and settings related to what you typed: `flash` suggests `torch`, `silent` suggests `ring`, `music` suggests `media`, and `24` suggests the 24-hour clock setting (as `config set clock.24h`).
- **Arguments**: almost every command suggests what comes next.
  - App names after `open`, `info`, `hide`, `rename`, `pin`, `shortcuts`, `notifs mute` and
    similar. After `open maps:` you get that app's shortcuts.
  - Contacts after `call`, `sms` and `contacts`: favourites first, then everyone, even before you
    type a name. A contact with several numbers shows one row per number, and choosing one fills in
    that number. In the Play build, the people you've picked ([People](/guides/people/#in-the-play-build)).
  - Script names after `script run|edit|…`, keys and values after `config`, theme and font names,
    feeds after `feed read|rm|…`, aliases after `unalias`, status lines after `status clear`.
  - The options a command's usage lists, such as `clear history|all`, `torch on|off`,
    `dnd alarms` or `apps work|personal|…`.
  - Your earlier commands that start with what you typed, so `search ` or `yt ` offers your past
    queries.

Command chips start with `$` (`$ maps`), app chips show the app name, and a ✕ at the end of the
prompt clears it. Tap a chip to use it. Tab (on a hardware keyboard, or on the key bar if you add it) inserts the first one. That chip is filled when Enter would also run it. `suggestions.max` sets the number of chips (default 30).

By default (`suggestions.style list`) the suggestions are a **list** stacked directly above the
prompt instead of chips: the best match is at the bottom, nearest your thumb, and Tab inserts it.
When Enter would also run it, it is highlighted with a ⏎: a command typed in full (`clear`, above its
options `clear history` and `clear all`), or the app Enter launches. When Enter would run the line as typed (`torch ` toggles the torch, and no row shows that), no row is highlighted. Command rows show `$ name` and the command's short
description, shortened to one line (`suggestions.wrap on` shows all of it); app rows show the profile tag. The list uses at most about 40% of the screen, and never more than the space above the prompt, so the prompt stays visible. It scrolls if there are more rows. Long-press an app row for its actions. `config set suggestions.style chips`
brings back the chip strip (`suggestions.rows` applies to chips only). In both styles each app's icon appears before its name, and commands show a terminal icon in the same place, so all names line up. **Show app icons** (`suggestions.icons`) turns the icons off. Work and private apps show the system's profile badge.

### App selector

Turn on **Show the app selector** (Settings → App selector, or `config set selector.rail on`) and, while the keyboard is closed, a slim handle appears on an edge of the log. It opens an **app selector** that you use with one thumb, without typing. **Edge** puts it on the right (the default) or the left
(`selector.side`), **Position on the edge** at the bottom (the default), middle or top
(`selector.position`), and **Length on the edge** sets how much of the edge it uses (`selector.height`). Keep it away from the back gesture. With gesture navigation, Android lets an app block the back gesture on only 200 dp of an edge, so the selector starts only from the middle 200 dp of that length, where the handle is. At the ends, the back gesture works as usual.
Once your thumb is down, you can slide over the whole length.

- **Touch the edge at the handle.** The home screen dims, and a full-height panel slides in on the other side of the screen, listing *all* your apps in one list:
  your favourites (★), then everything alphabetically, with small section letters in the
  margin (`#` holds apps that start with a digit, a symbol or a non-Latin letter), and each app's
  icon if you turn on the selector's **Show app icons** (`selector.icons`). Its **Row height**
  (`selector.row-height`, 38 dp) spaces the list out. Its **System font** (`selector.system-font`) shows the list and the letters in the system font instead of the terminal font. Hidden apps are left out, work and private apps show their `[W]` / `[S]` tags and
  paused profiles are faded. About 20 apps fit on screen at once. With the selector at the bottom of the edge (the
  default), your favourites come last, at the bottom where your thumb rests; at the middle or the
  top they come first.
- **Slide along the edge to a letter.** It moves a letter at a time, with a light vibration for each. Every letter that has apps gets an equal length of the edge, so a letter with a single app is as easy to reach as one with many. The current letter appears large in a bubble beside your thumb, and the letters around it bulge out from the edge, clear of your thumb (the list is narrower while your thumb is down), so you can see which way to go. The list scrolls to that letter's apps and stops, with the first app level with your thumb and the rest below it (moved up only enough to stay on screen). Other letters' apps fade while you slide. Near the ends of the list, the panel moves to keep the apps in place. **Show letters on the edge** (`selector.letters`) shows each letter along the edge when you aren't sliding, in place of the handle, so you can see where to touch.
- **Only that letter's apps** (`selector.filter`, off by default): the list shows only that letter's apps, beside the bubble, not the whole list scrolled to it.
- Set **Slide through** (`selector.browse`) to `apps` to move through the whole list by app instead of by letter. Your thumb's position on the edge maps smoothly to the list (top = first app, bottom = last), so small moves give fine control and a long slide covers the alphabet. Every letter gets room along the edge by the square root of its number
  of apps: a letter with four times the apps gets twice the length. The current app is level with your thumb and magnified (its neighbours a little less), and the bubble shows its letter. Slide slowly to move one app at a time: under about 100 dp per second, the list moves one app for every 10 dp of your slide, with a light vibration for each. Speed up and it catches up with your thumb.
  (Set these with `config set`: `selector.aim` and `selector.aim-speed`.)
- **Slide well off the edge, toward the panel,** and the list stops moving: move up or down to pick
  an app (near the panel's top or bottom it keeps scrolling), then **lift to launch** it. A short vibration marks leaving or returning to the edge, and a lighter one marks each app you pass. Or hold still on an app: its row fills and, after just under a second, the app launches without you lifting your thumb. Moving resets the fill. For an app's actions (the same sheet as long-pressing it), leave the list open and long-press, or turn on [actions while picking](#app-actions-while-picking) to reach them as you pick. To cancel without launching, slide back onto the edge before you lift.
- **Lift on the edge** and the panel stays open as a normal list (with **Only that letter's apps**, just those apps), with a tapped letter's apps still beside it. It widens almost to the edge, so your thumb can reach every row. Scroll it, tap an app to launch it, long-press for its actions, or slide along the edge again.
  Tap elsewhere, press Back or wait 4 seconds to close it.

Android lets an app block the back gesture on at most 200 dp of each screen edge, so only the middle 200 dp starts the selector. Above and below it, a swipe in from the edge still goes back.

#### App actions while picking

Off by default. Turn it on with `config set selector.actions far-side` and off with `off`. It isn't in Settings. It changes what lifting does once you've slid off the edge onto the
list. The third of the list farthest from your thumb's edge becomes its **far side**: slide into it and you feel a short vibration, the current row shows **⋯ Actions**, and lifting there opens that
app's actions (the same sheet as long-pressing it) instead of the app. Holding still there doesn't
launch it either. Anywhere else on the list, lifting launches the app as usual. With the selector
on the left edge it's mirrored: the list opens on the right, and its far side is its right-hand
third.

## The log

The log is split into **groups**, with a gap above each one (`log.spacing`, 0–40 dp). A group is a
command you typed and its output (a script's lines too, when you ran it), a script's or a feed's
lines from one background run, or lines that arrived together. A line that arrives on its own more than 3 seconds after the previous one, such
as a tap launch, an app install or a notification, starts its own group. A thin coloured bar beside
each line shows where it came from: green for commands, the script colour for background output,
red for errors. Hide it with `log.gutter off`. Output older than the latest command is dimmed
(`log.dim`).

- The log shows day separators. Right-aligned times appear on each group's first line and again when the minute changes (`log.time`: `groups`, the default; `commands`, only on lines you type; `off`, none).
- `help`, `config` and `script ls` render in two columns; `apps` is a grid of tappable chips.
- Script, feed and notification lines show their source at the end, dimmed (`Show HN: … · Hacker News`), on the first line of a run from that source. Lines directly below the command that ran them don't, because the command already names it. Long-press a line to see where it came from and its exact time. Lines that arrived while you were away are marked `•` under a "N new since you left"
  divider.
- **Clean screen** (`log.fresh`, 10 minutes): return to the home screen after a while and it starts clean, so old output and app grids are out of the way. Nothing is deleted: tap
  "▴ N earlier lines" to bring it back. `fresh` does the same on demand (and isn't logged itself). Script lines that arrived while you were away stay visible.
- **Daily tips** (`log.tips`, on by default): for your first two weeks, the first time you open the home screen each day, the log shows a tip about something you haven't used yet (`todo`, `remind`, `=`, `alias`…, based on the commands you typed). Tap it to put the example in the prompt. `config set log.tips off` stops them.
- When you scroll up, a ↓ button jumps back to the newest lines. Repeating a command with nothing
  printed in between (`settings`, `settings`) doesn't add another line.
- Scroll to the top to load older entries. Lines older than `log.keep-days` (60), or beyond the newest `log.keep-lines` (5000), are deleted. Typed commands are counted separately, so ↑ history is kept.
- `clear` (or `Ctrl+L`) clears the screen, with **Undo** under the log for a few seconds; then
  its lines are deleted, except your commands, which ↑ still recalls. `clear history` deletes the ↑ history but keeps the log, and `clear all` removes both.

### Searching the log

Type `/` and some words at the prompt. The log shows only the lines that contain all of them, including lines hidden by a clean screen, with the words highlighted and each line's time.
The search covers a line's text, commands you typed, and a line's source and link: `/weather` finds the weather script's lines, `/github.com` the lines that link there.

```sh
/battery              # every line about the battery
/hacker news rust     # feed items from Hacker News that mention Rust
/@xkcd                # every line from the xkcd script
/@hackernews rust     # Rust, only in Hacker News's lines
/@scripts error       # errors from any script
```

`@` and a name shows only the lines from that source: a script, a feed or an app, using the name at the end of its lines, in any case and without spaces. Or a whole kind: `@commands` (what you typed and
what it printed), `@scripts`, `@feeds`, `@notifications`, `@apps` (installs and updates), `@calls`,
`@reminders`. Typing `/@` suggests them. Use two `@` names to find lines from either.

Tap a line to see it in the log, among the lines around it. `Enter` hides the keyboard so more results fit; `Esc`, Back or clearing the prompt ends the search. Long-press and swipes work as
they do in the log.

### Filtering by source

Long-press a line and pick **Show only xkcd** (its script, feed or app; a command line offers **Show only commands**), or type `log only xkcd` or `log only feeds`. The log then shows only those lines, including new ones, with a bar above the prompt to say so. The filter stays on, even if you leave the home screen or restart, until you tap ✕ on the bar, press Back, run `log all` or run another command, so what you type always appears.

### Pipes

Filter a command's output like a shell:

```sh
help | grep feed              # rows mentioning "feed" (the description column counts too)
history | tail 5              # last five commands
feed read | grep -v sponsored | head 3
contacts | count              # how many lines
config | sort
```

Filters: `grep [-v] <pattern>` (case-insensitive regex; an invalid regex is matched literally),
`head [n]`, `tail [n]` (default 10), `sort [-r]`, `uniq`, `count` (or `wc`). A `grep` pattern that takes over a second gives an error. If it's still running, `restart` stops it. Error lines are never filtered out. Only output the command prints immediately is filtered. Output that arrives later (network requests, scripts) appears as usual. A `|` only starts a filter when a filter name follows it,
so `js a || b` and Lua code aren't affected. The spaces around it are optional, but with no space before it, the `|` stays part of a `grep` pattern, code, quoted text and text you're saving: `grep head|tail` finds
either word, and `grep feed |head 3` is a second filter.

### Tap and long-press

**Tap** a line for its main action:

| Line | What a tap does |
| --- | --- |
| A command you typed | puts it back in the prompt |
| An app line or chip | launches the app |
| A link (feed item, search, script line with a URL) | opens it |
| A phone number or contact | opens the dialer |
| A notification | opens it (or the app, if it's gone) |
| An app shortcut | starts it |
| A setup or hint line | runs its fix command |
| A script error | opens the editor at the failing line |

**Long-press** opens an action sheet with everything that applies: run again, edit in prompt, copy
output, open, share or copy a link, call, message or copy a number, app shortcuts, app info, hide,
uninstall, run or edit a script, dismiss a notification or mute its app, copy text, delete the line,
or a command with all its output (a script's lines too, which can appear later, under other lines),
and launch in another profile.

### One-handed use

- **Quick actions:** tap the `$` at the start of the prompt for everything the header offers —
  settings, notifications, alarms, battery, network, unlocks, apps, widgets, feeds, scripts, lock
  and pause / resume the work or private profile, with the header's icons (battery and network
  as they are now). You can also set any gesture to open it (`quick`).
- **Swipe a log line:** right copies it, left deletes it (with Undo for a few seconds).
- **Long-press output** to run or edit the command that printed it.
- **Two rows of suggestions** while typing (`suggestions.rows`).

## The header

A large clock and date, then unlocks, battery, network, next alarm, ⚙︎ and profile state, shown
as icons: the battery is drawn to its charge level (green with a bolt while charging, red when
low), and the network icon shows Wi-Fi, mobile or offline. `header.icons off` brings back the
text labels (`bat`, `net`, …). Every item is tappable:

| Item | Tap | Config key |
| --- | --- | --- |
| Clock, next alarm | opens your alarms | `clock.24h`, `header.date`, `header.alarm` |
| `unlocks` | runs `unlocks 7` | `header.unlocks` |
| `bat` | battery usage | `header.battery` |
| `net` | network settings | `header.network` |
| ⚙︎ | the [settings screen](/guides/themes-and-settings/) | |
| Script status lines | runs that script | `header.status` |
| `work` / `private` | resumes a paused profile; pausing asks for a second tap | `header.profiles` |

Choose what shows in **Settings → Header → Header items**: each item has a box for the full
header and one for the one-line header described below. The clock (`header.clock`) and ⚙︎
(`header.settings`) can go too, and `settings` still opens Settings. If nothing is left to show,
the header takes no room.

**Auto-hide** (`header.autohide`, on by default): while you scroll back through older output the header
disappears entirely; scrolling toward the newest lines (or running a command) brings it back as one
line, by default with the time, battery, a music note while something plays and the number of hidden status lines. Tap it or swipe down on it to expand it; pressing Home, coming back from an app or `clear`
also brings it back.

While you type (the keyboard is open, or there is text in the prompt), the header shrinks to one line, so the suggestions have more room. It returns to full size when you finish.

`header.device` adds a `name@device` line, `kolahal@device` until you set **Your name**
(`user.name`) beside it in Settings. Swipe down on the header to pull down the
notification shade (a [gesture](/guides/gestures/) you can change).

To hide the header, turn off **Show the header** (`header.show`). The log then fills the screen, you open Settings with `settings`, and script status lines aren't shown.

### The pinned header

With the header off, one line at the top of home shows what's playing (with notification access)
and what scripts pin there with [`pin`](/scripting/api/#pintext-opts), such as a live score. With
more than one, they take turns in that line: each shows for **Pinned header: seconds per item**
(`header.pinned-seconds`, 5 seconds), then the next slides up. Dots at the end show which one is
on screen, for up to **Pinned header: dots up to** (`header.pinned-dots`, 3) items. A finger on the
line keeps the one showing.

- **What's playing**: tap to play or pause, long-press or **⏭** to skip, as in the header.
- **A script's item**: tap runs the script, long-press for Run, Hide from header and Edit. A bar
  under it shows how far along it is, when the script gives one.

With nothing to show, the line takes no room.

## The key bar

The bar appears only while the on-screen keyboard is open for the prompt, so an idle home screen
shows more of the log (`keybar.auto off` keeps it always visible). It sits
below the prompt, right on top of the keyboard, so the best suggestion stays just above what you type.
The ⌨ button at the right end of the prompt line turns the bar on or off (`keybar.show`, off by default); it is
green while the bar is on.
Make it and the prompt slimmer while typing with `keybar.height` (row height, 20–64 dp) and
`prompt.height` (20–72 dp), also under Settings → Keyboard.
`log.line-height` (Settings → Log, 22 by default) sets the height of log lines: lower
for a denser log (down to as short as the text allows), higher for more room. It scales with the phone's text size. **Taller tappable
lines** (`log.taller-taps`) makes the lines you can tap a little taller than the others, easier to
hit, and `chips.height` sets the height of suggestion and app-grid chips.

An on-screen keyboard's main page leaves out keys a terminal needs, so Kolahal adds a row of them:

```
/  |  =  ←  ↑  ↓  →
```

- `/` starts a [log search](#searching-the-log), `|` a [pipe](#pipes) and `=` the calculator.
- `←` / `→` move the cursor; `↑` / `↓` move through the command history.
- Arrows and backspace repeat while held, and dragging sideways across the bar moves the cursor.
- To change the bar, set `keybar.row1` and `keybar.row2` to comma-separated keys from `ESC TAB UP DOWN
  LEFT RIGHT HOME END BKSP ENTER SPACE KBD`, or any literal text. `KBD` shows the on-screen keyboard.
  Row 2 is empty by default. You can also set it in Settings. Hide the bar with `keybar.show off`.

```sh
config set keybar.row1 ESC,TAB,UP,DOWN,|,~,KBD
config set keybar.row2 HOME,END,-,BKSP
config reset keybar.row1      # back to the default row
```

## Touch

- Tap empty log space to bring up the keyboard (`keyboard.on-home on` opens it every time the home screen is shown: Home pressed, back from an app, or the phone unlocked).
- Pinch the log to resize the text (`font.size`, 10–24). When you let go, a short message shows the new size.
- Double-tap empty log space to lock the screen. Swiping up on the prompt does nothing until you
  set it: `config set gesture.swipe-up apps` opens the app grid. See [Gestures](/guides/gestures/).
