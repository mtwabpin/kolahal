Kolahal (package `com.mtwabpin.kolahal`) needs **Android 9 (API 28) or newer**.

## Download

Each release has two APKs. The newest release is Kolahal {VERSION}:

- **The full build** (the first button) has every feature. Download this one.
- **The Play build** (the second button) is the version for Google Play. See [The Play build](#the-play-build).

You can find release notes and older versions on the [releases page](https://github.com/mtwabpin/kolahal/releases).

Both APKs have the same package name and the same signing key. So you can install either one over the other,
or over an earlier version (0.3.1 or later), and you keep your data. Next, [sideload the APK](#sideload-the-apk).

Kolahal is also in a closed test on Google Play. If you want to install it from the Play Store and help release it to everyone, [join the test](/getting-started/play-testing/).

### If Play Protect blocks it

In India and some other countries, Google Play Protect blocks some sideloaded apps. A sideloaded app is one
you install from a browser, a messaging app or a file manager. Play Protect blocks it if it declares an
accessibility service or notification access.

- Both builds declare notification access. Kolahal uses it to show your notifications in the log.
- The full build also has an accessibility service. Kolahal uses it only to lock the screen.

To install Kolahal anyway, do one of these:

- Turn off **Play Store → profile → Play Protect → ⚙︎ → Scan apps with Play Protect**, install Kolahal, then turn the setting back on.
- Use `adb install`.

When Kolahal is on Google Play, you can install it from there and Play Protect won't block it.

### Updating

In the full build:

- `update` tells you if a newer release is available.
- `update install` downloads it, checks that it is signed with Kolahal's key and opens Android's installer.

The first time, Android asks you to allow Kolahal to install apps.

The Play build updates through Google Play. The Play build APK from GitHub has no `update` command, so you
must install each new version yourself.

### Upgrading from 0.3.0 or earlier

Versions up to 0.3.0 were signed with a different key. Later versions can't install over them.
To upgrade and keep your data:

1. Open **Settings → Backup → Export everything**.
2. Uninstall Kolahal.
3. Install the new version and make it your home app.
4. Open **Settings → Backup → Import a backup**.
5. Run `setup` to grant the permissions again.
6. Add your widgets again. A backup lists them but can't restore them ([Backup](/guides/backup/)).

If you used the lite APK, install the Play build. It is the closest to the lite APK.

### The Play build

The Play build is the version for Google Play, where Kolahal will be available soon. Each release includes its APK.

Because of Google Play's rules, the Play build is different from the full build in these ways:

- **No call log.** Play doesn't let a launcher read the call log. So the Play build has no calls in the log and no `calls`.
- **No accessibility service.** Play asks for a declaration and a video for an accessibility service. So the Play build has no `lock` and no double-tap to lock.
- **No contacts permission.** Play requires apps to use Android's contact picker when the picker is enough. So `call`, `sms` and `contacts` open the picker and remember who you pick ([People](/guides/people/#in-the-play-build)).
- **No `update`.** Apps on Play update only through Play.

Everything else is the same, including notification access. Before Android's Notification access screen opens,
Kolahal explains what it reads and asks for your permission. Play requires this of apps that read notifications.

## Build from source

You need a JDK and the Android SDK. The project uses AGP 9.5.0, Gradle 9.8.2 (through the
wrapper), Kotlin 2.4.21, compileSdk 37 and targetSdk 37.

```sh
git clone https://github.com/mtwabpin/kolahal.git
cd kolahal

./gradlew :app:assembleRelease            # R8-optimised; signed with keystore.properties or the debug key
./gradlew :app:bundlePlay                 # the Play build, as a bundle for Google Play
./gradlew -PplayApk :app:assemblePlay     # the Play build as an APK, signed like the full one
./gradlew :app:assembleDebug              # debug APK ("Kolahal debug", package suffix .debug)
./gradlew :app:testDebugUnitTest          # JVM tests
./gradlew :app:connectedDebugAndroidTest  # on-device tests (run them on an emulator)
```

You can find the APKs in `app/build/outputs/apk/<variant>/`.

:::tip[Use the release build day to day]
Debug builds scroll much more slowly. The debug build installs next to the release
build (it has a `.debug` package suffix), so you can keep both.
:::

### Signing

The APKs on the releases page are signed with the project's key. If you don't set up your own keys, your build is
signed with your debug key. Then it won't install over a downloaded APK, so uninstall that first.

`tools/make-keys.sh` makes two keys and lists both in `keystore.properties` (which git ignores):

- a release key, which signs the APKs
- an upload key, which signs the Google Play bundle

```properties
storeFile=/path/to/release.jks
storePassword=…
keyAlias=…
keyPassword=…
uploadStoreFile=/path/to/upload.jks
uploadStorePassword=…
uploadKeyAlias=…
uploadKeyPassword=…
```

GitHub Actions builds the releases. When you push a version tag such as `v0.3.1`, it builds, signs and
publishes them.

## Sideload the APK

Open the downloaded APK on the phone. The first time, Android asks you to allow your browser or file manager to install
apps. You can also install over USB:

<Code lang="sh" code={`adb install -r kolahal-${VERSION}.apk                         # a download
adb install -r app/build/outputs/apk/release/app-release.apk  # your own build`} />

Android doesn't compile a sideloaded APK ahead of time. It compiles it later, while the phone is idle.
Until then, Kolahal can feel slow. To compile it now, run:

```sh
adb shell cmd package compile -m speed -f com.mtwabpin.kolahal
```

## Make it your home app

Press Home and pick Kolahal. Or run `home` at the prompt to open Android's default home app
setting. Kolahal should be the default launcher, because only the default launcher can list an app's shortcuts
(in the app's long-press menu).

The first time Kolahal starts, it opens a short [tour](/getting-started/setup/#the-tour) that sets up a few
things. Run [`setup`](/getting-started/setup/) at any time to see the rest of the checklist.

## Work profile and private space

This section applies only if you use a work profile (apps your employer manages, shown with a briefcase) or Android 15's private space.

Kolahal lists their apps next to your own. As the default launcher, Kolahal can also:

- pause and resume the work profile (Android 10 and newer)
- see the private space (Android 15 and newer)

See [Work profile & private space](/guides/profiles/).
