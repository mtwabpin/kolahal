Kolahal (package `com.mtwabpin.kolahal`) needs **Android 9 (API 28) or newer**.

## Download

Every release comes with two APKs. The newest is Kolahal {VERSION}:

<div class="sl-flex" style="flex-wrap: wrap; gap: 0.75rem 1rem; margin-block: 1rem;">
	<LinkButton href={APK} icon="download" iconPlacement="start">Kolahal {VERSION}</LinkButton>
	<LinkButton href={PLAY_APK} icon="download" iconPlacement="start" variant="secondary">Kolahal {VERSION}, Play build</LinkButton>
</div>

Download the first one, the full build, which has every feature. The second is the Play build, the version
for Google Play ([below](#the-play-build)). Release notes and older versions are on the
[releases page](https://github.com/mtwabpin/kolahal/releases). Both APKs have the same package and
key, so either installs over the other or over an earlier version (0.3.1 or later), keeping your
data. Then [sideload it](#sideload-the-apk).

Kolahal is also in a closed test on Google Play: to install it from the Play Store and help bring it to everyone, [join the test](/getting-started/play-testing/).

### If Play Protect blocks it

Google Play Protect blocks sideloaded apps (installed from a browser, a messaging app or a file
manager) that declare an accessibility service or notification access, in India and some other
countries. Both builds declare notification access, which shows your notifications in the log,
and the full build also has an accessibility service, which only locks the screen.

To install, turn off **Play Store → profile → Play Protect → ⚙︎ → Scan apps with Play Protect**, then turn it back on. Or use `adb install`. Once Kolahal is on Google
Play, installing it from there avoids the block.

### Updating

With the full build, `update` says whether a newer release is out, and `update install` downloads it,
checks it's signed with Kolahal's key and opens Android's installer. The first time, Android asks you
to let Kolahal install apps. The Play build updates through Google Play; its APK from GitHub has no
`update`, so install a new one by hand.

### Upgrading from 0.3.0 or earlier

Versions up to 0.3.0 were signed with a different key, so later ones can't install over them.
To upgrade and keep your data: **Settings → Backup → Export everything**, uninstall Kolahal,
install the new version and make it your home app, then **Settings → Backup → Import a backup**.
Run `setup` to grant the permissions again, and add your widgets again: a backup lists them but can't restore them ([Backup](/guides/backup/)). If you had the lite APK, install the Play build, which is the closest to it.

### The Play build

The Play build is the version for Google Play, where Kolahal will be available soon. Every release includes its APK. Play's policy doesn't let a launcher read the call log, and asks for a declaration and a
video for an accessibility service, so the Play build leaves those two out: no `lock` or
double-tap lock, and no calls in the log or `calls`. It doesn't read your contacts either, because Play requires apps to use Android's contact picker when that's enough: `call`, `sms` and `contacts` open the picker and
remember who you pick ([People](/guides/people/#in-the-play-build)). It has no `update`, as apps on Play update only through Play. Everything else is the same,
notification access included: before Android's Notification access screen opens, Kolahal explains what it reads and asks for permission, as Play requires of apps that read notifications.

## Build from source

You need a JDK and the Android SDK. The project's toolchain is AGP 9.4.1, Gradle 9.8.2 (through the
wrapper), Kotlin 2.4.21, compileSdk 37 and targetSdk 37.

```sh
git clone https://github.com/mtwabpin/kolahal.git
cd kolahal

./gradlew :app:assembleRelease            # R8-optimised; signed with keystore.properties or the debug key
./gradlew :app:bundlePlay                 # the Play build, as a bundle for Google Play
./gradlew -PplayApk :app:assemblePlay     # the Play build as an APK, signed like the full one
./gradlew :app:assembleDebug              # debug APK ("Kolahal debug", package suffix .debug)
./gradlew :app:testDebugUnitTest          # JVM tests
./gradlew :app:connectedDebugAndroidTest  # on-device tests (run them on an emulator)
```

The APKs end up in `app/build/outputs/apk/<variant>/`.

:::tip[Use the release build day to day]
Debug Compose builds are noticeably slower to scroll. The debug build installs next to the release
one (it has a `.debug` package suffix), so you can keep both.
:::

### Signing

The APKs on the releases page are signed with the project's key. Your own build is signed with your
debug key unless you set up keys, so it won't install over a downloaded one (uninstall first).
`tools/make-keys.sh` makes a release key, which signs the APKs, and an upload key, which signs the
Google Play bundle, and lists both in `keystore.properties` (git-ignored):

```properties
storeFile=/path/to/release.jks
storePassword=…
keyAlias=…
keyPassword=…
uploadStoreFile=/path/to/upload.jks
uploadStorePassword=…
uploadKeyAlias=…
uploadKeyPassword=…
```

Releases are built by GitHub Actions: pushing a version tag such as `v0.3.1` builds, signs and
publishes them.

## Sideload the APK

Open the downloaded APK on the phone; Android asks once to let your browser or file manager install
apps. Or install over USB:

<Code lang="sh" code={`adb install -r kolahal-${VERSION}.apk                         # a download
adb install -r app/build/outputs/apk/release/app-release.apk  # your own build`} />

A sideloaded APK runs without ahead-of-time compilation until Android compiles it during idle
maintenance, so it can feel laggy at first. To compile it right away:

```sh
adb shell cmd package compile -m speed -f com.mtwabpin.kolahal
```

## Make it your home app

Press Home and pick Kolahal, or run `home` at the prompt to open Android's default home app
setting. Being the default launcher matters: only the default launcher can list an app's shortcuts
(in its long-press menu).

On its first start Kolahal opens a short [tour](/getting-started/setup/#the-tour) that sets up the
first few things; run [`setup`](/getting-started/setup/) any time for the rest of the checklist.

## Work profile and private space

This applies only if you use a work profile (apps your employer manages, shown with a briefcase) or Android 15's private space. Kolahal lists their apps next to your own, and as the default launcher
it can pause and resume the work profile (Android 10 and newer) and see the private space
(Android 15 and newer). See [Work profile & private space](/guides/profiles/).
