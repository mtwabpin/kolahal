Both engines expose the same API. In JavaScript, the network calls (`http.*`, `rss.fetch`,
`rss.fresh`) and `sleep` return promises, so `await` them. Everything else is synchronous in both
languages. Lua calls simply block, since scripts never run on the UI thread.

Tables in Lua and objects in JS are interchangeable in the descriptions below: `{ status, ok }`
means a table with those keys in Lua and an object with those properties in JS.

## Output

### log(title, body?, ctx?)

Appends a line to the log. `title` shows in bold, in
the script's colour (the link colour with a `url`). A run's first line ends with the script's name,
muted (`… · weather`), unless it's right under the command that ran it. `body`, if given, appears muted under it, on as many lines as it needs. Every
line a script logs is a title: to log several, call `log` for each, or use [`logs`](#logstitles).
`log(title, ctx)` works too, without a body.
`ctx` is an optional table / object of strings that decides what tapping and long-pressing do:

| Key | Effect |
| --- | --- |
| `url` | tap opens the link; long-press offers open, share and copy |
| `copy` | what "Copy text" copies instead of the title and body: all or part of what the line shows, or its `url`; anything else is dropped |
| `image` | an image URL (http or https): the picture shows under the line, as wide as the log; long-press offers "Open image" |
| `mono` | `"1"`: the line keeps the terminal font even with `font.sans all`, so columns padded with spaces line up |

A link or a picture counts as a network request: with internet switched off for the script, both are removed from the line, and one that contains a secret must go to the site its `@secret` line names, over https.

Other keys are dropped: a script can't add a line that runs a command or dials a number when
tapped, whatever keys the launcher uses itself.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
log("neovim/neovim", "Nvim 0.11.4", { url = "https://github.com/neovim/neovim/releases" })
log("Pune, IN", "Today: clear, 24–31°C\nTomorrow: rain, 23–29°C")
log("Kolahal on GitHub", { url = "https://github.com/mtwabpin/kolahal" })
log("Your code is 4821", { copy = "4821" })
log("xkcd #327", { image = "https://imgs.xkcd.com/comics/exploits_of_a_mom.png" })
print("print() also logs", 42)   -- arguments joined with tabs
```
</TabItem>
<TabItem label="JavaScript">
```js

log("Kolahal on GitHub", { url: "https://github.com/mtwabpin/kolahal" });

console.log("console.log also logs", 42);  // arguments joined with spaces
console.error("logged as an error line");
```
</TabItem>

### md.log(title, body?, ctx?)

Like [`log`](#logtitle-body-ctx), but renders Markdown in the title and the body: `**bold**` (or
`__bold__`), `*italic*` (or `_italic_`), `~~strike~~`, `++underline++` and `` `code` ``. In the
body, a line starting `- `, `* ` or `+ ` is a bulleted item and one starting `1. ` a numbered one;
two spaces before it make a second level. `log` itself never renders Markdown, so text from the web logged with it always appears exactly as written.

`md.escape(text)` puts a backslash before every Markdown mark in `text`, so text from the web can
go inside `md.log` and still show exactly as written.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
md.log("**3** new releases", "- neovim `v0.11.4`\n- termux ~~v0.118~~ v0.119")
md.log("**HN** " .. md.escape(item.title), nil, { url = item.link })
```
</TabItem>
<TabItem label="JavaScript">
```js
md.log("**3** new releases", "- neovim `v0.11.4`\n- termux ~~v0.118~~ v0.119");
md.log("**HN** " + md.escape(item.title), null, { url: item.link });
```
</TabItem>
</Tabs>

### Styles: fmt

Use these for lines that include text from the web, where Markdown would need escaping. Each function returns styled text that you can join with other text in any `log`, `logs` or `md.log`. Nothing else in the line is treated as a style.

| Function | Shows |
| --- | --- |
| `fmt.bold(text)` | bold (in a body, also in the text colour) |
| `fmt.italic(text)` | italic |
| `fmt.underline(text)` | underlined |
| `fmt.strike(text)` | struck through |
| `fmt.code(text)` | on a shaded chip, in the terminal font |
| `fmt.color(role, text)` | in one of the theme's colours: `accent`, `link`, `info`, `muted`, `text`, `good`, `warn` or `bad` |
| `fmt.list(items, numbered?)` | one item per line, bulleted, or numbered `1.`, `2.` … with `true`: for a body |
| `fmt.plain(text)` | the text without its styles |

Colours are set by role, never by value: the theme picks each one, in its dark and its light version, so a line is readable on every theme. `good` is for up, done or passing, `warn` for something short of
an error, `bad` for down or failed (the theme's error colour). Show it in the text too (`▲`, `▼`, "down"): a colour alone is easy to miss.

Styles appear only in the log: notifications, status lines, Copy text and search use the plain text.
A styled string is ordinary text with invisible marks around the styled parts, so shorten text
before styling it; if text is cut in the middle of a mark, the style continues to the end of the line. Use
`fmt.plain` before storing or sending a styled string anywhere else.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
log(fmt.bold(item.score) .. " · " .. item.title, nil, { url = item.link })
log("Today", fmt.list({ "standup " .. fmt.code("10:00"), "review" }, true))
log("BTC 67,120 USD " .. fmt.color("good", "▲ 1.2%"))
```
</TabItem>
<TabItem label="JavaScript">
```js
log(`${fmt.bold(item.score)} · ${item.title}`, null, { url: item.link });
log("Today", fmt.list([`standup ${fmt.code("10:00")}`, "review"], true));
log(`BTC 67,120 USD ${fmt.color("good", "▲ 1.2%")}`);
```
</TabItem>
</Tabs>

### notify(title, body, ctx?)

Posts an Android notification, if notifications are enabled **for this script** (`script notify
<name> on` or the switch in the script manager) and allowed for Kolahal. `ctx.url` is opened when
the notification is tapped. Returns `true` if a notification was posted. A run posts at most 10:
Android keeps about 50 for an app, and Kolahal's own reminders need room.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
notify("Build finished", "main is green", { url = "https://ci.example.org" })
```
</TabItem>
<TabItem label="JavaScript">
```js
notify("Build finished", "main is green", { url: "https://ci.example.org" });
```
</TabItem>
</Tabs>

### status(text, opts?)

Sets this script's status line (first line of `text`, at most 80 characters): it shows on the
script's card in Scripts and in `status`, and in the
[pinned header](/getting-started/basics/#the-pinned-header) at the top of home once you pin the
script (`script pin <name>`, or **Pin to the top** in its menus); a script can't pin itself.
`status(nil)` / `status(null)` or an empty string clears it. It only works in saved scripts, since
it is keyed by the script's name. Tapping the line at the top runs the script. A run changes it at
most 20 times; setting the line it already shows doesn't count.

`opts` can have:

- `progress`: how far along, from 0 to 1, drawn as a bar under the line at the top. Without it,
  there's no bar.
- `refresh`: run the script again every this many seconds (10 at the fastest, up to 3600) while
  home shows the line at the top, to keep it current. That run's [`event.name`](#event) is
  `"refresh"`, so it can skip what only a typed command needs. It runs only while home is on
  screen and the script is pinned: set the line without `refresh` once it stops changing. An
  error in those runs shows once until a run works again, and what a run returns isn't logged; its
  own `log` lines are.

Any other key, or a value that isn't a number, is an error. Kolahal before 0.4.14 ignores `opts`.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
status("HN: " .. count .. " new")
status("NZ 136/8 (33.2 ov) v IND", { progress = 200 / 300, refresh = 30 })
status(nil)
```
</TabItem>
<TabItem label="JavaScript">
```js
status(`HN: ${count} new`);
status("NZ 136/8 (33.2 ov) v IND", { progress: 200 / 300, refresh: 30 });
status(null);
```
</TabItem>
</Tabs>

### allowed(what)

Whether this script may use `what`: `"internet"`, `"header"`, `"notifications"`, `"apps"`,
`"clipboard"`, `"commands"`, `"dnd"`, an `@on` event such as `"unlock"`, or `"work"`. You switch these per script
([switching access off](/scripting/overview/#switching-access-off)); with one off, a script can do
something else instead. A script has `"internet"` only if its code uses `http`, `rss`, `url`,
`image` or `launcher.run`. `"header"` is whether you pinned it, so its status line shows at the top
of home; a script has it only if it calls `status`. Code typed at the prompt gets `true` for everything.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
if allowed("header") then status(text) else log(text) end
```
</TabItem>
<TabItem label="JavaScript">
```js
if (allowed("header")) status(text); else log(text);
```
</TabItem>
</Tabs>

### Return value

Whatever the script returns is printed as an output line (tables and objects as JSON; long-press
copies it). A one-liner run with `lua` / `js` that produces nothing prints `nil`.

## HTTP

Responses are `{ status, ok, body, headers }`: the numeric status, `ok` for 2xx, the body as a string
(read up to 4 MB) and response headers with lowercase names. A `User-Agent` of
`Kolahal-Launcher/0.1 (+https://github.com/mtwabpin)` is sent unless you set your own. Network errors raise an error (Lua) or
reject the promise (JS). An HTTP error status does **not**, so check `ok`. Plain `http://` URLs are
allowed. A request can go to any address: this phone, your local network (a router, a home server) and a VPN address like Tailscale's 100.x are all allowed. On Android 17 and newer,
Android itself blocks your local network, and those requests fail after a timeout. A JavaScript run makes at most 4 requests at a time; more are queued, and with 64 requests and sleeps waiting at once, another call fails.

### http.get(url, headers?)

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
local r = http.get("https://api.github.com/repos/neovim/neovim", { Accept = "application/json" })
if not r.ok then error("HTTP " .. r.status) end
local repo = json.decode(r.body)
return repo.stargazers_count
```
</TabItem>
<TabItem label="JavaScript">
```js
const r = await http.get("https://api.github.com/repos/neovim/neovim", { Accept: "application/json" });
if (!r.ok) throw new Error("HTTP " + r.status);
return JSON.parse(r.body).stargazers_count;
```
</TabItem>
</Tabs>

### http.request(opts)

Any method. `opts` = `{ url, method, body, contentType, headers }`; only `url` is required and
`method` defaults to `GET`. A string `body` is sent as is, as `text/plain; charset=utf-8`; a
table / object body is encoded as JSON and sent as `application/json`. `contentType`, or a
`Content-Type` header, sets the type instead.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
local r = http.request{
  url = "https://ntfy.sh/my-topic",
  method = "POST",
  body = "backup done",
}

local r2 = http.request{
  url = "https://httpbin.org/post",
  method = "POST",
  body = { hello = "world" },
  contentType = "application/json",
  headers = { Authorization = "Bearer " .. store.get("token") },
}
```
</TabItem>
<TabItem label="JavaScript">
```js
await http.request({ url: "https://ntfy.sh/my-topic", method: "POST", body: "backup done" });

const r2 = await http.request({
  url: "https://httpbin.org/post",
  method: "POST",
  body: { hello: "world" },
  contentType: "application/json",
  headers: { Authorization: "Bearer " + store.get("token") },
});
```
</TabItem>
</Tabs>

### http.cached(url, seconds?)

A GET that reuses this script's stored response while it is less than `seconds` old (default 600).
The result has an extra `cached` field (`true` when it came from the cache). Only successful
responses are cached, and only their body: a cached result has `status` 200 and empty `headers`.
Cached responses count toward the script's [store](#storegetkey--storesetkey-value) limits; when the store is full, the script's other cached responses are deleted to make room.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
local r = http.cached("https://open.er-api.com/v6/latest/USD", 6 * 3600)
```
</TabItem>
<TabItem label="JavaScript">
```js
const r = await http.cached("https://open.er-api.com/v6/latest/USD", 6 * 3600);
```
</TabItem>
</Tabs>

## RSS and Atom

Feeds come back as `{ title, link, items }`, where each item is
`{ title, link, id, date, summary }`. `rss.fetch` and `rss.fresh` raise an error on an HTTP failure,
so wrap them in `pcall` / `try` if you want a friendly message.

### rss.fetch(url)

Downloads and parses a feed.

### rss.parse(xml)

Parses feed XML you already have. Synchronous in both languages.

### rss.fresh(url)

Like `rss.fetch`, but returns only items this script hasn't seen before (by item id; the last 500
ids per URL are remembered). Items are only marked as seen **if the run succeeds**, so a script that
fails halfway sees the same items next time.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
local feed = rss.fresh("https://lobste.rs/rss")
for i, item in ipairs(feed.items) do
  if i > 5 then break end
  log(item.title, { url = item.link })
end
```
</TabItem>
<TabItem label="JavaScript">
```js
const feed = await rss.fresh("https://lobste.rs/rss");
for (const item of feed.items.slice(0, 5)) log(item.title, { url: item.link });
```
</TabItem>
</Tabs>

## Storage

### store.get(key) / store.set(key, value)

Persistent strings, private to each script. `store.get` returns `nil` / `null` for a missing key;
`store.set(key, nil)` deletes it. Store anything structured as JSON. Deleting a script deletes its
store; one-liners typed at the prompt share one scratch store. A value holds up to 1 MB and a key
up to 512 characters, and a script's store up to 1,000 keys and 16 MB, keys included, counted as
stored (an accented letter or a CJK character takes more than one byte); past those `store.set`
raises an error ("value too large", "key too long" or "store full"). It rejects a secret, because a store is included in backups.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
local n = tonumber(store.get("runs") or "0") + 1
store.set("runs", tostring(n))
store.set("list", json.encode({ "a", "b" }))
```
</TabItem>
<TabItem label="JavaScript">
```js
const n = Number(store.get("runs") ?? 0) + 1;
store.set("runs", String(n));
store.set("list", JSON.stringify(["a", "b"]));
```
</TabItem>
</Tabs>

### secrets.get(name)

A placeholder for the API key or token the script names with `@secret`, or `nil` / `null` until you
set it: never the value itself. Put it where a request needs the key (a header, the URL's path or
query, the body; not the site's name), as is or joined with other text, and Kolahal puts the value in its place when the request goes to a
site the `@secret` line names, over https; a request carrying it anywhere else stops the script
([API keys and other secrets](/scripting/overview/#api-keys-and-other-secrets)). It is shown as
`••••`, and a script can't turn it into the value: encoded, reversed or cut up, it is just text.
Reading a name without its `@secret` line is an error, and code typed at the prompt can't read secrets.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
-- @secret GH_TOKEN api.github.com A GitHub token with read access
local token = secrets.get("GH_TOKEN")
if not token then return "set GH_TOKEN in the script's sheet" end
local r = http.get("https://api.github.com/notifications", { Authorization = "Bearer " .. token })
```
</TabItem>
<TabItem label="JavaScript">
```js
// @secret GH_TOKEN api.github.com A GitHub token with read access
const token = secrets.get("GH_TOKEN");
if (!token) return "set GH_TOKEN in the script's sheet";
const r = await http.get("https://api.github.com/notifications", { Authorization: "Bearer " + token });
```
</TabItem>
</Tabs>

### json.encode(v) / json.decode(s)

Lua only; JavaScript has the built-in `JSON`. `json.decode` turns objects into tables and arrays
into 1-based sequences, and raises an error when `s` isn't JSON (an HTML error page, say): wrap it
in `pcall` when the text comes from a site.

```lua
local data = json.decode('{"ip":"203.0.113.7"}')
return json.encode({ ip = data.ip, ok = true })
```

## Device

### clipboard.get() / clipboard.set(text)

Needs `@uses clipboard` ([what a script may use](/scripting/overview/#what-a-script-may-use)).
Android only lets the focused app read the clipboard, so `clipboard.get()` usually returns `nil` in
timer runs. `clipboard.set` works any time, for up to 100,000 characters, and rejects a secret.

```lua
-- @uses clipboard
clipboard.set("copied by a script")
```

### device.battery()

`{ level, charging }`: `level` is 0–100 (or nil if unknown), `charging` is true when plugged in.

### device.network()

The active network: `"wifi"`, `"cell"`, `"eth"`, `"net"` (something else) or `"offline"`.

### device.unlocks()

Today's unlock count, as in the header.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
local b = device.battery()
return string.format("%d%% %s · %s · %d unlocks", b.level or -1,
  b.charging and "charging" or "", device.network(), device.unlocks())
```
</TabItem>
<TabItem label="JavaScript">
```js
const b = device.battery();
return `${b.level}% ${b.charging ? "charging" : ""} · ${device.network()} · ${device.unlocks()} unlocks`;
```
</TabItem>
</Tabs>

### device.dnd() / device.setDnd(mode)

`device.dnd()` returns the current Do Not Disturb mode: `"off"`, `"priority"`, `"alarms"` or `"none"` (total
silence). `device.setDnd(mode)` sets it to one of those (`"on"` is `"priority"`) and returns `true`,
or `false` when Kolahal has no Do Not Disturb access: run `dnd access` once to grant it. Since Android
15, what a script turns on is Kolahal's own Do Not Disturb mode, beside yours: turning it off again
never turns off one you turned on yourself. Needs `@uses dnd`.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
-- @uses dnd
if device.dnd() == "off" then device.setDnd("on") end
```
</TabItem>
<TabItem label="JavaScript">
```js
// @uses dnd
if (device.dnd() === "off") device.setDnd("on");
```
</TabItem>
</Tabs>

### apps.list()

Launchable apps in your personal profile and in a work or clone profile that is on, sorted by label:
`[{ label, pkg, profile }]`, where `profile` is `"personal"` or `"other"`. Apps in a paused profile or
the private space are left out. Needs `@uses apps`.

```js
// @uses apps
const work = apps.list().filter(a => a.profile !== "personal");
return `${work.length} apps outside the personal profile`;
```

### notifications.recent(n?)

The most recent notifications, newest first: `[{ pkg, app, title, text, time }]` (`time` in
milliseconds since the epoch). `n` defaults to 20, at most 50. Needs
[notification access](/guides/notifications/); returns an empty list without it. Needs
`@uses notifications`.

```lua
-- @uses notifications
for _, n in ipairs(notifications.recent(5)) do
  log(n.app .. ": " .. (n.title or "") .. " " .. (n.text or ""))
end
```

## Launcher

### launcher.run(command)

Runs a terminal command, as if typed, including another script's command. Needs `@uses commands`.
**Only when the script was started from the prompt** (a command script, `script run`, or a
one-liner); in timer and event runs it logs an error and returns `false`. Sensitive commands
(`clear`, `uninstall`, `work`, `notifs`, `script` and the like) must be typed: for those it logs
an error and returns `false`. The same applies to `search`, `yt`, `wiki`, `maps` and `play` with search words, and to another `@command` script that goes online when given words, unless the script has internet access: they send the words to a site. A run sends at most 10 commands, and a script that another script started this way can't send any.

```lua
-- @command
-- @desc Morning: the weather, then the news app
-- @uses commands
launcher.run("weather")
launcher.run("open news")
```

### sleep(ms)

Pauses for up to 5000 ms per call. In JS: `await sleep(1000)`.

### args and argline

When a script runs as a command, `args` holds the words after its name (a table in Lua, an array in
JS; quotes group words) and `argline` the same words joined by spaces. Both are empty in timer runs.

```js
// @command
// @desc Greet: greet <name>
return `hello, ${argline || "world"} (${args.length} args)`;
```

### options

The script's [`@option`](/scripting/overview/#options) settings by name, as text: the value you set
in its sheet or with `script set`, or the default its line gives. Empty in code typed at the prompt.

```lua
-- @option city London The city to show
log("Weather for " .. options.city)
```

### event

In a run started by an [`@on` trigger](/scripting/overview/#event-triggers), `event` describes what
happened. `event.name` is the event (`unlock`, `charger`, `unplug`, `wifi`, `offline`,
`notification`, `boot`, `headset`). Some events add more:

| Event | Other fields |
| --- | --- |
| `charger`, `unplug` | `level` (battery %), and `plug` (`ac`, `usb`, `wireless`, `other`) while plugged in |
| `notification` | `app`, `pkg`, `title`, `text`, `time` |
| `headset` | `type` (`wired`), `device`, `mic` |
| `wifi` | `network` (`wifi`) |
| `boot` | `uptime` (seconds) |

`unlock` and `offline` carry only `name`. Text over 2,000 characters is truncated.

A run at one of the script's [daily times](/scripting/overview/#running-scripts) gets `event.name`
`"at"` and `event.time`, the scheduled time (`"23:00"`), even when it runs late: a script with two
times can tell them apart. A run a [status line](#statustext-opts) asks for with `refresh` gets `event.name`
`"refresh"`. Other runs get nil (null in JavaScript).

## Work profile

### device.work() / device.setWork(on)

`device.work()` returns the work profile's state: `"on"`, `"paused"`, or nil (null in JavaScript) when the phone
has none. `device.setWork(true)` (or `"on"`) resumes it and `device.setWork(false)` (or `"off"`) pauses it, returning `true`
when Android accepted the request. Android lets only the default launcher do this, only while it is in the foreground, and from Android 10. A script run at one of its [daily times](/scripting/overview/#running-scripts)
counts as in the foreground when Kolahal may set exact alarms; one on an interval or an event usually doesn't,
and gets `false`. Resuming returns `false` too when your work profile asks for its PIN: Android
asks you for it. Needs `@uses work`.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
-- @uses work
if device.work() == "on" then device.setWork(false) end
```
</TabItem>
<TabItem label="JavaScript">
```js
// @uses work
if (device.work() === "on") device.setWork(false);
```
</TabItem>
</Tabs>
