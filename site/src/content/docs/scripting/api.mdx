Both languages have the same API.

- In JavaScript, the network calls (`http.*`, `rss.fetch`, `rss.fresh`) and `sleep` return
  promises, so you `await` them.
- Everything else is synchronous in both languages.
- In Lua, calls simply block. This is fine, because scripts never run on the UI thread.

In the descriptions below, a Lua table and a JS object mean the same thing. For example,
`{ status, ok }` means a table with those keys in Lua, and an object with those properties in JS.

## Output

### log(title, body?, ctx?)

Adds a line to the log.

- `title` shows in the script's colour (in the link colour if the line has a `url`). With a `body`, the title is bold, as a heading over the body. On its own it is in normal weight, so a list of lines stays easy to read.
- The first line of a run ends with the script's name, muted (`… · weather`), unless the line is
  right under the command that ran it.
- `body` is optional. It shows muted under the title, on as many lines as it needs.
- Each line a script logs is a title. To log several lines, call `log` for each one, or use
  [`logs`](#logstitles).
- `log(title, ctx)` also works, without a body.
- `log` returns the line. While the script runs, [`line.set`](#lineset) changes it in place.
- A body taller than `log.fold` lines (8 by default) folds, with a tap to show the rest.

`ctx` is an optional table / object of strings. It sets what happens when you tap or long-press the
line:

| Key | Effect |
| --- | --- |
| `url` | Tap opens the link. Long-press offers open, share and copy. |
| `copy` | What "Copy text" copies instead of the title and body. It must be all or part of what the line shows, or its `url`. Anything else is dropped. |
| `image` | An image URL (http or https). The picture shows under the line, as wide as the log. Long-press offers "Open image". |
| `mono` | `"1"`: the line keeps the terminal font even with `font.sans all`, so columns padded with spaces line up. |
| `actions` | Up to 3 [buttons](#buttons) under the line, each `{ label, args }`. A tap runs this script again with those args. |
| `gap` | `true`: the line starts a new item of a list, such as a story with its points under it. A small space shows above it (`log.item-spacing`, 5 dp by default), and the colour bar runs through it, so the items stand apart but stay one group. It has no effect on a group's first line or on the line right under the command. From Kolahal 0.5.0; an older one ignores it. |

A link or a picture counts as a network request:

- If internet is switched off for the script, both are removed from the line.
- If one contains a secret, it must go over https to the site that the `@secret` line names.

Other keys are dropped. Whatever keys the launcher uses itself, a script can't add a line that runs
a command or dials a number when you tap it.

</TabItem>

### md.log(title, body?, ctx?)

Works like [`log`](#logtitle-body-ctx), but shows Markdown in the title and the body:

- `**bold**` (or `__bold__`), `*italic*` (or `_italic_`), `~~strike~~`, `++underline++` and
  `` `code` ``.
- `[text](https://…)` is a [link](#links): the text opens the address when tapped.
- In the body, a line that starts with `- `, `* ` or `+ ` is a bulleted item. A line that starts
  with `1. ` is a numbered item. Two spaces before it make a second level.

`log` itself never shows Markdown. So text from the web that you log with `log` always appears
exactly as written.

`md.escape(text)` puts a backslash before every Markdown mark in `text`, `[` included. Use it to put
text from the web inside `md.log`, so that it still shows exactly as written.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
md.log("**3** new releases", "- neovim `v0.11.4`\n- termux ~~v0.118~~ v0.119")
md.log("**HN** " .. md.escape(item.title), nil, { url = item.link })
```
</TabItem>
<TabItem label="JavaScript">
```js
md.log("**3** new releases", "- neovim `v0.11.4`\n- termux ~~v0.118~~ v0.119");
md.log("**HN** " + md.escape(item.title), null, { url: item.link });
```
</TabItem>
</Tabs>

### Styles: fmt

Use these for lines that include text from the web, where Markdown would need escaping. Each
function returns styled text. You can join it with other text in any `log`, `logs` or `md.log`.
Nothing else in the line is read as a style.

| Function | Shows |
| --- | --- |
| `fmt.bold(text)` | bold (in a body, also in the text colour) |
| `fmt.italic(text)` | italic |
| `fmt.underline(text)` | underlined |
| `fmt.strike(text)` | struck through |
| `fmt.code(text)` | on a shaded chip, in the terminal font |
| `fmt.color(role, text)` | in one of the theme's colours: `accent`, `link`, `info`, `muted`, `text`, `good`, `warn` or `bad` |
| `fmt.tag(role?, text)` | a short label on a shaded chip: see [Tags](#tags) |
| `fmt.link(text, url)` | text that opens a link: see [Links](#links) |
| `fmt.stats(items)` | a line of big numbers, for a body: see [Big numbers](#big-numbers) |
| `fmt.list(items, numbered?)` | one item per line, with bullets, or numbered `1.`, `2.` … with `true`. Use it for a body. |
| `fmt.table(rows, opts?)` | a table, for a body: see [Tables](#tables) |
| `fmt.plain(text)` | the text without its styles |

Colours:

- You choose a colour by its role, never by its value. The theme picks each colour, in a dark and a
  light version, so the line is readable on every theme.
- `good` is for up, done or passing. `warn` is for something less than an error. `bad` is for down
  or failed (the theme's error colour).
- Also show the meaning in the text (`▲`, `▼`, "down"). People can easily miss a colour alone.

Where styles work:

- Styles appear only in the log. Notifications, status lines, Copy text and search use the plain
  text.
- A styled string is normal text with invisible marks around the styled parts. So shorten text
  before you style it. If text is cut in the middle of a mark, the style continues to the end of the
  line.
- Use `fmt.plain` before you store a styled string or send it anywhere else.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
log(fmt.bold(item.score) .. " · " .. item.title, nil, { url = item.link })
log("Today", fmt.list({ "standup " .. fmt.code("10:00"), "review" }, true))
log("BTC 67,120 USD " .. fmt.color("good", "▲ 1.2%"))
```
</TabItem>
<TabItem label="JavaScript">
```js
log(`${fmt.bold(item.score)} · ${item.title}`, null, { url: item.link });
log("Today", fmt.list([`standup ${fmt.code("10:00")}`, "review"], true));
log(`BTC 67,120 USD ${fmt.color("good", "▲ 1.2%")}`);
```
</TabItem>
</Tabs>

### Tables

`fmt.table(rows, opts?)` makes a table to use as a line's body. Each row is a list of cells.

- `opts.header`: `true` makes the first row the header. It names the columns and shows muted.
- `opts.align`: one letter for each column, `l` (left) or `r` (right). Numbers read best on the
  right. Columns without a letter are on the left.
- A cell is one line: a line break in it becomes a space. Cells take the other `fmt` styles and colours.
- Up to 8 columns and 50 rows besides the header. More rows end with a "+N more" line.
- The table shows in the terminal font, so its columns line up. A table wider than the screen
  scrolls sideways.
- How it looks is the user's choice (`log.tables`): boxed (the default) or plain columns.
- **Copy text** copies the table with tabs between the cells, so it pastes into a spreadsheet.
- Text can come before and after the table in the same body: join them with `"\n"`.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
log("Prices in USD", fmt.table({
  { "Coin", "Price", "24h" },
  { "BTC", "64,210", fmt.color("good", "▲ 2.1%") },
  { "ETH", "3,118", fmt.color("bad", "▼ 0.8%") },
}, { header = true, align = "lrr" }))
```
</TabItem>
<TabItem label="JavaScript">
```js
log("Prices in USD", fmt.table([
  ["Coin", "Price", "24h"],
  ["BTC", "64,210", fmt.color("good", "▲ 2.1%")],
  ["ETH", "3,118", fmt.color("bad", "▼ 0.8%")],
], { header: true, align: "lrr" }));
```
</TabItem>
</Tabs>

### Links

`fmt.link(text, url)` makes `text` a link: a tap on it opens `url`. A tap anywhere else on the
line does what a tap on the line does (opens its `url`, if it has one).

- A line can have several links, in its title and its body: a story and its comments, release
  notes and a diff.
- Links are in the link colour and underlined.
- They follow the rules of a line's `url`: web links only (http and https), none when internet is
  off for the script, and none that carries a secret anywhere but the sites its `@secret` line
  names. A link that breaks a rule shows its text as plain text.
- Long-press the line for **Open "…"** for each link (up to 4).
- In `md.log`, `[text](https://…)` makes a link too.
- Everywhere else (Copy text, search, notifications) only the text shows.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
log(item.title .. " · " .. fmt.link("138 comments", item.comments), { url = item.link })
md.log("New in [neovim](https://github.com/neovim/neovim/releases)")
```
</TabItem>
<TabItem label="JavaScript">
```js
log(`${item.title} · ${fmt.link("138 comments", item.comments)}`, { url: item.link });
md.log("New in [neovim](https://github.com/neovim/neovim/releases)");
```
</TabItem>
</Tabs>

### Tags

`fmt.tag(role, text)` shows a short label on a chip shaded in one of the theme's colours, by role,
as [`fmt.color`](#styles-fmt) takes it. `fmt.tag(text)` uses the accent colour.

- Use it for a state or a version: LIVE, NEW, pre-release, v0.12.0. For code, use `fmt.code`.
- A tag is one line, in bold and a little smaller than the text around it.
- Put a space between two tags, and between a tag and the text next to it.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
log(fmt.tag("bad", "LIVE") .. " IND v NZ")
log("neovim/neovim " .. fmt.tag("v0.12.0") .. " " .. fmt.tag("warn", "pre-release"))
```
</TabItem>
<TabItem label="JavaScript">
```js
log(`${fmt.tag("bad", "LIVE")} IND v NZ`);
log(`neovim/neovim ${fmt.tag("v0.12.0")} ${fmt.tag("warn", "pre-release")}`);
```
</TabItem>
</Tabs>

### Bars

Three functions make bars for a body. Each bar is a line of its own, like a table row. Bars on
lines that follow each other line up in columns: the labels, the texts before the bars, the bars,
and the texts after them.

| Function | Shows |
| --- | --- |
| `fmt.bar(value, opts?)` | one bar as wide as the line: `value` out of `opts.max` (1 by default) |
| `fmt.bars(rows, opts?)` | a bar for each row `{ label, value, text? }`, all on one scale from 0 to `opts.max` (by default the largest value), so the rows compare at a glance. `text` shows after the bar; by default it is the value with `opts.unit` |
| `fmt.ranges(rows, opts?)` | for each row `{ label, low, high, lowText?, highText? }`, a bar from low to high, all on one scale from `opts.min` to `opts.max` (by default the lowest low and the highest high). The low shows before the bar and the high after it |

- `opts.color` is the bars' colour, by role (`accent` by default). The unfilled part of a bar is
  a light shade of the same colour.
- `opts.unit` goes after each number that the bar shows itself, such as `°` or `%`.
- A value past the scale fills its bar, and one below it leaves it empty.
- Up to 50 rows. More end with a "+N more" line.
- Say the number in the text too: some people can't see a bar's length, and a screen reader
  reads only the texts.
- A wrong argument is an error that says what to pass, and so is an option that doesn't exist (a
  typo such as `colour`).
- Copy text copies the rows' texts with tabs between them. A bar alone copies nothing.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
log("Pune · AQI 168", "Unhealthy\n" .. fmt.bar(168, { max = 300, color = "bad" }))
log("Unlocks", fmt.bars({ { "Mon", 42 }, { "Tue", 21 } }, { color = "good" }))
log("Pune · 3 days", fmt.ranges({ { "Today", 23, 31 }, { "Tomorrow", 22, 30 } }, { unit = "°", color = "warn" }))
```
</TabItem>
<TabItem label="JavaScript">
```js
log("Pune · AQI 168", "Unhealthy\n" + fmt.bar(168, { max: 300, color: "bad" }));
log("Unlocks", fmt.bars([["Mon", 42], ["Tue", 21]], { color: "good" }));
log("Pune · 3 days", fmt.ranges([["Today", 23, 31], ["Tomorrow", 22, 30]], { unit: "°", color: "warn" }));
```
</TabItem>
</Tabs>

### Big numbers

`fmt.stats(items)` makes a line of big numbers for a body. Each item is `{ value, label }`: the
value large, in the terminal font, and its label under it, small. The first value is the biggest;
the others are smaller. They sit side by side and wrap when the screen is narrow.

- Use it for the one number that matters and a few beside it: the weather, a score, a count.
- Up to 5 items; more are left out. A value and a label are one line each, and take styles and colours.
- Copy text gets them as `25°C ☀️ Sunny · 36% humidity · …`.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
log("Pune", fmt.stats({ { "25°C", "☀️ Sunny" }, { "36%", "humidity" }, { "9 km/h", "wind" } }))
```
</TabItem>
<TabItem label="JavaScript">
```js
log("Pune", fmt.stats([["25°C", "☀️ Sunny"], ["36%", "humidity"], ["9 km/h", "wind"]]));
```
</TabItem>

### Buttons

`ctx.actions` puts up to 3 buttons under a line: `{ { label, args }, … }`. A tap on one runs
**this script** again, with that button's `args` (as if typed after its name) and
`event.name` `"action"` (with `event.label`). A button never runs any other command.

- Only a saved script's lines get buttons: code typed at the prompt has no script for them to run.
- A label is one line, at most 24 characters. More than 3 buttons, or one without a label, is an
  error that says so.
- Once tapped, the line shows that button alone, with a ✓, so it can't run twice.
- If the script is switched off, a tap says so instead of running it.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
if event and event.name == "action" then
  if args[1] == "snooze" then store.set("until", tostring(os.time() + tonumber(args[2]) * 60)) end
  return log("Snoozed for " .. args[2] .. " min")
end
log("Battery at 92%", "Unplug the charger.", { actions = { { "Snooze 30 min", "snooze 30" }, { "Not today", "snooze 720" } } })
```
</TabItem>
<TabItem label="JavaScript">
```js
if (event && event.name === "action") {
  if (args[0] === "snooze") store.set("until", String(Date.now() + Number(args[1]) * 60000));
  return log(`Snoozed for ${args[1]} min`);
}
log("Battery at 92%", "Unplug the charger.", { actions: [["Snooze 30 min", "snooze 30"], ["Not today", "snooze 720"]] });
```
</TabItem>
</Tabs>

### line.set

`log` and `md.log` return the line they added. `line.set(title, body?, ctx?)` changes that line
in place, where it is in the log. In Lua, `line:set(…)` works too.

- Show something at once, then the answer in the same place: "Fetching…" turns into the result.
  A slow script then doesn't look stuck, and leaves one line, not two.
- Show progress: "Checking 3 of 5 sites…", with a [bar](#bars).
- It takes what `log` takes. A line from `md.log` reads Markdown again.
- It works only while the script runs. After that, the line stays as it was last set.
- A run can change its lines 300 times. Later changes are ignored.
- Changes show about every 300 ms, and before each request.
- Kolahal versions before 0.4.16 return nothing from `log`. A script for those too can check
  `typeof fmt.bar === "function"` (JavaScript) or `fmt.bar ~= nil` (Lua) first.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
local line = log(fmt.color("muted", "Checking…"))
local up = 0
for i, site in ipairs(sites) do
  line.set("Checking " .. i .. " of " .. #sites .. "…", fmt.bar(i - 1, { max = #sites }))
  local ok, r = pcall(http.get, site)
  if ok and r.ok then up = up + 1 end
end
line.set(up .. " of " .. #sites .. " sites up")
```
</TabItem>
<TabItem label="JavaScript">
```js
const line = log(fmt.color("muted", "Checking…"));
let up = 0;
for (const [i, site] of sites.entries()) {
  line.set(`Checking ${i + 1} of ${sites.length}…`, fmt.bar(i, { max: sites.length }));
  try {
    if ((await http.get(site)).ok) up++;
  } catch (e) {}
}
line.set(`${up} of ${sites.length} sites up`);
```
</TabItem>
</Tabs>

### notify(title, body, ctx?)

Posts an Android notification. This works only if:

- notifications are on **for this script** (`script notify <name> on`, or the switch in the script
  manager), and
- notifications are allowed for Kolahal.

Tapping the notification opens `ctx.url`. Returns `true` if a notification was posted.

A run posts at most 10 notifications. Android keeps about 50 for each app, and Kolahal's own
reminders need room.

```lua
notify("Build finished", "main is green", { url = "https://ci.example.org" })
```

### status(text, opts?)

Sets this script's status line. Kolahal uses the first line of `text`, at most 80 characters.

- The line shows on the script's card in Scripts and in `status`.
- After you pin the script, it also shows in the
  [pinned header](/getting-started/basics/#the-pinned-header) at the top of home. Pin it with
  `script pin <name>` or **Pin to the top** in its menus. A script can't pin itself.
- `status(nil)` / `status(null)` or an empty string clears the line.
- It works only in saved scripts, because the line is stored under the script's name.
- Tapping the line at the top runs the script.
- A run can change the line at most 20 times. Setting the same line again doesn't count.

`opts` can have:

- `progress`: how far along, from 0 to 1. It is drawn as a bar under the line at the top. Without
  it, there is no bar.
- `color`: the bar's colour, by role, as [`fmt.color`](#styles-fmt) takes it: `good`, `warn`, `bad`, `info`,
  `accent` (the default), `link`, `muted` or `text`. The theme picks the colour, so it reads on
  every theme. For example, an air quality bar in `warn` or `bad` when the air is poor. Kolahal
  versions before 0.4.16 ignore it.
- `refresh`: run the script again every this many seconds (10 at the fastest, up to 3600) while
  home shows the line at the top. This keeps the line current.
  - In these runs, [`event.name`](#event) is `"refresh"`. The script can use this to skip work that
    only a typed command needs.
  - These runs happen only while home is on screen and the script is pinned.
  - When the line stops changing, set it without `refresh`.
  - If these runs fail, the error shows once, until a run works again.
  - What these runs return isn't logged. Their own `log` lines are.

Any other key, a `progress` or `refresh` that isn't a number, or a `color` that isn't a role, is an
error. Kolahal versions before 0.4.14 ignore
`opts`.

```lua
status("NZ 136/8 (33.2 ov) v IND", { progress = 200 / 300, refresh = 30 })
status("AQI 168", { progress = 168 / 300, color = "bad" })
status(nil)
```
</TabItem>

### allowed(what)

Returns whether this script may use `what`. `what` is one of:

- `"internet"`, `"header"`, `"widget"`, `"notifications"`, `"apps"`, `"clipboard"`, `"commands"`,
  `"dnd"`, `"work"`,
- an `@on` event, such as `"unlock"`.

You switch these on and off for each script
([switching access off](/scripting/overview/#switching-access-off)). When one is off, the script
can do something else instead.

- A script has `"internet"` only if its code uses `http`, `rss`, `url`, `image` or `launcher.run`.
- `"header"` means you pinned the script, so its status line shows at the top of home. A script has
  it only if it calls `status`.
- `"widget"` means you placed the script's [widget](#widgets) on the widgets page. A script has it
  only if it has an `@widget` line. It has no switch: placing the widget turns it on, and removing
  the widget turns it off.
- Code typed at the prompt gets `true` for everything.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
if allowed("header") then status(text) else log(text) end
```
</TabItem>
<TabItem label="JavaScript">
```js
if (allowed("header")) status(text); else log(text);
```
</TabItem>
</Tabs>

### Return value

Whatever the script returns is printed as an output line. Tables and objects are printed as JSON.
Long-press the line to copy it. If a one-liner run with `lua` / `js` produces nothing, it prints
`nil`.

## Widgets

A script can fill one card on the [widgets page](/guides/widgets/). The script says what to show: a
kind of card, and that kind's fields. Kolahal draws the card, in the theme's colours. A script
draws nothing itself.

1. Put an [`@widget` line](#the-widget-line) at the top of the script.
2. Call [`widget.show`](#widgetshowdesc) with a description: a table in Lua, an object in
   JavaScript.
3. Place the widget: tap **+ Add** on the widgets page. The picker lists your scripts' widgets in
   the **Kolahal** group. A script can't place its own widget.

Widgets need Kolahal 0.5.8 or newer.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
-- @title Steps
-- @widget stat 2x1

widget.show{
  value = "6,240",
  label = "steps today",
  more = { { value = "4.1 km", label = "walked" } },
}
```
</TabItem>
<TabItem label="JavaScript">
```js
// @title Steps
// @widget stat 2x1

widget.show({
  value: "6,240",
  label: "steps today",
  more: [{ value: "4.1 km", label: "walked" }],
});
```
</TabItem>
</Tabs>

### The @widget line

```lua
-- @widget <kind> [<size>]
```

- The kind is the card to draw. A description can name another kind with its `kind` field.
- The size is the size the widget has when you place it: `1x1`, `2x1`, `2x2`, `4x1`, `4x2` or
  `4x4`. It is in cells of a 4-column grid, as home screens count them, the width first. One cell
  is a quarter of the page wide.
- Without a size, the kind's own size is used. It is in the table below.
- After that, you resize the widget like any other
  ([Arrange and resize](/guides/widgets/#arrange-and-resize)). It can be as small as a quarter of
  the page wide and 72dp tall.
- A card draws for the space it has, not for the size on this line. A small card shows less.
- A script has one widget.
- Without this line, `widget.show` is an error that says to add it.

| Kind | Shows | Size without one |
| --- | --- | --- |
| `stat` | one big value with its label, and up to 3 smaller values | `2x1` |
| `text` | a few lines of text, and a caption | `2x2` |
| `list` | rows | `4x2` |
| `progress` | a ring or a bar, or up to 4 bars | `2x1` |
| `chart` | numbers over time, as a line or as bars | `2x2` |
| `countdown` | the time to a moment. Kolahal counts it down, with no run | `2x1` |

### widget.show(desc)

Checks the description `desc` and stores it as this script's widget. The card then shows it.

- It returns `true` when you placed the widget.
- It returns `false` when you didn't. The description is still checked, so a mistake shows either
  way. But nothing is stored.
- [`allowed("widget")`](#allowedwhat) tells the same before the call. A script can skip its work
  when it is `false`.
- It works only in saved scripts, like `status`. Code typed at the prompt gets a line that says so.
- A run can call `widget.show` and `widget.clear` 20 times in all. Later calls change nothing.
- A description can be 32 KB at most.
- Kolahal before 0.5.8 has no `widget`. A script that must also run there checks first:
  `if widget then … end` in Lua, `if (typeof widget !== "undefined") …` in JavaScript.

Rules for every description:

- An unknown field is an error that lists the fields the kind has. So a typo such as `colour`
  doesn't pass unseen.
- Each field has one type. A number where text is expected becomes text. Any other wrong type is an
  error that names the field.
- A field with no value (`nil`, `null`, `undefined`) counts as left out.
- Text over its limit is cut, with "…" at its end. A list over its limit keeps its first items.
- Text is plain. Styles from [`fmt`](#styles-fmt) are removed. A secret's value is masked, as in
  the log.
- A colour is a role, never a colour value. The theme picks the colour, so the card reads on every
  theme.

Every kind takes these fields. All are optional.

| Field | Value | What it is |
| --- | --- | --- |
| `kind` | a kind's name | The card to draw. Without it: the kind on the `@widget` line. |
| `title` | text, up to 40 characters | The card's small heading. Without it: the script's `@title`, or its name. |
| `icon` | text, up to 4 characters | An emoji or a letter, drawn in a badge. |
| `color` | a role | The colour of the badge, the bar, the ring or the chart: `accent` (without it), `link`, `info`, `muted`, `text`, `good`, `warn` or `bad`. |
| `tap` | an action | What a tap on the card does ([Taps](#taps)). Without it, a tap refreshes the card. |
| `staleAfter` | seconds, 60 to 604800 | How long the content counts as current. Without it: one hour. |
| `refresh` | seconds, 10 to 3600 | Run the script again this often while the widget is in view. |

### Kinds and their fields

**`stat`**: one big value.

| Field | Value | What it is |
| --- | --- | --- |
| `value` | text or a number, up to 40 characters | Needed. The big value. |
| `label` | text, up to 60 | What the value is, under it. |
| `unit` | text, up to 12 | Its unit: `°C`, `km`. |
| `delta` | text, up to 16 | A change, such as `+2.4%`. |
| `trend` | `up`, `down` or `flat` | An arrow for the change. |
| `more` | a list of `{ value, label }` | Up to 3 smaller values. Each text is up to 24 characters, and `value` is needed. |
| `progress` | a number, 0 to 1 | A bar under the value. |
| `moving` | true or false | Draws the bar as a wave, for something in progress. |

**`text`**: a few lines.

| Field | Value | What it is |
| --- | --- | --- |
| `text` | text, up to 500 | Needed. It keeps its line breaks. |
| `caption` | text, up to 60 | A line under it: an author, a source. |

**`list`**: rows. The card shows as many rows as fit, then "+3 more".

| Field | Value | What it is |
| --- | --- | --- |
| `items` | a list of rows | Needed. The first 12 are kept. It can be empty. |
| `empty` | text, up to 60 | What the card says with no rows: `Nothing new`. |

Each row is `{ title, detail, trailing, icon, color, tap }`. Only `title` is needed.

| Field | Value | What it is |
| --- | --- | --- |
| `title` | text, up to 80 | The row's text. |
| `detail` | text, up to 120 | A second line. |
| `trailing` | text, up to 24 | A short text at the row's end: a price, a count. |
| `icon` | text, up to 4 | An emoji or a letter in front. |
| `color` | a role | The colour of its icon and of its `trailing` text. A row with neither gets a dot in front. |
| `tap` | an action | What a tap on the row does ([Taps](#taps)). |

**`progress`**: how far along something is, as a ring, a bar, or several bars. It needs `value` or
`items`.

| Field | Value | What it is |
| --- | --- | --- |
| `value` | a number | How far along it is, from 0 to `max`. |
| `max` | a number above 0 | The top of the scale. Without it: 1. |
| `text` | text, up to 24 | What the ring's middle says: `68%`. Without it: the percent. |
| `label` | text, up to 60 | What it is. |
| `style` | `ring` or `bar` | Without it, the card picks one for the space it has. |
| `items` | a list of bars | Up to 4 bars, each `{ label, value, max, text, color }`. `value` is needed. |
| `moving` | true or false | Draws the ring and the bars as waves, for something in progress. |

A value is held between 0 and its `max`. Bars are on one scale: the widget's `max`, or else the
largest value among them. A bar with its own `max` uses that.

**`chart`**: numbers over time.

| Field | Value | What it is |
| --- | --- | --- |
| `points` | a list of numbers | Needed. The oldest comes first. The last 60 are kept. |
| `style` | `line` or `bars` | Without it: `line`. |
| `min`, `max` | numbers | The scale. Without them, it comes from the points; bars start at 0. `min` must be below `max`. |
| `value` | text or a number, up to 40 | The headline over the chart. |
| `label` | text, up to 60 | What the headline is. |
| `labels` | a list of two texts, up to 16 each | Words for the first and the last point: `Mon`, `Today`. |
| `summary` | text, up to 200 | What a screen reader says for the chart. |

**`countdown`**: the time to a moment. The script gives the moment once, and Kolahal counts. No
run is needed as time passes.

| Field | Value | What it is |
| --- | --- | --- |
| `to` | a time in seconds | Needed. The moment: `os.time{…}` in Lua, `Date.now() / 1000` in JavaScript. |
| `from` | a time in seconds, before `to` | Where the wait started. With it, the card has a bar from the start to the moment. |
| `label` | text, up to 60 | What the moment is. |
| `style` | `days` or `clock` | `days` says "12 days", `clock` says "03:25:10". Without it: days while the moment is more than 48 hours away, a clock after that. |
| `reached` | text, up to 60 | What the card says on the day, once the moment has passed. Without it: "today". |

- After that day, the card says how long ago the moment was.
- A time in milliseconds is an error that says to divide it by 1000.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
-- a list: each row opens a link
widget.show{
  title = "Reading list",
  items = {
    { title = "Lua 5.4 manual", trailing = "docs", tap = { url = "https://www.lua.org/manual/5.4/" } },
```

### Taps

`tap` is an action: a table with exactly one of `args` and `url`.

| Action | What a tap does |
| --- | --- |
| `{ args = "add 1" }` | This script runs again with these arguments. They are up to 200 characters, split at spaces. `args` can be empty: the script then runs with no arguments. |
| `{ url = "https://…" }` | The web link opens. |

An action can also have:

- `label`: what a screen reader says for it, up to 24 characters.
- `page = "log"`, with `args`: home turns to the log after the tap. Use it for a run that logs
  something.

Rules:

- In a run that a tap starts, [`event.name`](#event) is `"action"`, as for a
  [button](#buttons) under a line. `event.widget` is `true`, and `event.label` is the action's
  `label`, when it has one. The arguments are in `args`.
- A link must be a web link (`http` or `https`), and the script's internet access must be on. A link
  that is refused is an error in the script, so the card never has a tap that does nothing.
- One card or row starts at most one run in 2 seconds.
- A card with no `tap` refreshes when you tap it.
- A script can't put a terminal command behind a tap.
- A long-press on a card opens **Arrange widgets**.

This widget counts glasses of water. A tap adds one.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
-- @title Water
-- @widget progress 2x1
-- @option goal 8 Glasses a day

local today = os.date("%Y-%m-%d")
local n = tonumber(store.get(today) or "0")
if event and event.name == "action" and args[1] == "add" then
  n = n + 1
  store.set(today, tostring(n))
end
local goal = tonumber(options.goal) or 8
widget.show{
  value = n, max = goal,
  text = n .. " / " .. goal,
  color = n >= goal and "good" or "accent",
  tap = { args = "add", label = "Add a glass" },
}
```
</TabItem>
<TabItem label="JavaScript">
```js

```

This script has no timer. It runs when you place its widget, when you tap it, and when the widgets
page shows it with old content.

### When a widget's script runs

The script's own timers and events fill the widget, as they run the script
([`@every`, `@at`](/scripting/overview/#running-scripts), [`@on`](/scripting/overview/#event-triggers)).
A run fills it only when it calls `widget.show`.

The widgets page asks for runs too. In these runs, [`event.name`](#event) is `"widget"`:

- when you place the widget: one run at once.
- when the widgets page comes into view and the content is older than `staleAfter` (one hour
  without it): one run.
- every `refresh` seconds while the widget is in view, when the description has `refresh`.
- when you tap a card that has no `tap`.

Rules for a `"widget"` run:

- It is quiet. What the script returns isn't logged. Its own `log` lines are, so a script skips
  them when `event.name` is `"widget"`.
- There are never two at once for one script. A script that goes online (`http`, `rss`) waits for a
  network.
- If it fails, the card keeps its content and says "Failed 10:42" under it. A card with no content
  shows the error's first line. The error shows in the log once, until a run works again.
- The next `widget.show` clears the failure.
- A script that is switched off isn't run.

Content older than `staleAfter` stays on the card. The card says its age under it: "2 h ago".

### widget.clear()

Removes the widget's content. The card then says "Nothing to show". Like `widget.show`, it needs
the `@widget` line and works only in saved scripts.

## HTTP

A response is `{ status, ok, body, headers }`:

- `status`: the status code, as a number.
- `ok`: true for 2xx.
- `body`: the body as a string (up to 4 MB is read).
- `headers`: the response headers, with lowercase names.

Requests:

- Kolahal sends the `User-Agent` `Kolahal-Launcher/0.1 (+https://github.com/mtwabpin)` unless you
  set your own.
- A network error raises an error (Lua) or rejects the promise (JS).
- An HTTP error status does **not**, so check `ok`.
- Plain `http://` URLs are allowed.
- A request can go to any address. This phone, your local network (a router, a home server) and a
  VPN address such as Tailscale's 100.x are all allowed. On Android 17 and newer, Android itself
  blocks your local network, and those requests fail after a timeout.
- A JavaScript run makes at most 4 requests at a time. More requests wait in a queue. When 64
  requests and sleeps are waiting at once, another call fails.

### http.get(url, headers?)

<Tabs syncKey="lang">
<TabItem label="Lua">

```lua
local r = http.get("https://api.github.com/repos/neovim/neovim", { Accept = "application/json" })

local repo = json.decode(r.body)
return repo.stargazers_count
```
</TabItem>
<TabItem label="JavaScript">
```js

```

### http.request(opts)

Sends a request with any method. `opts` is `{ url, method, body, contentType, headers }`.

- Only `url` is required.
- `method` defaults to `GET`.
- A string `body` is sent as it is, as `text/plain; charset=utf-8`.
- A table / object `body` is encoded as JSON and sent as `application/json`.
- `contentType`, or a `Content-Type` header, sets a different type.

### http.cached(url, seconds?)

A GET request that reuses this script's stored response while the response is less than `seconds`
old (default 600).

- The result has an extra `cached` field. It is `true` when the result came from the cache.
- Only successful responses are cached, and only their body. A cached result has `status` 200 and
  empty `headers`.
- A response is not cached when:
  - its body is half the store's value limit or more (512 KB of text), or
  - its body contains one of the script's secrets.
- Cached responses count toward the script's [store](#storegetkey--storesetkey-value) limits. When
  the store is full, the script's other cached responses are deleted to make room.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
local r = http.cached("https://open.er-api.com/v6/latest/USD", 6 * 3600)
```
</TabItem>
<TabItem label="JavaScript">
```js
const r = await http.cached("https://open.er-api.com/v6/latest/USD", 6 * 3600);
```
</TabItem>

## RSS and Atom

A feed is returned as `{ title, link, items }`. Each item is `{ title, link, id, date, summary }`.
`rss.fetch` and `rss.fresh` raise an error when the HTTP request fails. To show a friendly message,
wrap them in `pcall` / `try`.

### rss.fetch(url)

Downloads and parses a feed.

### rss.parse(xml)

Parses feed XML that you already have. It is synchronous in both languages.

### rss.fresh(url)

Works like `rss.fetch`, but returns only the items this script hasn't seen before.

- Items are matched by their id. Kolahal remembers the last 500 ids for each URL. For a longer feed
  it remembers more: the feed's item count plus 100.
- Items are marked as seen only **if the run succeeds**. So if a script fails halfway, it gets the
  same items next time.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
local feed = rss.fresh("https://lobste.rs/rss")
for i, item in ipairs(feed.items) do
  if i > 5 then break end
  log(item.title, { url = item.link })
end
```
</TabItem>
<TabItem label="JavaScript">
```js
const feed = await rss.fresh("https://lobste.rs/rss");
for (const item of feed.items.slice(0, 5)) log(item.title, { url: item.link });
```
</TabItem>
</Tabs>

## Storage

### store.get(key) / store.set(key, value)

Strings that are kept between runs. Each script has its own private store.

- `store.get` returns `nil` / `null` for a missing key.
- `store.set(key, nil)` deletes the key.
- To store structured data, encode it as JSON.
- Deleting a script deletes its store.
- One-liners typed at the prompt share one scratch store.

Limits:

- A value can hold up to 1 MB.
- A key can be up to 512 characters.
- A script's store can hold up to 1,000 keys and 16 MB, keys included.
- Sizes are counted as stored: an accented letter or a CJK character takes more than one byte.
- Past these limits, `store.set` raises an error: "value too large", "key too long" or "store full".
- `store.set` rejects a secret, because the store is included in backups.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
local n = tonumber(store.get("runs") or "0") + 1
store.set("runs", tostring(n))
store.set("list", json.encode({ "a", "b" }))
```
</TabItem>
<TabItem label="JavaScript">
```js
const n = Number(store.get("runs") ?? 0) + 1;
store.set("runs", String(n));
store.set("list", JSON.stringify(["a", "b"]));
```
</TabItem>
</Tabs>

### secrets.get(name)

Returns a placeholder for the API key or token that the script names with `@secret`. It never
returns the value itself. Until you set the value, it returns `nil` / `null`.

- Put the placeholder where the request needs the key: a header, the URL's path or query, or the
  body. You can use it alone or joined with other text. It can't be in the site's name.
- Kolahal puts the value in its place when the request goes over https to a site that the
  `@secret` line names.
- A request that carries it anywhere else stops the script
  ([API keys and other secrets](/scripting/overview/#api-keys-and-other-secrets)).
- The placeholder shows as `••••`. A script can't turn it into the value: if the script encodes,
  reverses or cuts it, it is just text.
- Reading a name that has no `@secret` line is an error.
- Code typed at the prompt can't read secrets.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
-- @secret GH_TOKEN api.github.com A GitHub token with read access
local token = secrets.get("GH_TOKEN")
if not token then return "set GH_TOKEN in the script's sheet" end
local r = http.get("https://api.github.com/notifications", { Authorization = "Bearer " .. token })
```
</TabItem>
<TabItem label="JavaScript">
```js
// @secret GH_TOKEN api.github.com A GitHub token with read access
const token = secrets.get("GH_TOKEN");
if (!token) return "set GH_TOKEN in the script's sheet";
const r = await http.get("https://api.github.com/notifications", { Authorization: "Bearer " + token });
```
</TabItem>
</Tabs>

### json.encode(v) / json.decode(s)

Lua only. JavaScript has the built-in `JSON`.

- `json.decode` turns objects into tables, and arrays into sequences that start at 1.
- It raises an error when `s` isn't JSON (for example, an HTML error page). Wrap it in `pcall` when
  the text comes from a site.

```lua
local data = json.decode('{"ip":"203.0.113.7"}')
return json.encode({ ip = data.ip, ok = true })
```

## Device

### clipboard.get() / clipboard.set(text)

Needs `@uses clipboard` ([what a script may use](/scripting/overview/#what-a-script-may-use)).

- Android lets only the focused app read the clipboard. So `clipboard.get()` usually returns `nil`
  in timer runs.
- `clipboard.set` works at any time, for up to 100,000 characters. It rejects a secret.

```lua
-- @uses clipboard
clipboard.set("copied by a script")
```

### device.battery()

Returns `{ level, charging }`. `level` is 0–100 (or nil if unknown). `charging` is true when the
phone is plugged in.

### device.network()

Returns the active network: `"wifi"`, `"cell"`, `"eth"`, `"net"` (any other kind) or `"offline"`.

### device.unlocks(days?)

Without an argument, it returns how many times you unlocked the phone today, as in the header.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
local b = device.battery()
return string.format("%d%% %s · %s · %d unlocks", b.level or -1,
  b.charging and "charging" or "", device.network(), device.unlocks())
```
</TabItem>
<TabItem label="JavaScript">
```js
const b = device.battery();
return `${b.level}% ${b.charging ? "charging" : ""} · ${device.network()} · ${device.unlocks()} unlocks`;
```
</TabItem>
</Tabs>

With `days`, it returns a list instead: one count for each of the last `days` days.

- The oldest day comes first. Today's count is the last one.
- `days` is from 1 to 30. A number outside that is held at its nearest end, and a fraction is
  dropped. Anything that isn't a number is an error.
- The counts are the ones the [`unlocks` command](/guides/apps/#screen-time-and-unlocks) shows. A
  day that Kolahal has no count for is 0.
- It needs no `@uses` line, like today's count.
- Kolahal before 0.5.8 ignores `days` and returns today's count as a number.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
local week = device.unlocks(7)      -- { 12, 30, 0, 45, 7, 1, 8 }
local today = week[#week]           -- 8
```
</TabItem>
<TabItem label="JavaScript">
```js
const week = device.unlocks(7);     // [12, 30, 0, 45, 7, 1, 8]
const today = week[week.length - 1]; // 8
```
</TabItem>
</Tabs>

### device.dnd() / device.setDnd(mode)

Needs `@uses dnd`.

- `device.dnd()` returns the current Do Not Disturb mode: `"off"`, `"priority"`, `"alarms"` or
  `"none"` (total silence).
- `device.setDnd(mode)` sets one of those modes (`"on"` means `"priority"`). It returns `true`, or
  `false` when Kolahal has no Do Not Disturb access. Run `dnd access` once to give it access.
- Since Android 15, a script turns on Kolahal's own Do Not Disturb mode, separate from yours. When
  the script turns it off again, it never turns off one that you turned on yourself.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
-- @uses dnd
if device.dnd() == "off" then device.setDnd("on") end
```
</TabItem>
<TabItem label="JavaScript">
```js
// @uses dnd
if (device.dnd() === "off") device.setDnd("on");
```
</TabItem>
</Tabs>

### apps.list()

Needs `@uses apps`. Returns the apps you can launch, sorted by label: `[{ label, pkg, profile }]`.

- It includes apps in your personal profile, and in a work or clone profile that is on.
- `profile` is `"personal"` or `"other"`.
- It leaves out apps in a paused profile or in the private space.

```js
// @uses apps
const work = apps.list().filter(a => a.profile !== "personal");
return `${work.length} apps outside the personal profile`;
```

### notifications.recent(n?)

Needs `@uses notifications` and [notification access](/guides/notifications/). Without
notification access, it returns an empty list.

Returns the most recent notifications, newest first: `[{ pkg, app, title, text, time }]`.

- `time` is in milliseconds since the epoch.
- `n` defaults to 20. The maximum is 50.

```lua
-- @uses notifications
for _, n in ipairs(notifications.recent(5)) do
  log(n.app .. ": " .. (n.title or "") .. " " .. (n.text or ""))
end
```

## Launcher

### launcher.run(command)

Runs a terminal command as if you typed it. This includes another script's command. Needs
`@uses commands`.

- It works **only when the script was started from the prompt**: a command script, `script run`, or
  a one-liner. In timer and event runs, it logs an error and returns `false`.
- Sensitive commands (`clear`, `uninstall`, `work`, `notifs`, `script` and similar) must be typed by
  you. For these, it logs an error and returns `false`.
- The same applies when the script has no internet access, to:
  - `search`, `yt`, `wiki`, `maps` and `play` with search words,
  - another `@command` script that goes online when it gets words.

  These send the words to a site.
- A run sends at most 10 commands. A script started this way by another script can't send any.

```lua
-- @command
-- @desc Morning: the weather, then the news app
-- @uses commands
launcher.run("weather")
launcher.run("open news")
```

### sleep(ms)

Pauses for up to 5000 ms per call. In JS, use `await sleep(1000)`.

### args and argline

When a script runs as a command:

- `args` holds the words after its name (a table in Lua, an array in JS). Quotes group words.
- `argline` holds the same words joined by spaces.

Both are empty in timer runs.

```js
// @command
// @desc Greet: greet <name>
return `hello, ${argline || "world"} (${args.length} args)`;
```

### options

The script's [`@option`](/scripting/overview/#options) settings by name, as text. Each value is the
one you set in its sheet or with `script set`, or else the default from its line. In code typed at
the prompt, `options` is empty.

```lua
-- @option city London The city to show
log("Weather for " .. options.city)
```

### event

In a run started by an [`@on` trigger](/scripting/overview/#event-triggers), `event` describes what
happened. `event.name` is the event: `unlock`, `charger`, `unplug`, `wifi`, `offline`,
`notification`, `boot` or `headset`. Some events add more fields:

| Event | Other fields |
| --- | --- |
| `charger`, `unplug` | `level` (battery %), and `plug` (`ac`, `usb`, `wireless`, `other`) while plugged in |
| `notification` | `app`, `pkg`, `title`, `text`, `time` |
| `headset` | `type` (`wired`), `device`, `mic` |
| `wifi` | `network` (`wifi`) |
| `boot` | `uptime` (seconds) |

`unlock` and `offline` have only `name`. Text over 2,000 characters is cut short.

Other runs:

- A run at one of the script's [daily times](/scripting/overview/#running-scripts) gets
  `event.name` `"at"` and `event.time`, the scheduled time (`"23:00"`). This is true even when the
  run is late. A script with two times can tell them apart.
- A run that a [status line](#statustext-opts) asks for with `refresh` gets `event.name`
  `"refresh"`.
- A run that a [button](#buttons) under one of the script's lines starts gets `event.name`
  `"action"` and `event.label`, the button's label. Its arguments are in `args`.
- A run that a [tap on the script's widget](#taps) starts gets the same, and `event.widget` is
  `true`. `event.label` is the tap's `label`, when it has one.
- A run that the widgets page asks for gets `event.name` `"widget"`
  ([when a widget's script runs](#when-a-widgets-script-runs)).
- All other runs get nil (null in JavaScript).

## Work profile

### device.work() / device.setWork(on)

Needs `@uses work`.

- `device.work()` returns the work profile's state: `"on"`, `"paused"`, or nil (null in
  JavaScript) when the phone has no work profile.
- `device.setWork(true)` (or `"on"`) resumes it. `device.setWork(false)` (or `"off"`) pauses it.
  It returns `true` when Android accepted the request.

Android limits this:

- Only the default launcher can do it, only while it is in the foreground, and only on Android 10
  and newer.
- A script run at one of its [daily times](/scripting/overview/#running-scripts) counts as in the
  foreground when Kolahal may set exact alarms.
- A run on an interval or an event usually doesn't count, and gets `false`.
- Resuming also returns `false` when your work profile asks for its PIN. Android then asks you for
  it.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
-- @uses work
if device.work() == "on" then device.setWork(false) end
```
</TabItem>
<TabItem label="JavaScript">
```js
// @uses work
if (device.work() === "on") device.setWork(false);
```
</TabItem>
</Tabs>
