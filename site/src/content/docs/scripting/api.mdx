Both languages have the same API.

- In JavaScript, the network calls (`http.*`, `rss.fetch`, `rss.fresh`) and `sleep` return
  promises, so you `await` them.
- Everything else is synchronous in both languages.
- In Lua, calls simply block. This is fine, because scripts never run on the UI thread.

In the descriptions below, a Lua table and a JS object mean the same thing. For example,
`{ status, ok }` means a table with those keys in Lua, and an object with those properties in JS.

## Output

### log(title, body?, ctx?)

Adds a line to the log.

- `title` shows in the script's color (in the link color if the line has a `url`). With a `body`, the title is bold, as a heading over the body. On its own it is in normal weight, so a list of lines stays easy to read.
- The first line of a run ends with the script's name, muted (`… · weather`), unless the line is
  right under the command that ran it.
- `body` is optional. It shows muted under the title, on as many lines as it needs.
- Each line a script logs is a title. To log several lines, call `log` for each one, or use
  [`logs`](#logstitles).
- `log(title, ctx)` also works, without a body.
- `log` returns the line. While the script runs, [`line.set`](#lineset) changes it in place.
- A body taller than `log.fold` lines (8 by default) folds, with a tap to show the rest.

`ctx` is an optional table / object of strings. It sets what happens when you tap or long-press the
line:

| Key | Effect |
| --- | --- |
| `url` | Tap opens the link. Long-press offers open, share and copy. |
| `copy` | What "Copy text" copies instead of the title and body. It must be all or part of what the line shows, or its `url`. Anything else is dropped. |
| `image` | An image URL (http or https). The picture shows under the line, as wide as the log. Long-press offers "Open image". A see-through picture whose lines barely show on the log (dark lines on a dark theme, as Wikipedia's diagrams have) is drawn on a light backdrop, or a dark one on a light theme. |
| `mono` | `"1"`: the line keeps the terminal font even with `font.sans all`, so columns padded with spaces line up. |
| `actions` | Up to 3 [buttons](#buttons) under the line, each `{ label, args }`. A tap runs this script again with those args. |
| `gap` | `true`: the line starts a new item of a list, such as a story with its points under it. A small space shows above it (`log.item-spacing`, 5 dp by default), and the color bar runs through it, so the items stand apart but stay one group. It has no effect on a group's first line or on the line right under the command. From Kolahal 0.5.0; an older one ignores it. |

A link or a picture counts as a network request:

- If internet is switched off for the script, both are removed from the line.
- If one contains a secret, it must go over https to the site that the `@secret` line names.

Other keys are dropped. Whatever keys the launcher uses itself, a script can't add a line that runs
a command or dials a number when you tap it.

### md.log(title, body?, ctx?)

Works like [`log`](#logtitle-body-ctx), but shows Markdown in the title and the body:

- `**bold**` (or `__bold__`), `*italic*` (or `_italic_`), `~~strike~~`, `++underline++` and
  `` `code` ``.
- `[text](https://…)` is a [link](#links): the text opens the address when tapped.
- In the body, a line that starts with `- `, `* ` or `+ ` is a bulleted item. A line that starts
  with `1. ` is a numbered item. Two spaces before it make a second level.

`log` itself never shows Markdown. So text from the web that you log with `log` always appears
exactly as written.

`md.escape(text)` puts a backslash before every Markdown mark in `text`, `[` included. Use it to put
text from the web inside `md.log`, so that it still shows exactly as written.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
local item = {
  title = "Show HN: Kolahal, a launcher",
  link = "https://example.com/hn",
}

md.log(
  "**3** new releases",
  "- neovim `v0.11.4`\n- termux ~~v0.118~~ v0.119"
)

md.log(
  "**HN** " .. md.escape(item.title),
  nil,
  { url = item.link }
)
```
</TabItem>

| `fmt.plain(text)` | the text without its styles | the same text, with no styles |

Each picture is one line, such as `log("Rent " .. fmt.bold("due today"))`. The script editor's API
reference shows the same lines under these functions, drawn in your theme.

Colors:

- You choose a color by its role, never by its value. The theme picks each color, in a dark and a
  light version, so the line is readable on every theme.
- `good` is for up, done or passing. `warn` is for something less than an error. `bad` is for down
  or failed (the theme's error color).
- Also show the meaning in the text (`▲`, `▼`, "down"). People can easily miss a color alone.

Where styles work:

- Styles appear in the log, and in a few texts of a widget
  ([styles in a widget](#styles-in-a-widget)). Notifications, status lines, Copy text and search
  use the plain text.
- A styled string is normal text with invisible marks around the styled parts. So shorten text
  before you style it. If text is cut in the middle of a mark, the style continues to the end of the
  line.
- Use `fmt.plain` before you store a styled string or send it anywhere else.

### Tables

`fmt.table(rows, opts?)` makes a table to use as a line's body. Each row is a list of cells.

- `opts.header`: `true` makes the first row the header. It names the columns and shows muted.
- `opts.align`: one letter for each column, `l` (left) or `r` (right). Numbers read best on the
  right. Columns without a letter are on the left.
- A cell is one line: a line break in it becomes a space. Cells take the other `fmt` styles and colors.
- Up to 8 columns and 50 rows besides the header. More rows end with a "+N more" line.
- The table shows in the terminal font, so its columns line up. A table wider than the screen
  scrolls sideways.
- How it looks is the user's choice (`log.tables`): boxed (the default) or plain columns.
- **Copy text** copies the table with tabs between the cells, so it pastes into a spreadsheet.
- Text can come before and after the table in the same body: join them with `"\n"`.

### Links

`fmt.link(text, url)` makes `text` a link: a tap on it opens `url`. A tap anywhere else on the
line does what a tap on the line does (opens its `url`, if it has one).

- A line can have several links, in its title and its body: a story and its comments, release
  notes and a diff.
- Links are in the link color and underlined.
- They follow the rules of a line's `url`: web links only (http and https), none when internet is
  off for the script, and none that carries a secret anywhere but the sites its `@secret` line
  names. A link that breaks a rule shows its text as plain text.
- Long-press the line for **Open "…"** for each link (up to 4).
- In `md.log`, `[text](https://…)` makes a link too.
- Everywhere else (Copy text, search, notifications) only the text shows.

```lua
  comments = "https://example.com/c",

log(
  item.title .. " · "
    .. fmt.link(
      "138 comments",
      item.comments
    ),
  { url = item.link }
)

md.log(
  "New in [neovim](https://github.com/neovim/neovim/releases)"
)
```

### Tags

`fmt.tag(role, text)` shows a short label on a chip shaded in one of the theme's colors, by role,
as [`fmt.color`](#styles-fmt) takes it. `fmt.tag(text)` uses the accent color.

- Use it for a state or a version: LIVE, NEW, pre-release, v0.12.0. For code, use `fmt.code`.
- A tag is one line, in bold and a little smaller than the text around it.
- Put a space between two tags, and between a tag and the text next to it.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
log(
  fmt.tag("bad", "LIVE") .. " IND v NZ"
)

log(
  "neovim/neovim " .. fmt.tag("v0.12.0")
    .. " "
    .. fmt.tag("warn", "pre-release")
)
```

### Bars

Three functions make bars for a body. Each bar is a line of its own, like a table row. Bars on
lines that follow each other line up in columns: the labels, the texts before the bars, the bars,
and the texts after them.

| Function | Shows |
| --- | --- |
| `fmt.bar(value, opts?)` | one bar as wide as the line: `value` out of `opts.max` (1 by default) |
| `fmt.bars(rows, opts?)` | a bar for each row, all on one scale from 0 to `opts.max` (by default the largest value), so the rows compare at a glance. `text` shows after the bar; by default it is the value with `opts.unit`. A row is a list in this order: label, value, text, as `{ "Mon", 42 }` |
| `fmt.ranges(rows, opts?)` | for each row, a bar from low to high, all on one scale from `opts.min` to `opts.max` (by default the lowest low and the highest high). The low shows before the bar and the high after it. A row is a list in this order: label, low, high, lowText, highText, as `{ "Mon", 18, 27 }` |

- `opts.color` is the bars' color, by role (`accent` by default). The unfilled part of a bar is
  a light shade of the same color.
- `opts.unit` goes after each number that the bar shows itself, such as `°` or `%`.
- A value past the scale fills its bar, and one below it leaves it empty.
- Up to 50 rows. More end with a "+N more" line.
- Say the number in the text too: some people can't see a bar's length, and a screen reader
  reads only the texts.
- A wrong argument is an error that says what to pass, and so is an option that doesn't exist (a
  typo such as `colour`).
- Copy text copies the rows' texts with tabs between them. A bar alone copies nothing.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
log(
  "Pune · AQI 168",
  "Unhealthy\n"
    .. fmt.bar(
      168,
      { max = 300, color = "bad" }
    )
)

log(
  "Unlocks",
  fmt.bars(
    { { "Mon", 42 }, { "Tue", 21 } },
    { color = "good" }
  )
)

log(
  "Pune · 3 days",
  fmt.ranges(
    {
      { "Today", 23, 31 },
      { "Tomorrow", 22, 30 },

    { unit = "°", color = "warn" }
  )
)
```
</TabItem>

### line.set

`log` and `md.log` return the line they added. `line.set(title, body?, ctx?)` changes that line
in place, where it is in the log. In Lua, `line:set(…)` works too.

- Show something at once, then the answer in the same place: "Fetching…" turns into the result.
  A slow script then doesn't look stuck, and leaves one line, not two.
- Show progress: "Checking 3 of 5 sites…", with a [bar](#bars).
- It takes what `log` takes. A line from `md.log` reads Markdown again.
- It works only while the script runs. After that, the line stays as it was last set.
- A run can change its lines 300 times. Later changes are ignored.
- Changes show about every 300 ms, and before each request.
- Kolahal versions before 0.4.16 return nothing from `log`. A script for those too can check
  `typeof fmt.bar === "function"` (JavaScript) or `fmt.bar ~= nil` (Lua) first.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
local line = log(fmt.color("muted", "Checking…"))
local up = 0
for i, site in ipairs(sites) do
  line.set("Checking " .. i .. " of " .. #sites .. "…", fmt.bar(i - 1, { max = #sites }))
  local ok, r = pcall(http.get, site)
  if ok and r.ok then up = up + 1 end
end
line.set(up .. " of " .. #sites .. " sites up")
```
</TabItem>
<TabItem label="JavaScript">
```js
const line = log(fmt.color("muted", "Checking…"));
let up = 0;
for (const [i, site] of sites.entries()) {
  line.set(`Checking ${i + 1} of ${sites.length}…`, fmt.bar(i, { max: sites.length }));
  try {
    if ((await http.get(site)).ok) up++;
  } catch (e) {}
}
line.set(`${up} of ${sites.length} sites up`);
```
</TabItem>
</Tabs>

### status(text, opts?)

Sets this script's status line. Kolahal uses the first line of `text`, at most 80 characters.

- The line shows on the script's card in Scripts and in `status`.
- After you pin the script, it also shows in the
  [pinned header](/getting-started/basics/#the-pinned-header) at the top of home. Pin it with
  `script pin <name>` or **Pin to the top** in its menus. A script can't pin itself.
- `status(nil)` / `status(null)` or an empty string clears the line.
- It works only in saved scripts, because the line is stored under the script's name.
- Tapping the line at the top runs the script.
- A run can change the line at most 20 times. Setting the same line again doesn't count.

`opts` can have:

- `progress`: how far along, from 0 to 1. It is drawn as a bar under the line at the top. Without
  it, there is no bar.
- `color`: the bar's color, by role, as [`fmt.color`](#styles-fmt) takes it: `good`, `warn`, `bad`, `info`,
  `accent` (the default), `link`, `muted` or `text`. The theme picks the color, so it reads on
  every theme. For example, an air quality bar in `warn` or `bad` when the air is poor. Kolahal
  versions before 0.4.16 ignore it.
- `refresh`: run the script again every this many seconds (10 at the fastest, up to 3600) while
  home shows the line at the top. This keeps the line current.
  - In these runs, [`event.name`](#event) is `"refresh"`. The script can use this to skip work that
    only a typed command needs.
  - These runs happen only while home is on screen and the script is pinned.
  - When the line stops changing, set it without `refresh`.
  - If these runs fail, the error shows once, until a run works again.
  - What these runs return isn't logged. Their own `log` lines are.

Any other key, a `progress` or `refresh` that isn't a number, or a `color` that isn't a role, is an
error. Kolahal versions before 0.4.14 ignore
`opts`.

<TabItem label="Lua">
```lua

status("NZ 136/8 (33.2 ov) v IND", { progress = 200 / 300, refresh = 30 })
status("AQI 168", { progress = 168 / 300, color = "bad" })
status(nil)
```
</TabItem>
<TabItem label="JavaScript">
```js

status("NZ 136/8 (33.2 ov) v IND", { progress: 200 / 300, refresh: 30 });
status("AQI 168", { progress: 168 / 300, color: "bad" });

```
</TabItem>

- `value` is a number, or a word of letters, digits and `-`. `true` is 1 and `false` 0. A number from 0 to 1 is spread over a

- It stays until the script changes it, also after a restart. It goes when the script is switched off or deleted.
- It works only in saved scripts. A run can change values 40 times. Giving the same value again doesn't count.
- The script's sheet shows which parameters follow it.

### allowed(what)

Returns whether this script may use `what`. `what` is one of:

- `"internet"`, `"header"`, `"widget"`,
- an `@uses` item: `"notifications"`, `"clipboard"`, `"apps"`, `"commands"`, `"dnd"`, `"todos"`,
  `"notes"`, `"reminders"`, `"calendar"`, `"feeds"`, `"usage"`, `"screen"`, `"effects"`, `"work"`,
- an `@on` event, such as `"unlock"`.

You switch these on and off for each script
([switching access off](/scripting/overview/#switching-access-off)). When one is off, the script
can do something else instead.

- A script has `"internet"` only if its code uses `http`, `rss`, `url`, `image` or `launcher.run`.
- `"header"` means you pinned the script, so its status line shows at the top of home. A script has
  it only if it calls `status`.
- `"widget"` means you placed the script's [widget](#widgets) on the widgets page. A script has it
  only if it has an `@widget` line. It has no switch: placing the widget turns it on, and removing
  the widget turns it off.
- Code typed at the prompt gets `true` for everything.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
if allowed("header") then status(text) else log(text) end
```
</TabItem>
<TabItem label="JavaScript">
```js
if (allowed("header")) status(text); else log(text);
```
</TabItem>
</Tabs>

Whatever the script returns is printed as an output line. Tables and objects are printed as JSON.
Long-press the line to copy it. If a one-liner run with `lua` / `js` produces nothing, it prints
`nil`.

## Widgets

A script can fill a card on the [widgets page](/guides/widgets/), or
[several](#several-widgets-from-one-script). The script says what to show: a
kind of card, and that kind's fields. Kolahal draws the card, in the theme's colors. A script
draws nothing itself.

1. Put an [`@widget` line](#the-widget-line) at the top of the script.
2. Call [`widget.show`](#widgetshowdesc) with a description: a table in Lua, an object in
   JavaScript.
3. Place the widget: tap **+** at the top of the widgets page. The picker lists your scripts'
   widgets in the **Kolahal** group. A script can't place its own widget.

Widgets need Kolahal 0.5.8 or newer. To start from a widget that works, install a template from the
[library](/scripting/library/#templates): **template-widget** shows a number from the web, and
**template-widget-list** is a checklist you tap. Each also comes in JavaScript (`-js`).

```lua
-- @title Steps

widget.show{

  value = "6,240",
  label = "Steps today",

      value = "4.1 km",
      label = "walked",
    },
  },
}
```

### The @widget line

```lua
-- @widget <kind> [<size>]
```

- The kind is the card to draw. A description can name another kind with its `kind` field.
- The size is the size the widget has when you place it: `1x1`, `2x1`, `2x2`, `4x1`, `4x2` or
  `4x4`. It is in cells of a 4-column grid, as home screens count them, the width first. One cell
  is a quarter of the page wide.
- Without a size, the kind's own size is used. It is in the table below.
- After that, you resize the widget like any other
  ([Arrange and resize](/guides/widgets/#arrange-and-resize)). It can be as small as a quarter of
  the page wide and 72dp tall.
- A card draws for the space it has, not for the size on this line. A small card shows less.
- A script has one `@widget` line. You can place its widget more than once, each with its own
  options ([several widgets from one script](#several-widgets-from-one-script)).
- Without this line, `widget.show` is an error that says to add it.

| Kind | Shows | Size without one |
| --- | --- | --- |
| `stat` | one big value with its label, and up to 3 smaller values | `2x1` |
| `text` | a few lines of text, and a caption | `2x2` |
| `list` | rows | `4x2` |
| `progress` | a ring or a bar, up to 4 bars or rings, a gauge, or stages | `2x1` |
| `chart` | numbers over time, as a line, as bars or as a dot for each day | `2x2` |
| `countdown` | the time to a moment. Kolahal counts it down, with no run | `2x1` |
| `buttons` | 1 to 8 buttons | `4x1` |
| `toggles` | 1 to 6 switches, each on or off | `4x1` |
| `clock` | the time in up to 4 places. Kolahal moves the clocks, with no run | `2x1` |
| `agenda` | events by day | `4x2` |
| `image` | a picture from the web, with a caption | `2x2` |
| `versus` | two sides and the score between them, for a match or a game | `4x1` |
| `sky` | the sun's path from its rise to its set, or the moon's. Kolahal moves it, with no run | `2x2` |

Kolahal has one more kind, `media`, for its own
[Now playing widget](/guides/widgets/#kolahals-own-widgets). A script can't use it: it is an error
on the `@widget` line and in `kind`.

### widget.show(desc)

Checks the description `desc` and stores it as this script's widget. The card then shows it.

- `kind` names the card to draw, such as `kind = "stat"`. It may be left out: the card is then the
  kind on the script's `@widget` line. A `kind` in the description wins over that line.
- When the script has [several widgets](#several-widgets-from-one-script), it fills the one the
  run is for. A run that is for no widget fills the first one.
- It returns `true` when you placed the widget.
- It returns `false` when you didn't. The description is still checked, so a mistake shows either
  way. But nothing is stored.
- [`allowed("widget")`](#allowedwhat) tells the same before the call. A script can skip its work
  when it is `false`.
- It works only in saved scripts, like `status`. Code typed at the prompt gets a line that says so.
- A run can call `widget.show` and `widget.clear` 20 times in all. Later calls change nothing.
- A description can be 32 KB at most.
- Kolahal before 0.5.8 has no `widget`. A script that must also run there checks first:
  `if widget then … end` in Lua, `if (typeof widget !== "undefined") …` in JavaScript.

Rules for every description:

- An unknown field is an error that lists the fields the kind has. So a typo such as `colour`
  doesn't pass unseen.
- Each field has one type. A number where text is expected becomes text. Any other wrong type is an
  error that names the field.
- A field with no value (`nil`, `null`, `undefined`) counts as left out.
- Text over its limit is cut, with "…" at its end. A list over its limit keeps its first items.
- Buttons and switches are never cut. More than the kind takes is an error: a button that was
  left out without a word would be a tap you can't make. [Limits](#limits) has every number.
- Text is plain, except in a few fields that keep some styles from [`fmt`](#styles-fmt)
  ([styles in a widget](#styles-in-a-widget)). Everywhere else, styles are removed. A secret's
  value is masked, as in the log.
- A label starts with a capital, whatever the script writes
  ([capitals in a widget](#capitals-in-a-widget)).
- A color is a role, never a color value. The theme picks the color, so the card reads on every
  theme.

Every kind takes these fields. All are optional.

| Field | Value | What it is |
| --- | --- | --- |
| `kind` | a kind's name | The card to draw. Without it: the kind on the `@widget` line. |
| `title` | text, up to 40 characters | The card's name. A card has no title line: the name shows small where the content doesn't say what it is, over a large list or text, or as the label of a number, a bar, a ring, a chart or a countdown that has none. A screen reader always says it. Without it: the script's `@title`, or its name. |
| `icon` | an icon name, or text up to 4 characters | An icon from the list in [Icons](#icons), such as `"sun"`, drawn in the card's color by the Bold, Split and Shape looks; or an emoji or a letter. |
| `color` | a role | The color of the bar, the ring, the chart or the note: `accent` (without it), `link`, `info`, `muted`, `text`, `good`, `warn` or `bad`. The user can choose another for a placed card in its Color row in Arrange widgets; that one then wins, also over a color the script changes with what it shows. |
| `shape` | `cookie9`, `cookie12`, `clover4`, `clover8`, `sun` or `burst` | The card's shape in the **Shape** look, until the user chooses one in its Shape row: a 9-sided or 12-sided cookie, a 4-leaf or 8-leaf clover, a sun or a burst. Only for a card that is one shape, or whose main value sits in one: a `stat`, `text`, `progress` (not its bars), `chart` (not a habit's week), `clock` or `image`. Without it: the kind's own, such as a cookie for a `stat` and a clover for a `progress`. Needs Kolahal 0.5.17. |
| `tap` | an action | What a tap on the card does ([Taps](#taps)). Without it, a tap refreshes the card. |
| `staleAfter` | seconds, 60 to 604800 | How long the content counts as current. Without it: one hour, or one minute for `toggles`. |
| `refresh` | seconds, 10 to 3600 | Run the script again this often while the widget is on screen. A widget scrolled out of sight waits, and runs as soon as it is back if its time has passed. |
| `note` | text, up to 16 characters | A few words in the card's color on a large card's last line, before the content's age: `Done today`. A wide or small card has no room for that line; a screen reader still says the note. Needs Kolahal 0.5.11. |

No card has a title line: the content has the card's room. A large card's last line has the note
and the content's age or "Failed 10:42". A wide or small card has no room for that line, and a
screen reader says them all the same.

| `label` | text, up to 60 | What the value is, under it. |
| `unit` | text, up to 12 | Its unit: `°C`, `km`. |
| `delta` | text, up to 16 | A change, such as `+2.4%`. |
| `trend` | `up`, `down` or `flat` | An arrow for the change. |
| `more` | a list of `{ value, label }` | Up to 3 smaller values. Each text is up to 24 characters, and `value` is needed. |
| `progress` | a number, 0 to 1 | A bar under the value. |
| `moving` | true or false | Draws the bar as a wave, for something in progress. |
| `points` | a list of numbers | The value's recent numbers, the oldest first: a soft line from edge to edge under the value, as a chart's line. The last 60 are kept. A `1x1` card leaves it out. Needs Kolahal 0.5.17. |
| `scene` | a shader's name | A still of that shader as the card's ground, under a scrim that keeps the figures readable ([scenes](#a-stats-scene)). Needs Kolahal 0.5.17. |

#### A stat's scene

With `scene`, a stat's card has a still of one of Kolahal's [shaders](/scripting/shaders/) as its
ground, such as the pond on a clear night or rain when it rains. The figures sit over it on a scrim
of the card's color, strongest where they are, so they read on a light and a dark theme.

- Name a shader that draws a picture behind the text: one that can be a wallpaper. The ones that
  suit weather are `pond`, `rain`, `snowfall`, `dunes` and `mountains`; `night`, `aurora`, `dusk`,
  `frost` and the others work too, and so does a shader of your own.
- `crt`, `lcd`, `eink`, `riso` and `foil` work on the text, and `hearts` and `pulse` play once: they
  are an error here. A shader of your own that does either is left out when the card draws.
- It is one frame, drawn again only when the card is: it never moves, and costs nothing while the
  card sits there. Its time of day follows the phone's.
- It shows in the **Plain**, **Tonal** and **Bold** looks, in place of the card's color. **Split**,
  **Shape** and **Poster** keep their own.
- Without it the card is the plain stat: under Android 13, with TalkBack on, and when the shader is
  missing or doesn't compile.

**`text`**: a few lines.

**`list`**: rows. The card shows as many rows as fit, and says "+3 more" under them.
When every row fits, the rows grow to fill the card.

| Field | Value | What it is |
| --- | --- | --- |
| `items` | a list of rows | Needed. The first 12 are kept. It can be empty. |
| `empty` | text, up to 60 | What the card says with no rows: `Nothing new`. |
| `lead` | `{ value, unit, label }` | A big line over the rows: `value` (needed, up to 24) big, its `unit` (up to 12) small, and `label` (up to 60) under them: the next reminder, or the total of the rows. A small or a wide card shows the lead alone, and counts the rows as "+3 more". |

Each row is `{ title, detail, trailing, icon, color, tap, done, range }`. Only `title` is needed.

| Field | Value | What it is |
| --- | --- | --- |
| `title` | text, up to 80 | The row's text. |
| `detail` | text, up to 120 | A second line. |
| `trailing` | text, up to 24 | A short text at the row's end: a price, a count. |
| `icon` | an icon name, or text up to 4 | An [icon](#icons), an emoji or a letter in front, in the row's color. |
| `color` | a role | The color of its icon, or of a dot in front when it has no icon. The `trailing` text stays dim. |
| `tap` | an action | What a tap on the row does ([Taps](#taps)). |
| `done` | true or false | The row has a checkbox in front: ticked with `true`, empty with `false`. Without it, the row has none. |
| `range` | `{ low, high, value }` | A bar from `low` to `high`, between the row's text and its `trailing` text, in the row's color or the card's. `value` is a dot on the bar. Needs Kolahal 0.5.16. |

A checkbox is for a todo or a habit. It only shows a state: Kolahal doesn't change it. Give the
row a `tap` with `args`, and let that run change the thing and call `widget.show` again.

A range is for numbers that compare at a glance: each day's lowest and highest temperature, or a
price's low and high of the day, with `value` where it is now.

- `low` and `high` are numbers, and both are needed. `low` above `high` is an error.
- `value` is a number. One outside the range is held at its nearer end.
- The bars are all on one scale: from the lowest `low` to the highest `high` of the rows the card
  shows. So they line up and compare.
- Give the numbers in `trailing` too. The bar is drawn beside them, never in their place. A screen
  reader says the row's texts; a row with a range and no `trailing` says "from 22 to 31", and a
  range with a `value` says it too: "27, from 22 to 31".
- A bar is at least 48dp long. Where a row is too narrow for that, the icons go first, and then
  the bars. The texts stay.

**`progress`**: how far along something is, as a ring, a bar, several bars, a gauge, rings inside
each other, or stages. It needs `value`, `items` or `stages`.

| Field | Value | What it is |
| --- | --- | --- |
| `value` | a number | How far along it is, from 0 to `max`. |
| `max` | a number above 0 | The top of the scale. Without it: 1. |
| `text` | text, up to 24 | What the ring's middle says: `68%`. Without it: the percent. A gauge's value. |
| `label` | text, up to 60 | What it is. A gauge's word for its value: `High`. |
| `style` | `ring`, `bar`, `gauge` or `rings` | Without it, the card picks a ring or a bar for the space it has. `gauge` and `rings` are below. |
| `items` | a list of bars | Up to 4 bars, each `{ label, value, max, text, color, unit, moving }`: a `label` up to 40 characters, a `text` up to 24, a `unit` up to 12. `value` is needed. |
| `moving` | true or false | Draws the ring and the bars as waves, for something in progress. |
| `min` | a number below `max` | A gauge's lowest value. Without it: 0. |
| `unit` | text, up to 12 | A gauge's unit: `US AQI`, `km/h`. |
| `zones` | a list of zones | A gauge's zones, up to 5, each `{ from, color }`. |
| `stages` | a list of 2 to 6 texts, up to 24 each | The stages, the first one first: `Ordered`, `Shipped`, `Delivered`. |
| `stage` | a whole number | The stage it is at: 1 for the first. Needed with `stages`. |

A value is held between 0 and its `max`. Bars are on one scale: the widget's `max`, or else the
largest value among them. A bar with its own `max` uses that.

A **gauge** (`style = "gauge"`) is a thick arc from `min` to `max`, filled to the value, with the
value large in it: air quality, UV, wind. Needs Kolahal 0.5.17.

- `zones` color the arc: each zone is `{ from, color }`, both needed, and runs from its `from` to
  the next zone's, the last one to `max`. Each zone starts above the one before. A `from` outside
  the scale is held at its nearer end.
- The arc is filled in each zone's color up to the value, and dim past it. Without zones, it is
  in the card's color.
- `label` is the word for the value, in the color of the zone the value is in: `Unhealthy for
  some`. `unit` is written with the value.
- The value is held between `min` and `max`. Only a gauge takes `min` and `zones`: on any other
  style they are an error.
- A 2×2 has the arc around the value, and the word under it. A 1-row card has half the arc, with
  the title, the word and the unit beside it.

**Rings** (`style = "rings"`) draw `items` as rings inside each other, the first outside: steps,
water, sleep. Needs Kolahal 0.5.17.

- Each ring is in its `color`, or the card's, with a dim track. A ring with `moving` is a wave: the
  one still in progress.
- A 4×2 names each ring beside them, with its value large and its scale after it: "6,240 of 8,000".
  `unit` goes after the scale: "5 of 8 glasses". The value is the ring's `text`, or its number.
- A 2×2 has the values of the first 3 under the rings; a 1-row card has them beside the rings, as
  many as fit. A value there is the ring's `text`, or its percent.
- `rings` needs `items`.

**Stages** (`stages`) are a path of fixed steps: a parcel, a flight, a build. Needs Kolahal 0.5.17.

- Stages done are ticked dots, the one it is at (`stage`) is a cookie, and later ones are rings.
- The way from the current stage to the next is a wave. `value` of `max` says how far along that
  way it is, from 0 to 1 without a `max`. Without `value` the wave is short: it is on its way.
  With `moving`, the wave moves.
- The current stage's name is the card's main text, and `label` is a line under it: `Arrives
  Thursday`. A 4×1 has each stage's name under its dot.
- `stages` keeps its first 6 names and needs 2. `stage` must be one of them. Stages take no `items`
  and no `style`.

**`chart`**: numbers over time.

| Field | Value | What it is |
| --- | --- | --- |
| `points` | a list of numbers | Needed. The oldest comes first. The last 60 are kept. |
| `style` | `line`, `bars` or `dots` | Without it: `line`. `dots` draws a dot for each day (below). |
| `min`, `max` | numbers | The scale. Without them, it comes from the points; bars start at 0. `min` must be below `max`. |
| `value` | text or a number, up to 40 | The headline over the chart. |
| `label` | text, up to 60 | What the headline is. |
| `labels` | a list of two texts, up to 16 each | Words for the first and the last point: `Mon`, `Today`. |
| `summary` | text, up to 200 | What a screen reader says for the chart. |

With `style = "dots"`, each point is a day, and the last point is today. Needs Kolahal 0.5.16.

- The card draws a calendar: a row for each week, from the first day of the week in your phone's
  region, with as many weeks as fit. Today's dot is in today's column. A `2x1` card has the last 7
  days in one row.
- When every point is 0 or 1, as for a habit, a 1 is a filled dot and a 0 is a ring. Any other
  points are filled dots whose size is the value, on the scale of `min` and `max`, or else of the
  days shown.
- Today's dot is larger. When it turns from 0 to 1, it grows into a filled shape. The days still to
  come this week are small dots.
- `labels` are not shown: the days of the week are over the calendar.
- In the **Shape** look, a `1x1` or `2x2` card with a week of days or fewer, all 0 or 1, is a
  flower with a leaf for each day of the week: a leaf for each day done, a faint one for the days
  missed or still to come, and the days done this week in the middle. A longer run keeps its
  calendar.
- Without a `summary`, a screen reader says "Done on 23 of the last 35 days", or for other points
  "35 days, from 26 to 62, today 42".

**`countdown`**: the time to a moment. The script gives the moment once, and Kolahal counts. No
run is needed as time passes.

| Field | Value | What it is |
| --- | --- | --- |
| `to` | a time in seconds | Needed. The moment: `os.time{…}` in Lua, `Date.now() / 1000` in JavaScript. |
| `from` | a time in seconds, before `to` | Where the wait started. With it, the card has a bar from the start to the moment. A large card writes both dates under the bar. |
| `label` | text, up to 60 | What the moment is. |
| `style` | `days`, `clock`, `dots` or `page` | `days` says "12 days", `clock` says "03:25:10". Without it: days while the moment is more than 48 hours away, a clock after that. `dots` draws a dot a day, and `page` the date as a calendar page (below). |
| `reached` | text, up to 60 | What the card says on the day, once the moment has passed. Without it: "Today". |

- After that day, the card says how long ago the moment was.
- In the **Shape** look, a `1x1` or `2x2` card is a sun with a ray for each step of the wait that
  is left, 12 at most, and it loses a ray as each step goes. A step is a day for a wait of a day
  or more, an hour for a shorter one, and five minutes for one under an hour. The wait runs from
  `from` when the card has one, else it is the time left. With less than a step left, the sun is
  a plain circle.
- A time in milliseconds is an error that says to divide it by 1000.

With `style = "dots"`, the days left are dots in a grid, today's ringed, with the number and
"days left" under them. A dot goes out each day. With `from`, the days already over stay as small
faint dots; without it, there are only the days left. Needs Kolahal 0.5.17.

- A day is the phone's day: a moment on 20 December is 26 days away all through 24 November.
- Over 60 days, a dot is a week, and the card says "A dot a week". Over 60 weeks, the card has the
  number without dots.

With `style = "page"`, the moment is a calendar page: the month on a band, the day large, and
beside it the card's name, "In 26 days" and the weekday. On the day, the weekday's place has the
moment's time. A large card has the bar from `from`. Needs Kolahal 0.5.17.

- Both count days on the calendar to the end, never as a clock, and change at midnight with no
  run. On the day they say "Today", or `reached` once the moment has passed.
- In the **Shape** look, `dots` go round a circle and `page` is cut to a shape, in place of the
  sun. **Poster** keeps its number.

**`buttons`**: 1 to 8 buttons. Each button has its own tap.

| Field | Value | What it is |
| --- | --- | --- |
| `items` | a list of buttons | Needed: 1 to 8. No buttons, or more than 8, is an error. |

Each button is `{ label, icon, color, tap }`. `label` and `tap` are needed.

| Field | Value | What it is |
| --- | --- | --- |
| `label` | text, up to 24 | The button's text. |
| `icon` | an icon name, or text up to 4 | An [icon](#icons), an emoji or a letter in front of the text. |
| `color` | a role | The button's color. |
| `tap` | an action | Needed. What the button does: `{ args }` runs this script again, `{ url }` opens a web link ([Taps](#taps)). |

- A small card shows fewer buttons, never smaller ones. So put the important ones first.
- A button is at least 48dp tall. The same goes for `toggles`.
- A button can't run a terminal command. In a run that a button starts, the script can use
  [`launcher.run`](#launcherruncommand), under its rules.

**`toggles`**: 1 to 6 switches. Each has a state, on or off, that the script reports.

| Field | Value | What it is |
| --- | --- | --- |
| `items` | a list of switches | Needed: 1 to 6. No switches, or more than 6, is an error. |

Each switch is `{ label, icon, on, tap }`. `label`, `on` and `tap` are needed.

| Field | Value | What it is |
| --- | --- | --- |
| `label` | text, up to 24 | The switch's text. |
| `icon` | an icon name, or text up to 4 | An [icon](#icons), an emoji or a letter in front of the text. |
| `on` | true or false | Needed. The state now. |
| `tap` | `{ args }` | Needed. The arguments that switch it. A link is an error: a switch always runs this script again. |

A switch is filled while it is on. Where there is room, it says "On" or "Off" under its label.

How a switch works:

1. You tap it. The switch shows that it is working.
2. The script runs with the tap's arguments. [`event.name`](#event) is `"action"`.
3. The script changes the thing, for example with
   [`device.setDnd`](#devicednd--devicesetdndmode). Then it calls `widget.show` with the new
   state.
4. When the run ends, the switch stops waiting. It shows the state that the script reported.

- Kolahal never guesses the new state. So call `widget.show` in every run that a tap starts, also
  when the change didn't work. The same description as before is fine.
- A run that fails ends the wait too. The switch then shows the state it had, the card says
  "Failed 10:42" under it, and the error is in the log. So when a change can't be made, call
  `widget.show` with the state as it is, and raise an error after it.
- With no answer in 10 seconds, the switch stops waiting and shows the state it had.
- A second tap on the same switch within 2 seconds does nothing. No run starts for it.
- The thing can change outside Kolahal. So without `staleAfter`, the content of a `toggles`
  widget counts as old after one minute, not one hour. The widgets page then runs the script when
  it shows the widget. The card says its age only after an hour, so the line doesn't come and go.

**`clock`**: the time in up to 4 places. The script gives the places once, and Kolahal moves the
clocks. No run is needed as time passes.

| Field | Value | What it is |
| --- | --- | --- |
| `zones` | a list of places | Needed, with at least one place. The first 4 are kept. |
| `seconds` | true or false | Shows the seconds too. |

Each place is `{ zone, label }`. `zone` is needed.

| Field | Value | What it is |
| --- | --- | --- |
| `zone` | a time zone's name | Needed: `Asia/Kolkata`, `Europe/London`, `America/New_York`, `UTC`. A name that Kolahal doesn't know is an error that names it. |
| `label` | text, up to 24 | What to call the place. Without it: the last part of the zone's name, "New York" for `America/New_York`. |

- Each place shows how far its time is from your phone's: "5 h 30 min behind", "3 h ahead",
  "Same time", or "Here" for your phone's own time zone. A place whose day isn't your day says so
  too: "10 h 30 min behind · Yesterday".
- Where there is little room, the card writes it shorter: "−5:30", or "−10:30 −1" for a place on
  the day before. On a one-line label where even that doesn't fit, only the day shows: "+1" or
  "−1". A screen reader always hears the difference in words.
- Kolahal writes each time in 12-hour or 24-hour form, as the header does
  ([`clock.24h`](/reference/config/)).
- A small card shows the first place only. A wide one shows as many as fit, side by side.
- A large card has a row for each place. A row with room (three places in a 2×2 card) has the
  difference under the place's name.
- A 4×2 card, or any large card as wide, with two places or more also has a strip of the day for
  each place, in the Plain and Tonal looks. One place keeps its big time. Each strip is your day
  from 00 to 24, shaded by the time at that place: night (before 06:00 and from 22:00), day, and
  working hours (09:00 to 18:00). A line across the strips marks the time now.
- Tap a strip to move the line to that hour: every place then shows its time at that hour of your
  day, from 00:00 to 23:00. Tap the line again, or tap **Now** under the strips, to go back to
  now. Leaving the widgets page, or a new day, goes back to now too. A tap on a strip doesn't run
  the script.
- A clock never gets old. Give it a long `staleAfter`, such as a week (604800), so the widgets
  page doesn't run the script each hour for nothing.

**`agenda`**: events by day. The script gives the events with their times, and Kolahal writes the
times and the days.

| Field | Value | What it is |
| --- | --- | --- |
| `events` | a list of events | Needed. The first 20 are kept. It can be empty. |
| `days` | a number, 1 to 14 | How many days to show, from today. Without it: 3. |
| `empty` | text, up to 60 | What the card says with no events: `Nothing planned`. |

Each event is `{ title, starts, ends, allDay, where, color, tap }`. `title` and `starts` are
needed.

| Field | Value | What it is |
| --- | --- | --- |
| `title` | text, up to 80 | The event's name. |
| `starts` | a time in seconds | Needed. When it starts: `os.time{…}` in Lua, `Date.now() / 1000` in JavaScript. |
| `ends` | a time in seconds, not before `starts` | When it ends. |
| `allDay` | true or false | The event takes the whole day. It says "all day" where the others have their time, and comes first in its day. Its `starts` must be midnight on the phone: `os.time{ year = 2026, month = 12, day = 21, hour = 0 }`. |
| `where` | text, up to 60 | The place, at the end of the event's line when the card has room. |
| `color` | a role | The color of a dot in front of the event's title. Without it, no dot. |
| `tap` | an action | What a tap on the event does ([Taps](#taps)). |
| `id` | a number | Not shown, and not kept. An event of [`calendar.events`](#calendareventsdays) has one, so that list can be the `events` as it is. |

- The events are under their day: "Today", "Tomorrow", then the date. The card shows as many as
  fit, then "+3 more".
- Kolahal writes each time in 12-hour or 24-hour form, as the header does
  ([`clock.24h`](/reference/config/)).
- An event that has ended is left out, with no run. An event with no `ends` stays until its day
  is over. One with `ends` that has begun says "now".
- An event that began on an earlier day and still goes on is under Today.
- An all-day event whose times aren't midnights on the phone can show on the wrong day. Some
  calendars keep such events at midnight UTC: shift those first. The events of
  [`calendar.events`](#calendareventsdays) are shifted already.
- A time in milliseconds is an error that says to divide it by 1000.

**`image`**: a picture from the web. The script gives the picture's link, and home fetches the
picture.

| Field | Value | What it is |
| --- | --- | --- |
| `image` | an `https://` link, up to 2000 characters | Needed. Where the picture is. |
| `alt` | text, up to 200 | Needed, and not empty. What the picture shows, in words. |
| `caption` | text, up to 60 | A line with the picture: its name, its source. |
| `fit` | `crop` or `fit` | `crop` covers the whole card, to its edges, and the picture loses its edges: the caption and the title are on a chip over it. `fit` shows the whole picture inside the card, under its title line, with space beside it. Without it: `crop`. |

- The link must start with `https://`. A link with plain `http://` is an error here. A line's
  [`ctx.image`](#logtitle-body-ctx) still takes one.
- The link is never cut. One over 2000 characters is an error.
- It is checked as every link of a widget is ([Taps](#taps)): the script's internet access must be
  on, and a link that is refused is an error in the script.
- `alt` is for a screen reader, which can't see the picture. The card also shows it while it has
  no picture: before the picture has come, with no network, and when the picture can't be read.
- Home fetches the picture when the widgets page comes into view, not when the script runs. It
  fetches a link once and keeps the picture, as it does for the pictures on log lines.
- A picture file can be 10 MB at most. A larger one is not shown, and the card keeps its `alt`.
- A see-through picture whose lines barely show on the card gets a light or a dark backdrop, as on
  a log line.
- In the **Shape** look, the picture is cut to a shape, a cookie with the caption under it, or in
  a `2x1` card a clover with the caption beside it. It always covers its shape, also with
  `fit = "fit"`.
- **Arrange widgets** shows the picture only when home has it already. It fetches nothing.
- The script itself needs no request for the picture. It makes one only to learn the link.

**`versus`**: two sides and the score between them, for a match or a game of chess. Needs Kolahal
0.5.17.

| Field | Value | What it is |
| --- | --- | --- |
| `sides` | a list of two sides | Needed: exactly 2, the first at the start. One or three is an error. |
| `score` | text or a number, up to 24 | Needed. The score, large between the sides: `2–1`, `1½–½`. |
| `turn` | 1 or 2 | The side to move, or the side with the ball: a dot by its name. |
| `moving` | true or false | Draws the part of the bar of the side in `turn` as a wave that moves: its clock runs. |
| `line` | text, up to 60 | A last line: the last move, the last goal. |
| `badge` | text, up to 8 | A small text at the top, in the card's color: `67'`, `LIVE`. |

Each side is `{ name, mark, color, value, text }`. Only `name` is needed.

| Field | Value | What it is |
| --- | --- | --- |
| `name` | text, up to 24 | The player or the team. |
| `mark` | text, up to 2 characters | A letter or two on a shape, in the side's color: `L`, `NO`. Without it: the first letter of the name. A mark is never a picture. |
| `color` | a role | The side's color: its mark, its part of the bar and its figure. Without it: `accent` for the first side, `link` for the second. |
| `value` | a number, 0 or more | The side's part of the bar between the sides: its clock's time left in seconds, its share of the ball. |
| `text` | text, up to 12 | What the bar's end says for the side: `58:10`, `58%`. Without it: the value. |

- The bar shows when both sides have a `value` and they aren't both 0. Each side's part is its
  value over the two, and moves to a new value smoothly.
- Kolahal doesn't run a clock. A script that shows clocks gives the time left at each run, with
  `refresh` while the game is on.
- A small card shows the score over the two marks. A `2x1` card has the score between the marks
  and the names under them, with no bar. A `4x1` card has each name beside its mark, the score with
  the badge and the last line in the middle, and the bar under them. A large card has the title and
  the badge at the top, the marks either side of the score with the names under them, then the bar
  and the last line.
- The marks are shapes in every look, so a versus card has no **Shape** look.
- A screen reader says the badge, the sides with the score ("Lisbon 2–1 Paris"), each side's figure
  where there is a bar, whose turn it is, and the last line.

**`sky`**: the sun on its path across the sky, or the moon in its phase on its own path. The script
gives the times once, and Kolahal moves the sun or the moon. No run is needed as time passes. Needs
Kolahal 0.5.17.

| Field | Value | What it is |
| --- | --- | --- |
| `rises` | a time in seconds | Needed. When the sun rises, or with `phase` the moon. |
| `sets` | a time in seconds, after `rises` | Needed. When it sets: less than a day after `rises`, or for the moon (with `phase`) less than 24 h 50 min. |
| `phase` | a number, 0 to 1 | The part of the moon that is lit. With it, the card is the moon's. |
| `waxing` | true or false | The moon's lit part grows. It is drawn on the right. |
| `phases` | a list of phases | Up to 4 of the moon's next phases, each `{ phase, waxing, at }`. They go with `phase`. |

Each phase is `{ phase, waxing, at }`. `phase` and `at` are needed.

| Field | Value | What it is |
| --- | --- | --- |
| `phase` | a number, 0 to 1 | The part of the moon that is lit then: 1 for a full moon, 0.5 for a quarter, 0 for a new moon. |
| `waxing` | true or false | Whether it grows then. |
| `at` | a time in seconds | When the phase comes. The card writes its day under it. |

- By day, the sun is on the arc over the horizon, at its place for the time now. The part of the
  arc it has travelled is stronger than the part to come. At night it is under the horizon, on a
  dotted arc, and the part under the horizon is darker.
- The big text is the time of the next sunrise or sunset ("17:20"), or for the moon the part that
  is lit ("78%"). Beside it is what comes next, "Sunset in 2 h 10 min", or for the moon its phase's
  name, "Waxing gibbous", from `phase` and `waxing`.
- A large card writes the times of the rise and the set at the arc's ends. A large moon card has its
  next phases under them, each with its day. A phase whose time has passed is left out, with no run.
- Times of an earlier day still work: Kolahal moves them by whole days to the day now, so the card
  stays close for a few days with no run. A day of the moon is 24 h 50 min.
- The times change little from day to day. Give it a `staleAfter` of a day (86400), so the widgets
  page runs the script once a day, not each hour.
- `color` is the color of the sun or the moon and of its path: `warn` suits the sun, `link` the moon.
- Kolahal writes each time in 12-hour or 24-hour form, as the header does
  ([`clock.24h`](/reference/config/)).
- A small card has the sky over the big text. A screen reader says what comes next and the times,
  and for the moon its phase, how much of it is lit and its next phases.
- A time in milliseconds is an error that says to divide it by 1000.

### Limits

What a description keeps, and what it refuses.

| What | Limit | Over the limit |
| --- | --- | --- |
| A whole description | 32 KB | an error |
| `widget.show` and `widget.clear` in one run | 20 calls | later calls change nothing |
| A text | the number in its field's table | cut, with "…" at its end |
| `list`: `items` | 12 rows | the first 12 are kept |
| `list`: a row's `range` | `value` from `low` to `high` | held at the nearer end; `low` above `high` is an error |
| `stat`: `more` | 3 smaller values | the first 3 are kept |
| `stat`: `points` | 60 numbers | the last 60 are kept: the newest |
| `progress`: `items` | 4 bars | the first 4 are kept |
| `progress`: `zones` | 5 zones | the first 5 are kept |
| `progress`: `stages` | 2 to 6 names | the first 6 are kept; fewer than 2 is an error |
| `chart`: `points` | 60 numbers | the last 60 are kept: the newest |
| `chart`: `labels` | 2 texts | the first 2 are kept |
| `buttons`: `items` | 1 to 8 buttons | an error, as for none |
| `toggles`: `items` | 1 to 6 switches | an error, as for none |
| `clock`: `zones` | 1 to 4 places | the first 4 are kept; none is an error |
| `agenda`: `events` | 20 events | the first 20 are kept |
| `agenda`: `days` | 1 to 14 | held between 1 and 14 |
| `image`: `image` | 2000 characters | an error: a link is never cut |
| `image`: the picture's file | 10 MB | not shown; the card keeps its `alt` |
| `versus`: `sides` | 2 sides | an error, as for one or three |
| `sky`: `sets` | less than a day after `rises`, 24 h 50 min for the moon | an error |
| `sky`: `phases` | 4 phases | the first 4 are kept |
| `staleAfter` | 60 to 604800 seconds | held between them |
| `refresh` | 10 to 3600 seconds | held between them |
| A tap's `args` | 200 characters | cut |
| A tap's `url` | 2000 characters | an error: a link is never cut |
| A tap's `label` | 24 characters | cut |
| Taps on one card, row, button or event | one run in 2 seconds | one tap waits and runs when the 2 seconds are over; more are ignored |
| Taps on one switch | one run in 2 seconds | the tap is ignored |
| A switch that waits for its run | 10 seconds | it shows the state it had |

### Capitals in a widget

A card's labels start with a capital, as the rest of Kolahal's text does, whatever the script
writes: `label = "unlocks today"` shows "Unlocks today". This goes for the `label` of a card, of a
`lead`, of a `progress` bar, of a button and of a switch, the names of `stages`, each `caption`,
a row's `detail`, `empty`, `reached`, a chart's `labels` and a versus card's `line`, and for the
labels of [`fmt.stats`](#big-numbers) in the log. Every other text stays as written, such as
titles, `note`, `text`, `trailing`, `where`, values and units, a clock's place names and a tap's
`label`.

A label also stays as written when:

- its first character is not a small letter: "3 days ago", "+2%", "(beta)";
- its first word has a capital after its first letter ("iOS", "macOS", "eSIM"), or a digit ("v1.2", "x86");
- it is a unit: a common unit symbol on its own ("km", "kg", "mph", "kcal"), or a first word with
  a "/" in it ("km/h", "m/s per day"). "kWh", "°C" and "%" stay by the rules above. A label that
  only starts with a unit is a label: "in 3 days" shows "In 3 days".

The label of a smaller value in `more` gets its capital only where a look puts it under its value.
Where a look writes it after the value on one line, it stays as written, so write it as part of a
phrase: `{ value = "62%", label = "humidity" }` shows "62% humidity" on one line, and "Humidity"
under the value.

### Styles in a widget

Some texts of a card keep styles from [`fmt`](#styles-fmt): bold, italic, underline, strike and a
color.

| Kind | Texts that keep styles |
| --- | --- |
| `text` | `text` and `caption` |
| `list` | a row's `title`, `detail` and `trailing` |
| `stat` | `label` |
| `image` | `caption` |
| `versus` | `line` |

- These work there: `fmt.bold`, `fmt.italic`, `fmt.underline`, `fmt.strike` and
  `fmt.color(role, text)`. You join them with other text, as in the log.
- Every other text is plain. A style there is removed, and its text stays.
- A widget draws no link, tag, code chip, table or bar inside a text. `fmt.link`, `fmt.tag`,
  `fmt.code`, `fmt.table` and `fmt.bar` lose their marks there and keep their text. For a link,
  give the card or the row a [`tap`](#taps).
- A color is a role, as everywhere in a widget. The theme picks the color.
- A text's limit counts the characters that show, not the styles. A text over its limit is cut,
  with "…" at its end, and its styles end there too.
- A screen reader says the plain text.
- A secret's value is masked in a styled text too.
- Markdown is not read in a widget. `**bold**` shows as it is written: use `fmt.bold`.

| Action | What a tap does |
| --- | --- |
| `{ args = "add 1" }` | This script runs again with these arguments. They are up to 200 characters, split at spaces. `args` can be empty: the script then runs with no arguments. |
| `{ url = "https://…" }` | The web link opens. It is up to 2000 characters, and never cut: a longer one is an error. |

An action can also have:

- `label`: what a screen reader says for it, up to 24 characters.
- `page = "log"`, with `args`: home turns to the log after the tap. Use it for a run that logs
  something.

Where an action goes:

- `tap` in the description: a tap on the card.
- `tap` in a row of a `list`, a button of `buttons`, a switch of `toggles` or an event of an
  `agenda`: a tap on that item. A button and a switch need one. A switch takes only `{ args }`.

Rules:

- In a run that a tap starts, [`event.name`](#event) is `"action"`, as for a
  [button](#buttons) under a line. `event.widget` is `true`, and `event.label` is the action's
  `label`, when it has one. The arguments are in `args`.
- A link must be a web link (`http` or `https`), and the script's internet access must be on. A link
  that is refused is an error in the script, so the card never has a tap that does nothing.
- One card, row, button, switch or event starts at most one run in 2 seconds. A quick second tap on a
  card, row, button or event waits and runs when the 2 seconds are over, so two taps on a counter's +
  add two. A third quick tap is ignored, and so is a quick second tap on a switch.
- A run that a tap started is a run like any other that you start: what it logs is in the log,
  and so is its error. If it fails, the card also says "Failed 10:42" under its content, as after
  a failed [`"widget"` run](#when-a-widgets-script-runs). The next run that works clears that.
- A card with no `tap` refreshes when you tap it.
- A script can't put a terminal command behind a tap.
- A long-press on a card opens **Arrange widgets**.

### When a widget's script runs

The script's own timers and events fill the widget, as they run the script
([`@every`, `@at`](/scripting/overview/#running-scripts), [`@on`](/scripting/overview/#event-triggers)).
A run fills it only when it calls `widget.show`.

The widgets page asks for runs too. In these runs, [`event.name`](#event) is `"widget"`:

- when you place the widget: one run at once.
- when the widgets page comes into view and the content is older than `staleAfter` (one hour
  without it, one minute for `toggles`): one run.
- every `refresh` seconds while the widget is on screen, when the description has `refresh`. A widget scrolled out of sight runs when it is back, if its time has passed.
- when you tap a card that has no `tap`.

Rules for a `"widget"` run:

- It is quiet. What the script returns isn't logged. Its own `log` lines are, so a script skips
  them when `event.name` is `"widget"`.
- There are never two at once for one script. A script that goes online (`http`, `rss`) waits for a
  network.
- If it fails, the card keeps its content and says "Failed 10:42" under it. A card with no content
  shows the error's first line. The error shows in the log once, until a run works again.
- The next `widget.show` clears the failure.
- A script that is switched off isn't run.

Content older than `staleAfter` stays on the card. A large card says its age under it: "2 h ago".
Switches (`toggles`) say it only after an hour, whatever `staleAfter` is.

### Several widgets from one script

You can place a script's widget more than once: the weather for two cities, a countdown to two
days. Each widget is a card of its own, with its own content and its own
[options](/scripting/overview/#options).

- In the picker, the row of a script whose widget is placed says **Added · tap to add another**. A
  tap places one more widget, and opens its options.
- A script can have 6 widgets at most.
- The script needs no change. It reads `options` and calls `widget.show`, as for one widget.

Which widget a run fills:

- A run for one widget fills that widget: a [`"widget"` run](#when-a-widgets-script-runs) that the
  widgets page asks for, and a run that a [tap](#taps) on that card starts. In such a run,
  [`options`](#options) has that widget's values, and `widget.show` and `widget.clear` change
  that widget only.
- Every other run fills the first widget, with the script's own options: a timer, a daily time,
  an event, a run you type, a pinned line's refresh.
- So a further widget is not filled by the script's timer. It gets a quiet run of its own when
  you place it, when it is in view with old content, on its `refresh`, on a tap, and after you
  change one of its options in its **Options** sheet. Nothing more runs in the background.
- One script's runs go one after another, also for two of its widgets.

How a script tells its widgets apart:

- [`event.instance`](#event) is the widget's number, as text: `"2"`, `"3"` and so on for the
  further widgets. For the first widget it is nil (undefined in JavaScript).
- A widget keeps its number while it is placed. When you remove a widget, its number is free, and
  the next further widget you place takes the smallest free one. If the first widget was removed,
  the picker brings it back before it adds a further one.
- It is there only in a run for one widget: a `"widget"` run, or a tap on a card.
- `event.widget` is `true` in a tap's run, as for one widget.
- Kolahal sets it. A script can't choose which widget it fills.
- Most scripts don't need it, because `options` is that widget's already. Use it for a
  [`store`](#storegetkey--storesetkey-value) key that each widget needs for itself.

A widget's options:

- A further widget follows the script's options until you set one for that widget. After that,
  it keeps its own value for that option, and follows the script for the others.
- To change them, open **Arrange widgets**, select the card and tap **Options**
  ([Widgets from scripts](/guides/widgets/#widgets-from-scripts)).
- The first widget has no options of its own. Its **Options** are the script's.
- Removing a widget deletes its content and its own options.

## Screens

A script can open a full-screen screen of its own over home, and draw on the character grid, as
`matrix` and `clock` do. It is the same in both home styles, in your theme's colors and font.

To start from a screen that works, install the library's
[`template-screen`](/scripting/library/#templates), or `template-screen-js` in JavaScript: a short
screen with a comment on each part. For longer examples, the library's
[screens](/scripting/library/#screens) `tty-matrix`, `tty-pipes`, `tty-sl`, `tty-clock`,
`tty-top`, `tty-decode` and `tty-boot` each draw one of Kolahal's screens, in Lua, with comments on
how it works.

### tty.screen(spec)

Needs `@uses screen`. Opens a screen once the script's code has run to its end. `spec` says what it
draws and what it does with a tap or a key.

- A script with `@uses screen` is always a command, with or without `@command`. It has no timer, event
  or widget: `@every`, `@at`, `@on` and `@widget` don't work in it, and the editor says so.
- It opens only when you start the script: from the prompt, with a tap, a shortcut or a gesture, or
  with Run in the editor. In any other run it is an error: a timer, an event, or another script's
  `launcher.run`.
- A run opens one screen, and goes on until it closes. The screen stays for as long as you leave it
  open. Lines a function logs are in the log at once, under the screen.
- Any tap or key closes it, unless the script has a function for it. Back, Home or leaving home for
  more than 30 seconds always closes it. Like any app, it doesn't keep the phone's screen on.
- A function that returns `false` closes it. Any other result, or none, leaves it open.

| Field | What it is |
| --- | --- |
| `fps` | how many frames a second, `0` to `30` (10 by default). With `0` there are no frames, and the screen draws in `start`, `key` and `tap` only. Home gives fewer in battery saver |
| `title` | what a screen reader says for the screen. The script's name without one |
| `start(g)` | runs once, when the screen is there. `g` is the [grid](#the-grid) |
| `frame(g, t, dt)` | runs for each frame. `t` is how long the screen has been there and `dt` how long since the last frame, both in milliseconds. A script that is slow gets fewer frames, and the time that went by in `dt` |
| `key(k)` | runs for each key on a hardware keyboard: a letter or digit as it is typed (`"a"`, `"?"`), or `"up"`, `"down"`, `"left"`, `"right"`, `"enter"`, `"space"`, `"escape"`, `"tab"` or `"delete"` |
| `tap(col, row)` | runs for each tap, with the cell it was on |
| `resize(g)` | runs when the grid's size changed (the phone was turned, the font size changed). The grid is blank by then |
| `stop()` | runs when the screen closes. What it draws doesn't show |

`start` and `frame` are the ones that draw: a screen needs at least one of them. A screen keeps what
it knows in the variables of its code. In JavaScript it can also keep it on the object: `this` is
the spec.

```js
// @uses screen
tty.screen({ start(g) { g.put(1, 1, "hello", "accent"); } });
```

#### The grid

`g` is what a screen draws on. `g.cols` and `g.rows` are its size in cells. Columns and rows count
from `0` in both languages. In Lua, `g.put(…)` and `g:put(…)` are the same.

| Call | What it does |
| --- | --- |
| `g.put(col, row, text, style?)` | writes text from a cell. A line break goes to the next row, at the same column. Text past the right edge is cut |
| `g.fill(col, row, width, height, char?, style?)` | fills a rectangle with one character, or with blank cells without one |
| `g.clear(style?)` | blanks every cell |
| `g.box(col, row, width, height, style?)` | a frame of lines. It needs a width and height of 2 or more |
| `g.bar(col, row, width, value, style?)` | a bar from the left, `value` from 0 to 1 of the width, drawn in eighths of a cell |

A wide character takes two cells, and an emoji does too. Drawing off the grid is cut off.

A style is a color, or a table of:

- `color` and `bg`: the text's color and the background's, each one of `accent`, `link`, `info`,
  `muted`, `text`, `good`, `warn` and `bad`, as [`fmt.color`](#styles-fmt) takes them. The theme picks
  the real colors.
- `bold`, `faint`, `italic`, `underline`, `strike` and `inverse`: each `true` or `false`.

```lua
g.put(0, 0, "over", "warn")
g.put(0, 1, "under", { color = "good", bold = true })
```

```lua
    end
```

#### Screen limits

- Each call of a function has 1 second. A call that takes longer is stopped, and the screen closes
  with an error.
- A frame that takes over 50 ms, 30 times in a row, closes the screen too, with an error that says
  so. Draw less each time, or use a lower `fps`.
- The code before the screen has the limit of any run, 60 seconds. The screen itself has none.
- If Android stops the script's process, the screen closes, and a line in the log says so.
- `http`, `rss` and `sleep` work in a function, but they count towards its second and the screen
  stands still meanwhile. Fetch what a screen needs before `tty.screen`. In JavaScript, a call in a
  function that isn't awaited is dropped when the function ends.
- In one call a script can draw as much as 8 full screens, and more is an error. The whole screen
  each frame is one of them.

## HTTP

A response is `{ status, ok, body, headers }`:

- `status`: the status code, as a number.
- `ok`: true for 2xx.
- `body`: the body as a string (up to 4 MB is read).
- `headers`: the response headers, with lowercase names.

Requests:

- Kolahal sends the `User-Agent` `Kolahal-Launcher/0.1 (+https://github.com/mtwabpin)` unless you
  set your own.
- A network error raises an error (Lua) or rejects the promise (JS).
- An HTTP error status does **not**, so check `ok`.
- Plain `http://` URLs are allowed.
- A request can go to any address. This phone, your local network (a router, a home server) and a
  VPN address such as Tailscale's 100.x are all allowed. On Android 17 and newer, Android itself
  blocks your local network, and those requests fail after a timeout.
- A JavaScript run makes at most 4 requests at a time. More requests wait in a queue. When 64
  requests and sleeps are waiting at once, another call fails.

### http.cached(url, seconds?)

A GET request that reuses this script's stored response while the response is less than `seconds`
old (default 600).

- The result has an extra `cached` field. It is `true` when the result came from the cache.
- Only successful responses are cached, and only their body. A cached result has `status` 200 and
  empty `headers`.
- A response is not cached when:
  - its body is half the store's value limit or more (512 KB of text), or
  - its body contains one of the script's secrets.
- Cached responses count toward the script's [store](#storegetkey--storesetkey-value) limits. When
  the store is full, the script's other cached responses are deleted to make room.

```lua
local r = http.cached("https://open.er-api.com/v6/latest/USD", 6 * 3600)
```

## RSS and Atom

A feed is returned as `{ title, link, items }`. Each item is `{ title, link, id, date, summary }`.
`rss.fetch` and `rss.fresh` raise an error when the HTTP request fails. To show a friendly message,
wrap them in `pcall` / `try`.

### rss.fetch(url)

Downloads and parses a feed.

### rss.parse(xml)

Parses feed XML that you already have. It is synchronous in both languages.

### rss.fresh(url)

Works like `rss.fetch`, but returns only the items this script hasn't seen before.

- Items are matched by their id. Kolahal remembers the last 500 ids for each URL. For a longer feed
  it remembers more: the feed's item count plus 100.
- Items are marked as seen only **if the run succeeds**. So if a script fails halfway, it gets the
  same items next time.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
local feed = rss.fresh("https://lobste.rs/rss")
for i, item in ipairs(feed.items) do
  if i > 5 then break end
  log(item.title, { url = item.link })
end
```
</TabItem>
<TabItem label="JavaScript">
```js
const feed = await rss.fresh("https://lobste.rs/rss");
for (const item of feed.items.slice(0, 5)) log(item.title, { url: item.link });
```
</TabItem>
</Tabs>

## Storage

### store.get(key) / store.set(key, value)

Strings that are kept between runs. Each script has its own private store.

- `store.get` returns `nil` / `null` for a missing key.
- `store.set(key, nil)` deletes the key.
- To store structured data, encode it as JSON.
- Deleting a script deletes its store.
- One-liners typed at the prompt share one scratch store.

Limits:

- A value can hold up to 1 MB.
- A key can be up to 512 characters.
- A script's store can hold up to 1,000 keys and 16 MB, keys included.
- Sizes are counted as stored: an accented letter or a CJK character takes more than one byte.
- Past these limits, `store.set` raises an error: "value too large", "key too long" or "store full".
- `store.set` rejects a secret, because the store is included in backups.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
local n = tonumber(store.get("runs") or "0") + 1
store.set("runs", tostring(n))
store.set("list", json.encode({ "a", "b" }))
```
</TabItem>
<TabItem label="JavaScript">
```js
const n = Number(store.get("runs") ?? 0) + 1;
store.set("runs", String(n));
store.set("list", JSON.stringify(["a", "b"]));
```
</TabItem>
</Tabs>

### secrets.get(name)

Returns a placeholder for the API key or token that the script names with `@secret`. It never
returns the value itself. Until you set the value, it returns `nil` / `null`.

- Put the placeholder where the request needs the key: a header, the URL's path or query, or the
  body. You can use it alone or joined with other text. It can't be in the site's name.
- Kolahal puts the value in its place when the request goes over https to a site that the
  `@secret` line names.
- A request that carries it anywhere else stops the script
  ([API keys and other secrets](/scripting/overview/#api-keys-and-other-secrets)).
- The placeholder shows as `••••`. A script can't turn it into the value: if the script encodes,
  reverses or cuts it, it is just text.
- Reading a name that has no `@secret` line is an error.
- Code typed at the prompt can't read secrets.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
-- @secret GH_TOKEN api.github.com A GitHub token with read access
local token = secrets.get("GH_TOKEN")
if not token then return "set GH_TOKEN in the script's sheet" end
local r = http.get("https://api.github.com/notifications", { Authorization = "Bearer " .. token })
```
</TabItem>
<TabItem label="JavaScript">
```js
// @secret GH_TOKEN api.github.com A GitHub token with read access
const token = secrets.get("GH_TOKEN");
if (!token) return "set GH_TOKEN in the script's sheet";
const r = await http.get("https://api.github.com/notifications", { Authorization: "Bearer " + token });
```
</TabItem>
</Tabs>

### json.encode(v) / json.decode(s)

Lua only. JavaScript has the built-in `JSON`.

- `json.decode` turns objects into tables, and arrays into sequences that start at 1.
- It raises an error when `s` isn't JSON (for example, an HTML error page). Wrap it in `pcall` when
  the text comes from a site.

```lua
local data = json.decode('{"ip":"203.0.113.7"}')
return json.encode({ ip = data.ip, ok = true })
```

## Device

### clipboard.get() / clipboard.set(text)

Needs `@uses clipboard` ([what a script may use](/scripting/overview/#what-a-script-may-use)).

- Android lets only the focused app read the clipboard. So `clipboard.get()` usually returns `nil`
  in timer runs.
- `clipboard.set` works at any time, for up to 100,000 characters. It rejects a secret.

```lua
-- @uses clipboard
clipboard.set("copied by a script")
```

### device.battery()

Returns `{ level, charging }`. `level` is 0–100 (or nil if unknown). `charging` is true when the
phone is plugged in.

### device.network()

Returns the active network: `"wifi"`, `"cell"`, `"eth"`, `"vpn"`, `"net"` (any other kind) or `"offline"`. The header names it the same way.

### device.unlocks(days?)

Without an argument, it returns how many times you unlocked the phone today, as in the header.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
local b = device.battery()
return string.format("%d%% %s · %s · %d unlocks", b.level or -1,
  b.charging and "charging" or "", device.network(), device.unlocks())
```
</TabItem>
<TabItem label="JavaScript">
```js
const b = device.battery();
return `${b.level}% ${b.charging ? "charging" : ""} · ${device.network()} · ${device.unlocks()} unlocks`;
```
</TabItem>
</Tabs>

With `days`, it returns a list instead: one count for each of the last `days` days.

- The oldest day comes first. Today's count is the last one.
- `days` is from 1 to 30. A number outside that is held at its nearest end, and a fraction is
  dropped. Anything that isn't a number is an error.
- The counts are the ones the [`unlocks` command](/guides/apps/#screen-time-and-unlocks) shows.
- A day with no data is left out, so the list can be shorter than `days`. Android keeps usage
  events for the last days only (about 10 on many phones), and Kolahal saves each day's count
  from 0.5.12 on. Before 0.5.12, such a day was 0.
- It needs no `@uses` line, like today's count.
- Kolahal before 0.5.8 ignores `days` and returns today's count as a number.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
local week = device.unlocks(7)      -- { 12, 30, 0, 45, 7, 1, 8 }
local today = week[#week]           -- 8
```
</TabItem>
<TabItem label="JavaScript">
```js
const week = device.unlocks(7);     // [12, 30, 0, 45, 7, 1, 8]
const today = week[week.length - 1]; // 8
```
</TabItem>
</Tabs>

### device.dnd() / device.setDnd(mode)

Needs `@uses dnd`.

- `device.dnd()` returns the current Do Not Disturb mode: `"off"`, `"priority"`, `"alarms"` or
  `"none"` (total silence).
- `device.setDnd(mode)` sets one of those modes (`"on"` means `"priority"`). It returns `true`, or
  `false` when Kolahal has no Do Not Disturb access. Run `allow dnd` once to give it access.
- Since Android 15, a script turns on Kolahal's own Do Not Disturb mode, separate from yours. When
  the script turns it off again, it never turns off one that you turned on yourself.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
-- @uses dnd
if device.dnd() == "off" then device.setDnd("on") end
```
</TabItem>
<TabItem label="JavaScript">
```js
// @uses dnd
if (device.dnd() === "off") device.setDnd("on");
```
</TabItem>
</Tabs>

### apps.list()

Needs `@uses apps`. Returns the apps you can launch, sorted by label: `[{ label, pkg, profile }]`.

- It includes apps in your personal profile, and in a work or clone profile that is on.
- `profile` is `"personal"` or `"other"`.
- It leaves out apps in a paused profile or in the private space.

```js
// @uses apps
const work = apps.list().filter(a => a.profile !== "personal");
return `${work.length} apps outside the personal profile`;
```

### notifications.recent(n?)

Needs `@uses notifications` and [notification access](/guides/notifications/). Without
notification access, it returns an empty list.

Returns the most recent notifications, newest first: `[{ pkg, app, title, text, time }]`.

- `time` is in milliseconds since the epoch.
- `n` defaults to 20. The maximum is 50.

```lua
-- @uses notifications
for _, n in ipairs(notifications.recent(5)) do
  log(n.app .. ": " .. (n.title or "") .. " " .. (n.text or ""))
end
```

## Your lists

A script can read the lists you keep in Kolahal: your todos, notes and reminders, the phone's
calendar, and the unread items of your feeds. Its [widget](#widgets) can then show them your way.

| Call | Needs | Returns |
| --- | --- | --- |
| [`todos.list()`](#todoslist) | `@uses todos` | `[{ id, text, done }]` |
| [`todos.setDone(id, done)`](#todossetdoneid-done) | `@uses todos` | `true` if that todo changed |
| [`notes.list(n?)`](#noteslistn) | `@uses notes` | `[{ id, text, created }]` |
| [`reminders.list()`](#reminderslist) | `@uses reminders` | `[{ id, text, at, repeats }]` |
| [`calendar.events(days?)`](#calendareventsdays) | `@uses calendar` | `[{ id, title, starts, ends, allDay }]` |
| [`feeds.unread(n?)`](#feedsunreadn) | `@uses feeds` | `[{ id, feed, title, link, date, summary }]` |

What is true for all of them:

- Each list has its own [`@uses` item](/scripting/overview/#what-a-script-may-use), with a switch
  of its own. A script that may read your notes can't read your calendar.
- Without its `@uses` line, a call is an error that names the line.
- With the line and its switch off, a call returns an empty list.
  [`allowed("todos")`](#allowedwhat) tells a script which it is.
- They only read what is on the phone. No call makes a request, so none needs internet access.
- One call changes something: [`todos.setDone`](#todossetdoneid-done).
- They don't wait. In JavaScript they need no `await`.
- Every time is in seconds since 1970, as a widget takes it. `os.time()` gives the same in Lua, and
  `Date.now() / 1000` in JavaScript.
- Every text is plain: it has no styles. A text over 4,000 characters is cut, with "…" at its end.
- A number that sets how many rows come back (`n`, `days`) is held between 1 and its maximum, and
  a fraction is dropped. Anything that isn't a number is an error.
- They need Kolahal 0.5.8 or newer.

A script that reads a list could send it somewhere, if it also has internet access. So read the
code of a script from someone else before you allow it a list
([switching access off](/scripting/overview/#switching-access-off)).

### todos.list()

Needs `@uses todos`. Returns your [todos](/guides/productivity/#todos): `[{ id, text, done }]`.

- The open todos come first, the oldest first. Then the done ones, the last one done first. This
  is the order of the `todo` command.
- `id` is a number. It stays the same when the list changes, so
  [`todos.setDone`](#todossetdoneid-done) takes it.
- `done` is `true` or `false`.
- It returns 200 todos at most.

```lua
-- @uses todos
local open = 0
for _, t in ipairs(todos.list()) do
  if not t.done then open = open + 1 end
end
return open .. " open"
```

### todos.setDone(id, done)

Needs `@uses todos`, the same item as reading. A script that may read your todos may tick them.

Marks a todo done with `true`, or open again with `false`.

- `id` is the `id` of a row of `todos.list()`. It can be the number, or the same as text (`"12"`):
  a [tap](#taps) gives its `args` back as text.
- It returns `true` when that todo changed.
- It returns `false` when no todo has the id, when the todo is so already, and when the `todos`
  switch is off.
- It works in every run: a timer, an event, a tap on a widget.
- A run can call it 20 times. Later calls change nothing, and the first of them logs an error.
- Any other `id`, and a `done` that isn't `true` or `false`, is an error. Nothing is ticked then.
- It can't add, change or delete a todo.
- The [Todos widget](/guides/widgets/#todos) and the `todo` list show the change.

This widget lists your open todos. A tap on a row ticks its todo.

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
-- @title Open todos
-- @uses todos
-- @widget list

-- A tap on a row runs the script again, with the row's args.
if event and event.name == "action" and args[1] == "tick" then
  todos.setDone(args[2], true)
end

local rows = {}
for _, t in ipairs(todos.list()) do
  if not t.done then
    rows[#rows + 1] = { title = t.text, done = false, tap = { args = "tick " .. t.id, label = "mark as done" } }
  end
end
widget.show{ kind = "list", items = rows, empty = "Nothing open" }
```
</TabItem>
<TabItem label="JavaScript">
```js
// @title Open todos
// @uses todos
// @widget list

// A tap on a row runs the script again, with the row's args.
if (event && event.name === "action" && args[0] === "tick") {
  todos.setDone(args[1], true);
}

const rows = todos.list().filter(t => !t.done).map(t => (
  { title: t.text, done: false, tap: { args: `tick ${t.id}`, label: "mark as done" } }
));
widget.show({ kind: "list", items: rows, empty: "Nothing open" });
```
</TabItem>
</Tabs>

### notes.list(n?)

Needs `@uses notes`. Returns your newest [notes](/guides/productivity/#notes), the newest first:
`[{ id, text, created }]`.

- `text` keeps its line breaks.
- `created` is when you wrote the note, in seconds.
- `n` is how many: 10 without it, 50 at most.

```lua
-- @uses notes
-- @widget text
local newest = notes.list(1)[1]
widget.show{ kind = "text", text = newest and newest.text or "No notes yet" }
```

### reminders.list()

Needs `@uses reminders`. Returns the [reminders](/guides/productivity/#reminders) that are set,
the soonest first: `[{ id, text, at, repeats }]`.

- `at` is when the reminder is next due, in seconds.
- `repeats` is there only for a reminder that repeats. It says how, in words: `"every day"`,
  `"every Mon and Thu"`, `"on the 15th of every month"`.
- A reminder that fired and doesn't repeat is no longer in the list.
- It returns 200 reminders at most.

```js
// @uses reminders
// @widget countdown
const next = reminders.list()[0];
if (next) widget.show({ kind: "countdown", to: next.at, label: next.text, style: "clock" });
else widget.clear();
```

### calendar.events(days?)

Needs `@uses calendar`. Returns the events of the next days from the phone's calendar, as the
[Agenda widget](/guides/widgets/#agenda) shows them: `[{ id, title, starts, ends, allDay }]`.

- `days` is how many days from today: 3 without it, 30 at most. `1` is today only.
- The events are in the order of the days. In one day, all-day events come first.
- An event that has ended is left out. Events from hidden calendars and events you declined are
  left out too.
- `starts` and `ends` are in seconds. Every event has both. An event with no length ends when it
  starts.
- An all-day event starts and ends at midnights on the phone. One that began before today starts
  today. One of several days is in the list once.
- `id` is the calendar's number for the event. Every day of a repeating event has the same one.
- It returns 100 events at most.
- Kolahal also needs Android's calendar permission. Without it, the list is empty. A script can't
  ask for the permission: run [`agenda`](/guides/productivity/#agenda) once, or tap the Agenda
  widget.

The list is what an [`agenda` widget](#kinds-and-their-fields) takes as its `events`, as it is:

<Tabs syncKey="lang">
<TabItem label="Lua">
```lua
-- @title This week
-- @uses calendar
-- @widget agenda

widget.show{ kind = "agenda", events = calendar.events(7), days = 7, empty = "A free week" }
```
</TabItem>
<TabItem label="JavaScript">
```js
// @title This week
// @uses calendar
// @widget agenda

widget.show({ kind: "agenda", events: calendar.events(7), days: 7, empty: "A free week" });
```
</TabItem>
</Tabs>

An `agenda` widget keeps the first 20 events and shows 14 days at most
([Limits](#limits)).

### feeds.unread(n?)

Needs `@uses feeds`. Returns the newest unread items of the [feeds](/guides/feeds/) you follow,
the newest first: `[{ id, feed, title, link, date, summary }]`.

- It reads the items Kolahal has fetched already. It makes no request and marks nothing as read.
- `feed` is the name of the item's feed: its title, or else its site.
- `id`, `title`, `link`, `date` and `summary` are as in an item of [`rss.fetch`](#rssfetchurl).
  `id` is the item's guid. `date` is text, as the feed wrote it, so it is not a time in seconds.
- `link`, `date` and `summary` are nil (null in JavaScript) when the feed gave none.
- `n` is how many: 10 without it, 50 at most.
- A row's `tap` with a `url`, like any link, needs the script's internet access.

```lua
-- @title Unread
-- @uses feeds
-- @widget list

local rows = {}
for _, item in ipairs(feeds.unread(12)) do
  rows[#rows + 1] = { title = item.title, detail = item.feed }
end
widget.show{ kind = "list", items = rows, empty = "Nothing unread" }
```

## Your app usage

Screen time, data use and the apps you don't open, as `usage`, `data today` and `storage` show
them, and `usage month`. All five need `@uses usage`, and Kolahal needs **Usage access** (`allow usage`). Each gives
nil (null in JavaScript) when it can tell nothing: Kolahal has no usage access, or you switched the
script's "Your app usage" off. So a widget can say so, instead of showing 0. They read only what
Android keeps. They work in Kolahal 0.5.12 and later; `usage.summary` in 0.5.15 and later.

| Call | Gives |
| --- | --- |
| [`usage.today(n?)`](#usagetodayn) | `{ total, apps = [{ app, pkg, minutes }] }` |
| [`usage.days(n?)`](#usagedaysn) | `[minutes]`, the oldest day first |
| [`usage.data(since?)`](#usagedatasince) | `{ mobile, wifi }` in bytes; with `"month"`, your plan's month too |
| [`usage.unused(days?)`](#usageunuseddays) | `[{ app, pkg, days, bytes }]` |
| [`usage.summary(period, app?)`](#usagesummaryperiod-app) | `{ perDay, rows, top }` |

### usage.today(n?)

Today's screen time since midnight, in minutes (`total`), and the `n` apps you used most
(`apps`), biggest first: 10 without `n`, 30 at most. Each is `{ app, pkg, minutes }`. Only apps of
your personal profile, used for a minute or more, are in the list. `total` counts every app,
Kolahal too, as `usage` does, so it can be more than the list adds up to.

### usage.days(n?)

The screen time of each of the last `n` days, in minutes, the oldest first: 7 without `n`, 30 at
most. Today is the last. Only the days Android has data for are there: on a phone that keeps
about 10 days, `usage.days(30)` has about 10.

### usage.data(since?)

The mobile and Wi-Fi data used since `since`, in bytes: `{ mobile, wifi }`.

- `since` is a time in seconds since 1970 (`os.time()`), not later than now. Without it, midnight.
- `"month"`: the month of your data plan, as `data month` counts it (`data.plan`, `data.start-day`):
  `{ mobile, wifi, since, plan, pace, daysLeft }`. `since` is when the month began, in seconds;
  `plan` is your plan in bytes, nil with none; `pace` is the mobile data the month comes to at the
  rate so far; `daysLeft` counts today.
- `mobile` is nil on Android 9, which doesn't tell it.

### usage.unused(days?)

The apps you haven't opened for `days` days or more (30 without it, 7 to 365), up to 50: those
Android has no use recorded for first, then the longest unused. Each is `{ app, pkg, days, bytes }`:
`days` is nil for an app with no use recorded, and `bytes` its size (the app and its data), nil
when Android doesn't tell. An app installed less than `days` ago is not in the list.

```lua
-- @title Screen time
-- @uses usage
-- @widget stat

local today = usage.today(3)
widget.show{ kind = "stat", value = today.total .. " min", label = "Screen time today" }
```

### usage.summary(period, app?)

Screen time over Android's weeks, months or years, as `usage week`, `month` and `year` show it: `period` is
`"week"`, `"month"` or `"year"`. With `app`, a package name such as `"com.google.android.youtube"`,
for that app alone; without it, for all apps. It gives `{ perDay, rows, top }`:

- `perDay`: the minutes a day over the rows that count, the `≈` number of `usage month`. The
  current week, month or year counts once it has run a week.
- `rows`: the oldest first, each `{ from, to, minutes, perDay, unlocks, current }`. `from` and `to`
  are its real dates, in seconds: Android starts each where the one before ended, not on a Monday or
  the 1st. `minutes` is its total, `perDay` its minutes a day, `unlocks` its unlocks a day (nil for
  one app, or when Android has no count), and `current` is true for the one still going.
- `top`: the 5 apps with the most time over all the rows, `{ app, pkg, minutes }`, biggest first.
  Nil with `app`.

These are Android's own totals, so they are about right, not exact. A year counts each app at
least as much as the months inside it hold.

```lua
-- @title Screen time by month
-- @uses usage
-- @widget chart

local s = usage.summary("month")
if s then
  local points = {}
  for i, r in ipairs(s.rows) do points[i] = r.perDay end
  widget.show{ kind = "chart", value = (s.perDay or 0) .. " min", label = "A day", points = points, style = "bars" }
end
```


## Launcher

### launcher.run(command)

Runs a terminal command as if you typed it. This includes another script's command. Needs
`@uses commands`.

- It works **only when the script was started from the prompt**: a command script, `script run`, or
  a one-liner. In timer and event runs, it logs an error and returns `false`.
- Sensitive commands (`clear`, `uninstall`, `work`, `notifs`, `script` and similar) must be typed by
  you. For these, it logs an error and returns `false`.
- The same applies when the script has no internet access, to:
  - `search`, `yt`, `wiki`, `maps` and `play` with search words,
  - another `@command` script that goes online when it gets words.

  These send the words to a site.
- A run sends at most 10 commands. A script started this way by another script can't send any.

```lua
-- @command
-- @desc Morning: the weather, then the news app
-- @uses commands
launcher.run("weather")
launcher.run("open news")
```

### sleep(ms)

Pauses for up to 5000 ms per call. In JS, use `await sleep(1000)`.

### args and argline

When a script runs as a command:

- `args` holds the words after its name (a table in Lua, an array in JS). Quotes group words.
- `argline` holds the same words joined by spaces.

Both are empty in timer runs.

```js
// @command
// @desc Greet: greet <name>
return `hello, ${argline || "world"} (${args.length} args)`;
```

### options

The script's [`@option`](/scripting/overview/#options) settings by name, as text. Each value is the
one you set in its sheet or with `script set`, or else the default from its line. In code typed at
the prompt, `options` is empty.

In a run for a [further widget](#several-widgets-from-one-script) of the script, each value is
the one you set for that widget, or else the script's value, or else the default.

```lua
-- @option city London The city to show
log("Weather for " .. options.city)
```

### event

In a run started by an [`@on` trigger](/scripting/overview/#event-triggers), `event` describes what
happened. `event.name` is the event: `unlock`, `charger`, `unplug`, `wifi`, `offline`,
`notification`, `boot` or `headset`. Some events add more fields:

| Event | Other fields |
| --- | --- |
| `charger`, `unplug` | `level` (battery %), and `plug` (`ac`, `usb`, `wireless`, `other`) while plugged in |
| `notification` | `app`, `pkg`, `title`, `text`, `time` |
| `headset` | `type` (`wired`), `device`, `mic` |
| `wifi` | `network` (`wifi`) |
| `boot` | `uptime` (seconds) |

`unlock` and `offline` have only `name`. Text over 2,000 characters is cut short.

Other runs:

- A run at one of the script's [daily times](/scripting/overview/#running-scripts) gets
  `event.name` `"at"` and `event.time`, the scheduled time (`"23:00"`). This is true even when the
  run is late. A script with two times can tell them apart.
- A run that a [status line](#statustext-opts) asks for with `refresh` gets `event.name`
  `"refresh"`.
- A run that a [button](#buttons) under one of the script's lines starts gets `event.name`
  `"action"` and `event.label`, the button's label. Its arguments are in `args`.
- A run that a [tap on the script's widget](#taps) starts gets the same, and `event.widget` is
  `true`. `event.label` is the tap's `label`, when it has one.
- A run that the widgets page asks for gets `event.name` `"widget"`
  ([when a widget's script runs](#when-a-widgets-script-runs)).
- A run for a [further widget](#several-widgets-from-one-script) of the script also gets
  `event.instance`, that widget's number as text (`"2"`). This is so in a `"widget"` run and in a
  run that a tap on that card starts. For the script's first widget, `event.instance` is not there.
- All other runs get nil (null in JavaScript).

## Work profile

### device.work() / device.setWork(on)

Needs `@uses work`.

- `device.work()` returns the work profile's state: `"on"`, `"paused"`, or nil (null in
  JavaScript) when the phone has no work profile.
- `device.setWork(true)` (or `"on"`) resumes it. `device.setWork(false)` (or `"off"`) pauses it.
  It returns `true` when Android accepted the request.

Android limits this:

- Only the default launcher can do it, only while it is in the foreground, and only on Android 10
  and newer.
- A script run at one of its [daily times](/scripting/overview/#running-scripts) counts as in the
  foreground when Kolahal may set exact alarms.
- A run on an interval or an event usually doesn't count, and gets `false`.
- Resuming also returns `false` when your work profile asks for its PIN. Android then asks you for
  it.
