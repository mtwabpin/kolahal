Kolahal has a small built-in feed reader. You don't need a script to use it.

## Subscribe

```sh
feed add https://hnrss.org/frontpage
feed add lwn.net/headlines/rss       # https:// is assumed; feed:// links work too
```

When you add a feed, Kolahal fetches it right away.

- Kolahal cleans up the address. If you add the same feed twice, you get the existing subscription.
- `feed://` links open as `https://`.
- A feed can be on your own network, for example a home server. On Android 17 and newer, Android blocks this,
  and the fetch fails after a timeout.
- Kolahal loads the newest 300 items of a feed.

## Read

<Image src={terminal} alt="Feed items in the log, each with its feed name, and the feed list with unread counts" class="shot shot-single" width={320} />

```sh
feed                 # list: #id, title, unread/total, interval, notify, last status (also: feed ls)
feed read            # all unread items, then mark them read
feed read 2          # unread items of feed #2
feed all 2           # the 40 newest stored items of feed #2, read or not
feed open 2          # open up to 5 unread items of #2 in the browser, mark them read
feed fetch           # refresh every feed now (feed fetch 2 for one)
```

Tap an item line to open its link. Long-press it to share or copy.

When a fetch finds new items, they appear in the log:

- Each feed's items are in their own group.
- Each feed shows at most `feeds.log-lines` items (default 10).
- If there are more, a "+N more" line appears. Tap it to put `feed read <id>` in the prompt.

## Read and unread

Every item is **unread** when Kolahal first fetches it. It becomes **read** when you:

- open it: tap its line in the log, use "Open link" in the long-press menu, or tap it on the
  Feeds screen
- list it with `feed read` (only the items that were shown count; items beyond the first 40 stay unread)
- open it with `feed open`
- use "Mark all read" on the Feeds screen

An item does not become read just because you saw it in the log. To change this, turn on
`feeds.read-shown`. `feed all` lists items without changing their state.

The unread count is the number of stored items that are still unread. Kolahal keeps up to 300 items per feed, unread ones first.

When you subscribe, all items already in the feed are unread too. A busy feed can start with
20 or more unread items. Turn on `feeds.backlog-read` to mark those as read. Then only new posts
are unread.

### Feeds screen

Run `feeds`, or open the **Feeds** tab in Settings. This screen lets you manage subscriptions without typing ids:

- Add, remove, and turn feeds on or off. Change their intervals and notifications.
- Tap a feed's ⋮ to open its sheet. Use **Edit address** to fix a typo or follow a feed that moved.
  The feed's items and settings stay.
- Tap a feed to see its items. Tap an item to open it and mark it read.
  Swipe an item either way to mark it read, or unread again if it's already read.
- Use the top bar to refresh all feeds, and to import or export **OPML**. OPML lets you move subscriptions
  from or to another feed reader.

The `feed …` subcommands still work.

At the bottom of the same screen, under **Settings**, you can set:

- whether new items go to the log, and how many
- the read / unread options above
- refresh on Wi-Fi only (`feeds.wifi`)
- the interval and notification setting for new subscriptions (`feeds.interval`, `feeds.notify`)

You can also find these with Settings search.

## Per-feed settings

```sh
feed every 2 2h          # check feed #2 every 2 hours (minimum 15m; default 1h)
feed notify 2 on         # one notification per fetch with new items (off to stop)
feed off 2               # pause a feed; feed on 2 resumes it
feed url 2 lwn.net/headlines/newrss   # a new address (a typo fixed): its items stay
feed rm 2                # unsubscribe and delete its items
```

## How fetching works

- One background job fetches the feeds that are due, based on each feed's interval.
  It runs only as often as your most frequent feed needs, and at most every 15 minutes.
  It runs only when there is a network. With `feeds.wifi on`, it runs only on Wi-Fi.
- Requests are conditional (ETag / Last-Modified). If a feed hasn't changed, the server returns a `304`, and Kolahal doesn't parse it.
- Kolahal keeps up to 300 items per feed: unread items first, then the newest.
- If a scheduled fetch fails, Kolahal only records it in the feed's status (shown by `feed`).
  If a manual fetch (`feed fetch`) fails, Kolahal also logs the error.
- Feeds run in the launcher process, not in the script sandbox.
- To look at a feed once without subscribing, use `rss <url>`. It prints up to 15 items in the log.

## Feeds or a script?

Built-in feeds are the simplest option. Write a script with
[`rss.fresh(url)`](/scripting/api/#rssfreshurl) if you want to:

- filter items
- merge several feeds into one line
- score items
- show a status line at the top

The bundled [`hn` script](/scripting/library/#hn) is an example.
