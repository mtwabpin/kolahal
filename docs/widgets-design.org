** Built

As designed:

- *The description and its checks*: typed, closed, bounded, colors by role only, secrets masked,
  links checked ([[src:widgets/WidgetParser.kt::object WidgetParser][WidgetParser]]). The stored
  form is JSON with a format number, and the main process checks it again when it reads it
  ([[src:widgets/WidgetSpec.kt::object WidgetJson][WidgetJson]]).
- *The script API*: =@widget <kind> [<size>]=, =widget.show=, =widget.clear=,
  =allowed("widget")=, =event.name= ="widget"= and ="action"=, =event.widget=, and
  =device.unlocks(days)=.
- *The stored state*: the =widget= and =widget.meta= scopes, kept on this phone only, and one
  message from =:script= to the main process when a run ends.
- *Runs from the page*: one when a widget is placed, one when the page shows old content, and
  =refresh= while the card can be seen. They share one queue per script with the pinned line's
  refresh.
- *Kinds*: all 12. A script can use 11 of them; =media= is Kolahal's own.
- *Taps*: ~{ args }~ runs the script again, ~{ url }~ opens a link, ~page = "log"~ turns home
  to the log, and a card with no =tap= refreshes. Each item starts at most one run in 2 seconds.
- *Built-in widgets*: all 7 (Battery and network, Shortcuts, Now playing, Todos, Agenda, Reminders,
  Notes).
- *Ready-made widgets*: all 24 of the catalog. Live score is two scripts, =cricket.js= and
  =football.js=.
- *Phase 3*: the =image= kind; read functions for scripts (=todos.list=, =todos.setDone=,
  =notes.list=, =reminders.list=, =calendar.events=, =feeds.unread=), each behind its own =@uses=
  item; styles in a few text fields.
- *Several widgets from one script*, up to 6 ([[src:widgets/WidgetRef.kt::data class WidgetRef][WidgetRef]]).
  Each has its own content and may have its own options: =script:weather#2= on the page,
  =event.instance= ="2"= in its runs. Its options are on its settings page, from the Widgets screen
  ([[src:ui/widgets/WidgetSettingsScreen.kt::fun WidgetSettingsScreen][WidgetSettingsScreen]]).
- *Placing and backups*: placing is the permission (the =widget= access item follows the placed
  list), a rename moves the widgets, and a backup holds where each widget is, not what it shows.

Built, and not in the design:

- *Looks* (0.5.15). Each placed widget that Kolahal draws has a look
  ([[src:widgets/WidgetLook.kt::enum class WidgetLook][WidgetLook]]): Plain, Tonal, Bold, Split or
  Shape. A kind offers only the looks that change it: =image= has Plain, Tonal and Shape, and
  =buttons=, =toggles= and =media= have no Bold.
- *Places anywhere* (0.5.15). Every widget has a column (of 12) and a top in dp
  ([[src:widgets/WidgetPlacement.kt::object WidgetPlacement][WidgetPlacement]]). Widgets never
  overlap, keep 8 dp between them, and push down what is in their way. The page is laid out by
  [[src:ui/widgets/HostedWidgets.kt::internal fun WidgetGrid][WidgetGrid]].
- *Poster* (0.5.17), a sixth look for =stat=, =countdown= and =clock= only: the value so large that
  the card's end and bottom edges crop it, never more than a fifth of the last character's width
  and 15% of a digit's height ([[src:ui/widgets/WidgetPoster.kt::object PosterFit][PosterFit]]), with the label small in a corner.
- *Next and Stack* (0.5.17), looks of Kolahal's own cards only
  ([[src:ui/widgets/OwnDesigns.kt::internal object OwnDesigns][OwnDesigns]]). Next on Todos: the
  next todo large with a check, a ring of the ticked ones, and Undo for the last tick; it takes
  Shape's place there. Next on Reminders: the next one in a pill that empties over its last hour,
  the later ones as points on a line. Stack on Notes: the newest note on a stack of sheets, and +,
  which puts =note = in the prompt. A card in one of them is drawn on a Plain card by its own body
  (=WidgetCard='s =body=).
- *Now* (0.5.17), a look for =agenda= only (Kolahal's Agenda card and a script's): what is on now
  with a bar, the free time until the next event, and that event; a large card has the day with
  the free time between its events, 15 minutes or more
  ([[src:ui/widgets/AgendaFree.kt::internal object AgendaFree][AgendaFree]], drawn by =AgendaNow.kt=).
- *Dots and page* (0.5.17), two styles of =countdown= that count days on the calendar: a dot a day
  (a week each past 60 days, none past 60 weeks), and the date as a calendar page
  ([[src:ui/widgets/CountdownDays.kt::internal object CountdownDays][CountdownDays]], drawn by
  =WidgetCountdownDays.kt= in every look but Poster).
- *Arrange widgets* (the Widgets screen). A tap chooses a widget, a long-press drags it over column
  guides, handles on its end and bottom edges resize it, and dropping it on the Remove target
  removes it (after a question). Close gaps packs the page. The toolbar has a Look row and a Size
  row (the six sizes, one tap each) for Kolahal's own widgets, a Days row for Agenda, and Settings,
  which opens the card's own page (below). Another app's widget has Widget settings
  when its setup can run again (=setUpAgain= in =WidgetHost.kt=: a setup screen, and
  =reconfigurable=, or =configuration_optional= from Android 12), not while its profile is paused or
  its private space locked; =WidgetBinder.reconfigure= opens it with a request code of its own, so
  its answer, OK or Back, leaves the widget as it is. A screen reader has Move up, Move down, Move
  left, Move right, Wider, Narrower, Taller, Shorter, the widget's Settings or Widget settings, and
  Remove on each widget.
- *A card's own page* ([[src:ui/widgets/WidgetSettingsScreen.kt::fun WidgetSettingsScreen][WidgetSettingsScreen]], =Screen.WIDGET_SETTINGS=), from Settings in the toolbar, or as
  the picker places a further widget of a script with options. The card is at the top, live and at
  its real size; one taller than 40% of the room scrolls away with the page. Then This card (a
  script's options, a value saved running the card again; Shortcuts' editor), Color, Shape (in the
  Shape look, for a card with a choice), What shows (Name and Icon, where the card has them:
  =WidgetParts.offered=) and Reset to the card's own (color, shape, what shows; not the options,
  the look or the size), with Undo in a snackbar. Back returns to Arrange widgets with the card
  still chosen. An app's widget has no page. The button that opens it shows a dot in the card's color and, in the Shape look, a
  small copy of its shape.
- *Other apps' widgets* share the page and the grid with Kolahal's own. They have no look: they
  draw themselves. On a phone without app widgets (Android Go) Kolahal's own still work.
- *Fields the design didn't have*: =note= on every kind (up to 16 characters on a large card's last
  line), =lead= and a row's =range= on =list=, =style = "dots"= on =chart=, and =id= on an
  agenda's event (taken and not kept). =icon= takes a name from 63 line icons
  ([[src:widgets/WidgetIcons.kt::object WidgetIcons][WidgetIcons]]), or an emoji or a letter.
- *Capitals.* A label on a card starts with a capital, whatever the script wrote.
- *Now playing* shows the track's cover, takes a drag on its bar to move in the track, and shows the
  player that played last, with Play, when nothing plays.
- *Agenda* shows Auto (as many days as fit, up to 14) or 1, 3, 7 or 14 days
  (=widgets.agenda-days=).
- *More library widgets*: Daily counter (=counter.lua=, =buttons=), Screen time (=screen-time.lua=,
  =chart=), Screen time by month (=screen-time-months.lua=, =chart=), Data this month
  (=data-month.lua=, =progress=), Unused apps (=unused-apps.lua=, =list=), and four templates
  (=template-widget=, =template-widget-list=, and each in JavaScript). With the catalog's, 23
  library scripts and 4 templates have a widget.
- *Example cards in the script editor.* The editor's API reference draws a card of every kind from
  its example code ([[src:ui/reference/ReferenceExamplesWidgets.kt::internal object ReferenceExamplesWidgets][ReferenceExamplesWidgets]]).
- *A Widget chip* in the library screen of Scripts
  ([[src:script/LibraryTags.kt::enum class LibraryTag][LibraryTag]]).
- *Status cards are gone* (0.5.9). A Status card showed a script's status line as a one-line card.
  It looked plain, and the line shows at the top of home anyway. A placed one is removed once, at

** Built another way

- *Script names.* A script can't have a built-in command's name. So Unlocks is =unlock-chart=
  (not =unlocks=) and Quick toggles is =quick-toggles= (not =toggles=).
- *A long-press on a card* opens Arrange widgets with that card chosen, where it is moved, resized,
  given a look and removed. The card has no menu of its own, and no Refresh, Edit script or Run in
  the log.
- *No title line.* Since 21 November 2026 no card has one. The content shows the card's name small
  where it doesn't say what it is itself, and a large card's last line has the note and the age or
  "Failed 10:42". A wide or a small card has no room for that line; a screen reader still hears it.
- *The icon.* The description's =icon= shows only in the looks that have room for it: Bold and
  Split for =stat=, Split for =countdown=, Shape for =stat= and =text=. A Plain or Tonal card has
  no badge. A row's, a button's and a switch's own =icon= show in every look.
- *Default =staleAfter=*: one hour for every script, and 60 seconds for =toggles=. The design had
  twice the script's interval.
- *States.* A card has fewer states than the design's table: no "refreshing" sign, no Offline, no
  "Needs a key", no "Internet is off", and no Retry or Open script button. Without content a failed
  card shows the error's first line. A card with nothing stored shows the loading shape for 20
  seconds at most, then "Nothing to show".
- *Taps.* A quick second tap on a card, a row, a button or an event waits and runs when the 2
  seconds are over, so two taps on a counter's + add two. A third is dropped. An agenda's events
  take taps too.
- *Times.* A clock and an agenda write a time of day as Kolahal's own setting says (=clock.24h=),
  as the header and the log do. They don't follow the phone's setting.
- *Todos.* A tap on a row marks the todo done. The row stays, ticked, until the page is turned
  away, and a second tap opens the todo again. There is no Undo message. A tap on "+3 more" or on
  the list's name runs =todo=; the rest of the card takes no tap.
- *Shortcuts.* The list is one key of home's own preferences, not a part of the placed widget. Its
  editor is a sheet over the Widgets screen
  ([[src:ui/widgets/ShortcutsEditor.kt::internal fun ShortcutsEditor][ShortcutsEditor]]). A backup carries
  the list with that file, and an import lists each shortcut that the file brought
  as worth a look.
- *"Failed" on a card.* Two kinds of run note their end for the card: a run that the widgets page
  asked for (a ="widget"= run), and a run that a tap on the widget started. So the card says
  "Failed" after one of those failed. It does not after a failed timer, daily or event run: that
  error is in the log only.
- *Toggles.* A switch stops waiting when the card's stamp moves: the script called =widget.show=,
  or the tap's run ended, also when it failed. After 10 seconds with no answer it stops waiting
  too, and shows the state it had. A second tap on the same switch within 2 seconds starts no run.
- *Habit streak* is a command too (=habit done=, =habit undo=), because a tap can be a mistake.
  It draws =style = "dots"=, and says "Done today" as its =note=. It keeps its days as one text in
  its store: a store holds 1000 keys at most, so a key for each day would fill it in under three
  years.
- *GitHub releases* reads each feed once more for its widget, with =rss.fetch=. A release that the
  card shows must still be new to the check.
- *Lobsters* has no widget. Only Hacker News got the list.
- *An option change* runs the placed widgets that read the option, wherever it is set: on the
  widget's settings page, in the script's sheet on the Scripts screen, or
  with =script set=.
- *Backups.* A script widget whose script is missing is placed all the same. Its card says
  "Script removed" until you remove it or a script takes the name.
- *The picker* lists Kolahal's own widgets as plain rows: a name, the kind and the start size, with
  no drawn sample.

* Summary

- *What it is.* A script calls =widget.show{…}= with a small description: "a big number 24°C, the
  label Sunny, two smaller numbers". Kolahal checks the description and draws it as a card, in
  Material 3 Expressive, on the widgets page.
- *No UI code from scripts.* A script picks one of a fixed set of /kinds/ (stat, list, chart, …)
  and fills in its fields. Kolahal owns every pixel, every color and every tap.
- *Where.* On Kolahal's own widgets page, beside other apps' widgets. Not on other launchers'
  home screens.
- *How data moves.* The script runs in =:script=, as every script does. Kolahal stores the checked description
  in =kolahal.db=. The main process reads it and draws. The main process never waits for a script.
- *Refresh.* The script's own timers and events (=@every=, =@at=, =@on=), a tap, and "the page is
  showing and the content is old". Clocks and countdowns tick in Kolahal, with no script run.
- *Taps.* A tap runs /the same script/ again with arguments, or opens a web link. A script can
  never put a terminal command behind a tap. Commands you pick yourself live in a built-in
  Shortcuts widget.
- *Permission.* Placing a widget is the permission, like pinning a status line. No script places
  itself. Everything else uses the access a script already has (=@uses=, internet, secrets).
- *Two feeders, one renderer.* The same cards can also be filled by Kolahal itself, for data that
  must be live or that scripts may not touch (now playing, battery, todos, your own commands).
- *First build.* 6 kinds and 11 ready-made widgets. 7 of the 11 were library scripts that
  existed and gained one =widget.show= call.

* What existed before widgets, and what it meant for the design

These facts come from the code as it was on 14 November 2026, before widgets. Each one limited or
helped the design. Most still hold; where one changed, its line says so.

- *The widgets page* is a Compose page beside the log ([[src:ui/widgets/HostedWidgets.kt::fun WidgetPanel][WidgetPanel]]).
  - It lays widgets out in 12 columns, with a height in dp for each ([[src:widgets/WidgetModel.kt::object WidgetLayout][WidgetLayout]]).
    It has no cells. Then it filled rows in order (=WidgetFlow=); since 0.5.15 each widget has a
    column and a top ([[src:ui/widgets/HostedWidgets.kt::internal fun WidgetGrid][WidgetGrid]]).
  - A placed widget is a [[src:widgets/WidgetModel.kt::data class PlacedWidget][PlacedWidget]]: an AppWidget id and a provider. The stored form
    ([[src:widgets/WidgetModel.kt::object WidgetCodec][WidgetCodec]]) drops a line whose provider has no =/=.
  - The pager keeps the widgets page composed while the log shows (~beyondViewportPageCount = 1~
    in =HomePager=). So "the page is composed" does not mean "the user sees it".
- *Status lines* were the nearest thing to a widget ([[src:data/StatusLines.kt::object StatusLines][StatusLines]]).
  - =status(text, opts)= stores a line by script name in the =kv= table.
  - It shows at the top of home only after the user pins the script. No script pins itself.
  - =opts.refresh= runs the script again while the line shows, as unique work that is never
    queued twice ([[src:script/ScriptScheduler.kt::fun refreshPinned][refreshPinned]]). A failing refresh reports its error once.
  - The design below copies this pattern for widgets.
- *Taps from scripts are narrow on purpose.*
  - A script's log line keeps only =url=, =image=, =copy=, =mono= and =gap= ([[src:script/HostApi.kt::private fun safeCtx][safeCtx]]). The
    =run= key is dropped, so a script can't plant a one-tap command.
  - Buttons under a line (=ctx.actions=) run only the same script again, with arguments and
    =event.name= ="action"= ([[src:terminal/TerminalViewModel.kt::fun runLineAction][runLineAction]]).
  - =launcher.run= works only in a run the user started, needs =@uses commands=, and refuses
    sensitive commands. =torch=, =volume=, =dnd=, =media=, =todo=, =note=, =remind= and =widget=
    are all sensitive ([[src:commands/InstantRun.kt::fun isSensitive][InstantRun.isSensitive]], [[src:commands/ControlSpecs.kt::val SENSITIVE][ControlSpecs.SENSITIVE]]).
- *Scripts can't see the main process.* =MediaRepository.nowPlaying=, =DeviceStatus.status= and
  =UnlockCounter.today= are flows in the main process. A script reads the battery and the network
  itself (=device.battery()=, =device.network()=). It can't read what is playing.
- *Scripts had no call for Kolahal's own lists*: todos, notes, reminders, the calendar, or the
  built-in feed reader. Phase 3 added them, each behind its own =@uses= item.
- *Timers have a floor.* =@every= can't run more often than every 15 minutes (WorkManager). A
  script can't tick a clock.
- *Access is checked in code.* =internet= is on when the code mentions =http=, =rss=, =url=,
  =image= or =launcher.run=. The words =status= and =notify= switch on other items
  ([[src:script/ScriptMeta.kt::fun usesInternet][ScriptMeta]]). So a description must not use fields named =status= or =notify=.
- *The GUI kit is there.* =GuiTheme= builds a Material scheme from the terminal palette, in its dark
  and light version ([[src:ui/theme/GuiTheme.kt::fun schemeFrom][schemeFrom]]). Material 3 (=1.5.0-rc01= then, =1.5.0=
  now) has the Expressive parts this design names. They were checked in the library's sources: =LoadingIndicator=,
  =LinearWavyProgressIndicator=, =CircularWavyProgressIndicator=, =ButtonGroup=, =ToggleButton=,
  =MaterialShapes= with =toShape()=.

* Decisions

** 1. Where widgets show

*Decided: Kolahal's own widgets page only.* This is what was built.

| Place                                   | For                                                                                           | Against                                                                                                             |
|-----------------------------------------+-----------------------------------------------------------------------------------------------+---------------------------------------------------------------------------------------------------------------------|
| Kolahal's widgets page (Compose)        | The page, its layout, its edit screen and its backup exist. Full Expressive shapes and motion. Kolahal can tick clocks itself. Taps are instant. | Shows only while Kolahal is the launcher. That is the product.                                                      |
| Home-screen widgets for other launchers | Reaches people who use another launcher.                                                      | See the list below.                                                                                                 |
| The pinned header                       | Exists. Always in view.                                                                       | One line of text and a bar. It stays as it is.                                                                      |

Why not home-screen widgets (Glance or RemoteViews) now:

- They can't use Compose Material 3 Expressive. Glance has its own small set of parts: no shaped
  badges, no press morph, no springs. Charts would be pictures made in advance.
- They can't share the card code. It would be a second renderer for every kind.
- Kolahal's users have Kolahal as home. A widget for /another/ launcher helps few of them.
- =@on= events are received in the UI process ([[src:script/TriggerDispatcher.kt::class TriggerDispatcher][TriggerDispatcher]]). When Kolahal is not
  the launcher, that process may not run, so event widgets would be late.
- It needs a new dependency (=androidx.glance=) and a new receiver.

The description is data, not code. So a second renderer can be added later without changing any
script: it would read the same stored state. We decided not to build it (14 Nov 2026).

** 2. How a script defines a widget

Three parts: a directive, a call and a description.

*** The directive

#+begin_example
-- @widget <kind> [<size>]        Lua
// @widget <kind> [<size>]        JavaScript
#+end_example

- It says "this script has a widget". The widget picker lists the script, with the kind and the
  size. (The design had the picker draw a sample of the kind; it shows a plain row.)
- =<kind>= is the default kind: one of the 11 a script can use. With any other word the script
  has no widget.
- =<size>= is the size it gets when placed: =1x1=, =2x1=, =2x2=, =4x1=, =4x2= or =4x4=. Without
  one, or with a word that is no size, the kind's default is used
  ([[src:script/ScriptMeta.kt::fun widget(code: String)][ScriptMeta.widget]]).
- The first such line counts. A script with =@uses screen= has no widget: its =@widget= line counts
  for nothing.
- Without this line, =widget.show= is an error that says to add it. This is the rule =@uses= has.
- A script has one =@widget= line, and its widget can be placed up to 6 times, each with its own
  options. See [[*Open questions][Open questions]].

*** The calls

| Call                | What it does                                                                                              |
|---------------------+-----------------------------------------------------------------------------------------------------------|
| =widget.show(desc)= | Checks =desc= and stores it as the widget this run fills. Returns true when that widget is placed, else false. |
| =widget.clear()=    | Removes that widget's content. The card then shows "Nothing to show".                                     |
| =allowed("widget")= | True while one of the script's widgets is placed. A script can skip work when it is false.                |

- =event.name= is ="widget"= in a run the widgets page asked for (just placed, old content, a
  =refresh=, a tap on a card with no =tap=).
- =event.name= is ="action"= in a run a tap started. The tap's arguments are in =args=, and
  =event.label= is the tapped item's label. This is what a button under a log line does, so
  one handler serves both. =event.widget= is true for a tap on a widget.
- =event.instance= is ="2"=, ="3"=… in a run for a further widget of the script, and absent for
  its first widget. A run that is for no widget (a timer, an event, a run you type) fills the first.
- =widget.show= works only in saved scripts, as =status= does. Code typed at the prompt gets a
  line that says so.
- A run may call =widget.show= and =widget.clear= 20 times in all. Later calls change nothing,
  and the first one past the limit logs an error. The same description again is not written.
- A wrong description is an error in the script, with the line number, like any script error.
  Tapping the error opens the editor there.

*** The description

Every kind takes these fields. All are optional.

| Field        | Value                | Meaning                                                                                       |
|--------------+----------------------+-----------------------------------------------------------------------------------------------|
| =kind=       | a kind's name        | Which card to draw. Default: the =@widget= line's kind.                                       |
| =title=      | text, up to 40       | The card's name, shown small where the content needs it, and said by a screen reader. Default: the script's =@title=, else its name; a further widget adds its id ("Weather 2"). |
| =icon=       | a name, or text up to 4 | An icon name (=WidgetIcons=, Material Symbols drawn in the card's color), or an emoji or a letter. Only the Bold, Split and Shape looks draw it (see [[*Expressive shapes and motion][Expressive shapes]]). A lower-case word over 4 letters that is no name is an error. |
| =color=      | a role               | The color of the bar, ring, chart, note or tonal card. Default: =accent=.                     |
| =shape=      | =cookie4=, =cookie6=, =cookie9=, =cookie12=, =clover4=, =clover8=, =sun=, =burst=, =circle=, =pixel=, =gem=, =slanted=, =arch=, =ghost=, =pill= | The card's shape in the Shape look, where it is one shape or its main value sits in one (=hasShapeChoice=) and it may take that shape (=shapesFor=), until the user picks one on its page. Default: the kind's own. |
| =tap=        | an action            | What a tap on the card does. Default: refresh. See [[*4. Interaction][Interaction]].         |
| =staleAfter= | seconds, 60 to 604800 | How long the content counts as current. Default: one hour; 60 seconds for =toggles=. |
| =refresh=    | seconds, 10 to 3600  | Run again this often while the card can be seen. The same limits as =status=.                 |
| =note=       | text, up to 16       | A few words on a large card's last line, in the card's color: "Done today". (Not in the design.) |

A =staleAfter= or =refresh= outside its range is held at the nearer end; 0 or less counts as left
out.

Each kind adds its own fields. They are in [[*Widget kinds][the catalog]].

Rules for every description:

- *Typed.* Each field has one type: text, number, true or false, a role, a list, an action. A
  number where text is expected becomes text. Anything else is an error that names the field and
  says what to pass.
- *Closed.* An unknown field is an error that lists the known ones. A typo such as =colour= does
  not pass unseen. =fmt.bar= and =status= already work this way.
- *Bounded.* Text is cut with "…" at its limit. A list keeps its first items, up to the kind's
  limit. More buttons or switches than a kind allows is an error, and so is a link over 2000
  characters: neither is ever cut. The whole description is at most 32 KB, as JSON.
- *Left out.* A field with no value (=nil=, =null=, =undefined=) counts as left out.
- *Plain text, with a few exceptions.* Styles from =fmt= are removed. Seven fields keep bold,
  italic, underline, strike and color roles ([[src:widgets/WidgetParser.kt::val STYLED][WidgetParser.STYLED]]):
  a text's =text= and =caption=, a list row's =title=, =detail= and =trailing=, a stat's =label=
  and a picture's =caption=. The design had plain text only, and styles in phase 3.
- *Capitals.* A label (a card's, a lead's, a bar's, a button's, a switch's, a caption, a row's
  =detail=, =empty=, =reached=, a chart's =labels=) starts with a capital, whatever the script
  wrote. Titles, values, units and =text= stay as written.
- *Colors by role only.* A script never gives a color value. The theme picks the color, in its
  dark and its light version, so every widget reads on every theme.
- *Safe names.* No field is a Lua keyword (so not =end=, =until= or =in=), and none is =status= or
  =notify=. Links are in fields named =url= and =image=, so the internet switch covers them.
  =WidgetParserTest= checks the list ([[src:widgets/WidgetParser.kt::val FIELDS][WidgetParser.FIELDS]]).

*** Example in Lua: a number

#+begin_src lua
-- @title Weather
-- @widget stat 2x1
-- @every 1h
-- @option city "" City; empty: your IP address's location

local r = http.get("https://wttr.in/" .. options.city .. "?format=%l|%c|%t|%C|%h")
if not r.ok then error("wttr.in answered HTTP " .. r.status) end
local place, icon, temp, sky, humidity = r.body:match("^(.-)|(.-)|(.-)|(.-)|(.-)$")

widget.show{
  title = place,
  icon = icon,
  value = (temp:gsub("^%+", "")),
  label = sky,
  more = { { value = humidity, label = "humidity" } },
  staleAfter = 2 * 3600,
}
#+end_src

When the request fails, the script stops with an error. The card keeps the last good content and
says "Failed 10:42" under it.

*** Example in JavaScript: a list

#+begin_src js
// @title Headlines
// @widget list 4x2
// @every 1h
// @option url https://hnrss.org/frontpage The feed to show

const feed = await rss.fetch(options.url);
widget.show({
  title: feed.title,
  items: feed.items.slice(0, 8).map((it) => ({
    title: it.title,
    tap: { url: it.link },
  })),
});
#+end_src

*** Example with a tap: count glasses of water

#+begin_src lua
-- @title Water
-- @widget progress 2x1
-- @option goal 8 Glasses a day

local today = os.date("%Y-%m-%d")
local n = tonumber(store.get(today) or "0")
if event and event.name == "action" and args[1] == "add" then
  n = n + 1
  store.set(today, tostring(n))
end
local goal = tonumber(options.goal) or 8
widget.show{
  value = n, max = goal,
  text = n .. " / " .. goal,
  color = n >= goal and "good" or "accent",
  tap = { args = "add", label = "Add a glass" },
}
#+end_src

This widget has no timer. It runs when it is placed, when it is tapped, and when the page shows it
with old content.

*** Example where Kolahal does the ticking

#+begin_src lua
-- @widget countdown 2x1
widget.show{ title = "Goa trip", to = os.time{ year = 2026, month = 12, day = 20, hour = 0 } }
#+end_src

The script runs once. Kolahal counts the days, hours and seconds itself.

*** The same file on an older Kolahal

A library script that gains a widget keeps working on a version without widgets:

- An older Kolahal ignores the unknown =@widget= line.
- The script guards the call: ~if widget then widget.show{…} end~ in Lua,
  ~if (typeof widget !== "undefined") …~ in JavaScript. The library scripts already do this for
  =fmt.bar= and =fmt.stats=.
- So no =@requires= line has to change for the widget. (The changed library scripts have raised
  theirs since, most to 0.5.9 or later, for other parts of the API they use.)

** 3. Data flow and refresh

*** The flow

#+begin_example
 :script process                          kolahal.db (kv table)            main process
 ───────────────                          ─────────────────────            ────────────
 a run: timer, event, tap, refresh
   └ widget.show(desc)
       └ HostApi.widgetShow
           ├ WidgetParser.parse   types, limits, secrets masked, links checked
           └ WidgetStates.putEncoded ──▶  scope "widget"                       WidgetStates.versionOf(key)
 the run ends (ScriptRun.widgetEnd)    ── one message per run ─────────▶      └ the card re-reads
   └ ok, or the error ────────────────▶  scope "widget.meta"                      its own state
                                          scope "widget.placed" ◀──────────── the placed list's copy

                    ◀──── a tap or a refresh request, queued with WorkManager ────
#+end_example

1. The script calls =widget.show(desc)=.
2. =HostApi= checks it in the =:script= process. So a mistake is a script error with a line number.
3. The checked description is stored as JSON, by the widget's key, in a =kv= scope.
4. A package-private message tells the main process, as the log's message does.
5. The main process reads the state on an IO thread and decodes it again. It never trusts stored
   JSON: anything it can't read shows as "widget unavailable".
6. The card redraws.

*** The stored state

Two scopes, keyed by the widget's key ([[src:widgets/WidgetRef.kt::val key][WidgetRef.key]]):
the script's name for its first widget (=weather=), and the name with an id for a further one
(=weather#2=). The design keyed them by script name, and left room for this.

- =widget=: the description, as checked JSON with a format number.
- =widget.meta=: written by Kolahal, never by the script: when the content was last set, when a
  run was last tried, and the last error (masked, at most 300 characters).

A third scope, =widget.placed=, is the main process's copy of the placed list for =:script=: for
each script name, the ids of its widgets on the page ([[src:widgets/WidgetRef.kt::object PlacedIds][PlacedIds]]).
All three are in =Stores.THIS_PHONE=.

Rules:

- Kolahal writes the state only for a placed widget. For a widget that isn't placed,
  =widget.show= checks the description and returns false. So nothing private waits in the database
  for a widget nobody sees.
- A description equal to the stored one is not written again. Only its time moves.
- The content's time moves only when =widget.show= is called. A run that works but never calls it
  (=weather Paris= typed at the prompt) changes nothing on the card.
- A card says "Failed" after a failed ="widget"= run or a failed run that a tap on it started.
  A failed timer, daily, event or typed run shows its error in the log only, and leaves the card
  alone. (The design had timer, daily and event runs fail the card too.) The next =widget.show=
  clears the error.
- The state is a cache. It may hold private text, and a run makes it again. So it does not go
  into backups (see [[*Backups][Backups]]).
- A script's widgets' state is removed when the script is deleted, switched on or off, changed
  from outside, or saved without its =@widget= line, as its status line is
  ([[src:widgets/WidgetStates.kt::fun forgetScript][WidgetStates.forgetScript]]). The widgets stay
  placed. A new script that takes an old name starts empty.
- One widget's state, and a further widget's own options, are removed when that widget is taken
  off the page.
- A rename moves the state, the options and the placed entries to the new name.

*** The message between the processes

Do /not/ reuse =LogRepository.onStatusChanged()=. It raises the log's version, and that makes the
view model read the log again. Widgets get their own message and their own counter:

- =:script= sends =WIDGETS_CHANGED= (package-private, like =LOGS_CHANGED=).
- It names the widget by its key. =LauncherApp= receives it and raises that widget's number
  (=WidgetStates.versionOf=). A message with no name raises every widget's number.
- A run stores quietly and sends one message when it ends (=ScriptRun.widgetEnd=), not one per =widget.show=.
  A =widget.show= early in a long run is drawn when the run ends.
- Each card collects only its own number, and only while home is started.

*** What starts a run

| Trigger                    | How                                                                                             | =event.name=            |
|----------------------------+-------------------------------------------------------------------------------------------------+-------------------------|
| The script's timer         | =@every=. 15 minutes at the fastest.                                                            | none                    |
| A daily time               | =@at=.                                                                                          | ="at"=                  |
| A device event             | =@on=. At most once in 30 seconds for each event.                                               | the event               |
| The widget was just placed | One run at once.                                                                                | ="widget"=              |
| The card shows old content | While the card can be seen (the page in view, the card on screen), a card whose content (or last try) is older than its =staleAfter= asks for one run. It looks again every minute. | ="widget"=           |
| =refresh= in the description | While the card can be seen (the page in view, the card on screen), run again that often.     | ="widget"=              |
| A tap with arguments       | See [[*4. Interaction][Interaction]].                                                           | ="action"=              |
| A tap on a card with no =tap= | One quiet run, at most one in 2 seconds.                                                     | ="widget"=              |
| An option changed          | A value set on the widget's settings page, in the script's sheet or with =script set=: the placed widgets that read it run. | ="widget"=              |
| A switch turned on         | An access switch of the script was allowed: its placed widgets run, so a card that the switch had stopped is filled at once. | ="widget"=              |

The design had a "Refresh" item in a menu on the card. There is no menu: a long-press opens
Arrange widgets, and a tap on a card with no =tap= refreshes it.

- "In view" means: the pager has settled on the widgets page, and home is on screen. Being
  composed is not enough, because the pager keeps the page composed beside the log.
- A card with nothing stored and no run ended yet asks for a run at once. A script that is off,
  gone, or without its =@widget= line gets no run.
- The ="widget"= runs of each widget of a script and its pinned line's refreshes share one queue
  per script (=script-<id>-refresh=). Each widget is a kind of its own (=widget=, =widget#2=). A
  new request of a kind that waits or runs already is dropped; another kind waits behind it. A
  run for a changed option is never dropped: it goes after the one there.
  A script that goes online waits for a network.
- A ="widget"= run is quiet, like a pinned line's refresh. What it returns isn't logged. A failure
  is logged once, until a run works again.
- The script's own =log()= lines /are/ still logged in these runs. A library script skips them
  when =event.name= is ="widget"=. This is the rule pinned lines have, so there is one rule.
- Default =staleAfter=: one hour, and 60 seconds for =toggles=
  ([[src:terminal/WidgetActions.kt::internal object WidgetAge][WidgetAge]]). The design had twice
  the script's interval, and 26 hours for daily times. So a library script with a longer timer
  sets its own: =weather= and =hn= say two hours, =exchange= 12 hours.

A script with no timer at all is a good widget: it runs only when you look at it, so it uses no
battery in the background.

*** How each state looks

What the card shows in each state ([[src:ui/widgets/ScriptWidgets.kt::internal enum class CardNote][CardNote]]).
A card says its name small over a note where there is room; a small card has the note alone. The
footer ("2 h ago", "Failed 10:42") is a large card's last line; a wide or small card has no room
for it, and a screen reader still hears it.

| State                          | What the card shows                                                                                     |
|--------------------------------+---------------------------------------------------------------------------------------------------------|
| Not read yet                   | Nothing, for the moment it takes to read the stored state.                                              |
| No content yet                 | A =LoadingIndicator= (the Expressive shape that changes form), drawn only while the card can be seen. After 20 seconds with no run ended: "Nothing to show". |
| Current                        | The content. No footer.                                                                                 |
| Old (past =staleAfter=)        | The content stays readable. The footer says its age: "2 h ago". Nothing is dimmed. A =toggles= card says it only after an hour. |
| Failed, with content           | The content stays. The footer says "Failed 10:42" (or "Failed 2 d ago" when not today) in the error color. |
| Failed, no content             | The error's first line, with secrets masked and its line number as "(line 12)".                         |
| Can't be read                  | "Widget unavailable": the stored description fails the checks, or a built-in widget this version doesn't have. |
| The script is off              | "Script is off". A tap opens Scripts. No run is asked for.                                              |
| The script was deleted         | "Script removed". A tap opens Arrange widgets, where it can be removed.                                 |
| The script has no =@widget=    | "Script has no widget now". A tap opens Scripts. No run is asked for.                                   |
| Nothing to show (=widget.clear=) | "Nothing to show".                                                                                    |

The design had more, and these are not built: a small sign in the corner while a card with content
refreshes, a tap on the footer to try again, Retry and Open script buttons on a failed card,
"Offline · 2 h ago", "Needs WAQI_TOKEN" with Add key, and "Internet is off for this script" with
Allow. Such a run fails, and the card shows its error.

The words come from Kolahal, never from the script, except the content and the error's first line.

** 4. Interaction

*** What a tap can do

An /action/ is a small table with exactly one of these:

| Action                    | What happens                                                                                  | Build       |
|---------------------------+-----------------------------------------------------------------------------------------------+-------------|
| ~{ args = "add 1" }~      | This script runs again with these arguments, split at spaces. =event.name= is ="action"=. =args= may be empty. | Built |
| ~{ url = "https://…" }~   | The web link opens. At most 2000 characters; a longer one is an error, never cut.             | Built       |
| ~{ app = "com.example" }~ | The app opens. Needs =@uses apps=. Never an app in the private space.                         | Not built (phase 2) |

Both =args= and =url=, or neither, is an error.

An action can also have:

- =label=: what a screen reader says for it. Up to 24 characters.
- ~page = "log"~, with =args=: home turns to the log at the tap. Use it for a run that prints,
  such as the full weather report. With =url= it is an error.

Where actions go:

- =tap= on the card: the whole card.
- =tap= on an item of a =list=, a button of =buttons=, a switch of =toggles=, or an event of an
  =agenda=. A button and a switch need one, and a switch takes only ~{ args }~.
- No =tap= on the card means "refresh": a quiet ="widget"= run.

*** Three paths for a tap, and who may use each

1. *Run the same script again* (~{ args }~). Any script widget.
   - It is the path buttons under a log line use
     ([[src:terminal/WidgetActions.kt::class WidgetActions][WidgetActions]]), with arguments up
     to 200 characters, and at most one run in 2 seconds for each item. A quick second tap waits
     and runs when the 2 seconds are over (=TapGate.runOrWait=), so two taps on a counter's +
     add two; a third is dropped. The gate is per widget, so the same button on two widgets of
     one script runs for each.
   - The run is =ScriptScheduler.runNow=, with =event.widget= true and, for a further widget,
     =event.instance=.
   - The run counts as started by the user. So =launcher.run= works in it, under its rules:
     =@uses commands= allowed, no sensitive command, no secret in the command, and a command that
     sends words to a website needs the internet switch.
2. *Open a link or an app* (~{ url }~, ~{ app }~). Any script widget.
   - A link passes the check a log line's link passes when =widget.show= stores it: web links
     only, the internet switch must be on, and no secret goes to a site its =@secret= line doesn't
     name. A link that fails stops the run with an error.
   - The ~{ app }~ action is not built.
3. *Run a command you picked yourself.* Only the built-in Shortcuts widget.
   - You type or pick each command in its editor on the Widgets screen.
   - A tap runs it the way a gesture runs its command: as if you had typed it and pressed Enter
     (the view model's =runTyped= hands it to =processor.run=), and home turns to the log. It may
     be =torch= or =dnd=, because you chose it.
   - The card's description holds only the button's place in the list (=run 2=). The command is
     looked up in your list at the tap ([[src:terminal/OwnWidgets.kt::internal object OwnTaps][OwnTaps]]).
   - The other built-in cards' taps are a fixed set of words too: mark a todo done, a media
     button, open an event, ask for an access. None runs a script.
   - This is /not/ the path of a tapped history line. That path needs =launch.instant all= and
     refuses sensitive commands, so half the buttons would do nothing.
   - A script can't write to this list. =ShortcutsWriteTest= checks every file that touches it.

What is refused, and why:

- *A command in a description* (~{ command = "…" }~). It would break the rule that a script can't
  plant a one-tap command. A timer run could store it, and a later tap would run it unseen. Path 1
  gives a script the same reach, with the checks that exist.
- *Toggling the torch, the volume or media from a script.* Those commands are sensitive, and
  scripts have no function for them. They belong in Shortcuts (path 3) or in the Now playing
  widget.

*** Toggles

A =toggles= widget shows switches. Each has =on= (true or false) and a =tap= with =args=.

1. You tap. The switch shows "working".
2. The script runs with the arguments. It changes the thing (=device.setDnd(…)=) and calls
   =widget.show= with the new state.
3. The switch takes the new state. It stops waiting when the run ends, also when it failed, or
   after 10 seconds with no answer, and shows the state it had. (The design had the card say the
   run failed after 10 seconds.) A switch that waits takes no second tap, and a tap within 2
   seconds of the last one on it starts no run.

Kolahal never guesses the new state. The script reports it.

*** The card's own menu

Not built. A long-press on any card of the widgets page opens Arrange widgets, with that card
chosen, and so does one on the line that stands for a widget that can't show (a paused profile, a
locked private space, an app that took its id back). Another app's widget has the long-press for a
screen reader too (=KolahalWidgetView=). Its toolbar has what the menu was to have, as far as it is
built: the look, the size, Settings (the card's settings page, for Kolahal's and scripts' cards),
Widget settings (for another app's widget whose setup can run again), and Remove. There is no
Refresh (a tap on a card with no =tap= refreshes it), Run in the log or Edit script.

On Arrange widgets, a tap chooses a widget and does not reach it. App widgets behave the same.

** 5. Layout and look

*** Sizes

The page has 12 columns. Script widgets name their size in /cells/ of a 4-column grid, as people
know from home screens. One cell is 3 columns.

| Size | Columns | Height                 | Good for                         |
|------+---------+------------------------+----------------------------------|
| 1×1  |       3 | 1 row                  | one number, one ring, one button |
| 2×1  |       6 | 1 row                  | a number with its label          |
| 2×2  |       6 | 2 rows                 | a small list, a ring, a chart    |
| 4×1  |      12 | 1 row                  | a row of numbers or buttons      |
| 4×2  |      12 | 2 rows                 | a list, a chart, an agenda       |
| 4×4  |      12 | 4 rows                 | a long list, a picture           |

- One row is as tall as one cell is wide on this phone, and at least 88 dp
  ([[src:widgets/WidgetSizes.kt::fun heightDp][WidgetSizes.heightDp]]). So 1×1 is about square.
  On a page 360 dp wide a cell is 84 dp (=WidgetLayout.widthDp(page, 3)=), so a row is 88 dp.
- =h= rows are =h= × row + (=h= − 1) × 8 dp, to match the 8 dp gap between widgets.
- The size is only where a widget /starts/. After that it is a placed widget like any other: on
  Arrange widgets its handles change its width in twelfths and its height in 8 dp steps. For one of
  Kolahal's own widgets the toolbar has the six sizes as one-tap buttons; an app's widget has width
  and height steppers and Square instead.
- A widget Kolahal draws is at least 3 columns wide and 72 dp tall; an app's widget at least 2
  columns and 48 dp, and never narrower than its app says it can be. A new app widget starts at the
  width its app asks for, not at the page's.
- The card draws for the box it gets, not for the size it asked for. Each kind has three layouts:
  small, wide and large, chosen from the measured box
  ([[src:widgets/WidgetSizes.kt::fun box][WidgetSizes.box]]): large from 150 dp tall, else wide
  from 150 dp wide, else small. Each kind says what it leaves out when it is small (the catalog
  lists it). What is left out is still read by a screen reader.

*** One page, one list

- Script widgets, built-in widgets and app widgets share one placed list and one
  [[src:ui/widgets/HostedWidgets.kt::internal fun WidgetGrid][WidgetGrid]]. You can put the weather card
  beside another app's clock. The design had them flow in rows in order (=WidgetFlow=); since
  0.5.15 each has a column and a top ([[*Built][Built]]).
- A =PlacedWidget= whose provider is a source has no AppWidget id, and it is not "pending". Its
  =source= is read from the provider field, which holds the source:

  | Source             | What it is                                                     |
  |--------------------+----------------------------------------------------------------|
  | =script:<name>=    | the first widget a script fills with =widget.show=             |
  | =script:<name>#<id>= | a further widget of the script: =script:weather#2=           |
  | =builtin:<id>=     | a built-in widget, such as =builtin:battery=                   |

- The stored line is =id|provider|serial|height|order|location|span|look|column|top=
  ([[src:widgets/WidgetModel.kt::object WidgetCodec][WidgetCodec]]). An older Kolahal reads the
  fields it knows by position.

- Script names are =a-z=, =0-9=, =-= and =_= only ([[src:script/ScriptNames.kt::val NAME][ScriptNames.NAME]]), so the line's
  separators can't appear. The codec still refuses a source with =|= or a line break, as it
  refuses such a provider from a backup.
- An older Kolahal skips a line whose provider has no =/=. So going back to an older version
  drops these widgets and breaks nothing.
- A built-in widget is placed once; the picker then says "Added". A script's widget can be
  placed up to 6 times; the picker says "Added · tap to add another", and "Added · 6 of 6" at
  the most.

*** Placed, and the =widget= access item

- The placed list is the source of truth. It is in the main process's preferences, which the
  =:script= process can't follow.
- So the main process copies "placed" into the database twice: the script's access item =widget=
  (on while one of its widgets is placed), and the =widget.placed= row of its name (which of its
  widgets are). =widget.show= reads both to decide whether to store
  ([[src:script/HostApi.kt::internal fun widgetPlacedNow][HostApi.widgetPlacedNow]]).
- When the two disagree, *the placed list wins*. At start and after a backup is imported, the main
  process sets =widget= on for each script with a placed =script:= entry and off for every other
  script ([[src:widgets/WidgetHost.kt::fun syncAccess][WidgetHost.syncAccess]]).
  This matters after a restore: a backup carries only the access you switched /off/, so without
  this step a restored widget would stay empty for ever.
- The item covers only =widget.show= and =widget.clear=. You can't switch it by hand.
- A rename moves everything with the script, as it moves the status line
  ([[src:data/ScriptRepository.kt::fun rename][ScriptRepository.rename]]): the state, the further
  widgets' options, the =widget.placed= row, and the placed =script:= entries.

*** The picker

The widget picker has a first section, *Kolahal*, above the apps
([[src:ui/widgets/WidgetPickerScreen.kt::fun WidgetPickerScreen][WidgetPickerScreen]]):

1. Built-in widgets.
2. Your scripts that have a =@widget= line.
3. Not built: library scripts with a widget that you haven't added, each saying what the script
   uses, and placing the widget as =script install= adds the script.

Picking an entry places the widget at once, at the end of the page, and opens Arrange widgets with
it chosen. Each entry is a plain row: its name, its kind ("Built-in" for Kolahal's own) and the
size it starts with. The design had a drawn sample of the kind. =widget add= opens the picker;

*** Accessibility

- Each card is one item for a screen reader: "Weather, Pune: 24 degrees, Sunny. Updated 5 minutes
  ago." Items with their own tap are separate items inside it.
- Every button and switch is at least 48 dp. A row of a list or an agenda that takes a tap is 44 dp,
  or as tall as its text at a larger font size:
  a list is read more than tapped, and a 4×2 card then shows three rows. A kind shows fewer buttons
  in a small box and never smaller ones.
- A chart has words. The script can give =summary=. Without one, Kolahal says "7 values, from 3 to
  12, the latest 9", or for dots "Done on 23 of the last 35 days".
- A picture needs =alt= text. The card shows it when it has no picture.
- Color is never the only sign. An error has words ("Failed 10:42"). A toggle has a shape and a state.
- Text follows the system font size. Long text is cut with "…".
- Rows run right to left in a right-to-left language: =WidgetGrid= counts columns from the start
  edge.
- Custom actions for a screen reader on the widgets page (Refresh, Resize and move, Remove) are not
  built. On Arrange widgets each widget has Move up, Move down, Move left, Move right, Wider,
  Narrower, Taller, Shorter and Remove.
- Content that changes by itself is not announced each time. That would be noise.

** 6. Safety and privacy

*** What a script can and can't do with a widget

- It can fill a card of a fixed kind. It can't draw, place views, or run code in the main process.
- It can't place, move, resize or remove a widget. The =widget= access item is on only while you
  have placed it, as =header= is on only while you pinned the script.
- It can't put a command behind a tap ([[*4. Interaction][Interaction]]).
- It can't make the card say "Kolahal" things. The footer and the state messages are Kolahal's.

*** Every text and link is checked

- Every text is passed through =redact= first. A secret's value, and its stand-in mark, never reach
  the screen or the database.
- A link (=url=) and a picture (=image=) pass =safeWebUrl=: =http= and =https= only, the internet
  switch on, and no secret sent to a site its =@secret= line doesn't name. A link that fails stops
  the run with an error that says why, as a refused request does. A card with a dead tap would be
  worse.
- A picture must be =https=: home fetches it without a tap, so never over plain http. Home fetches
  it only while the widgets page is in view, over https only (redirects too), with the log's
  picture cache on disk and a memory cache of its own (16 MB) for the cards.

*** What a widget may show on home

| Data                  | Rule                                                                                                          |
|-----------------------+---------------------------------------------------------------------------------------------------------------|
| Secrets               | Never. They are masked before anything is stored.                                                             |
| Notifications         | Only from a script with =@uses notifications= allowed. The log shows notifications, so this is no new exposure. No ready-made widget does it. |
| The clipboard         | Not useful: Android lets only the app in front read it, so a timer run gets nothing. No widget for it.        |
| The private space     | Never. Scripts can't see its apps or its notifications. (The =app= tap that was to keep out of it is not built.) |
| Your app list         | Only with =@uses apps= allowed.                                                                               |
| Todos, notes, calendar | The built-in widgets. Scripts read them with =todos.list=, =notes.list=, =reminders.list=, =calendar.events= and =feeds.unread=, each behind its own =@uses= item that you allow (=todos=, =notes=, =reminders=, =calendar=, =feeds=). =calendar.events= is empty without the calendar permission. |

*** When the private space is locked

- An app widget from the private space shows "Private space locked".
- A script widget holds nothing from the private space, so locking changes nothing for it.
- Built-in widgets never read the private space.

*** Who sees the widgets page

- Kolahal draws nothing on the lock screen. The page shows only after unlock.
- The page can appear in the Recents picture of home, as the log can.

*** Limits that stop a runaway script

- At most 20 =widget.show= and =widget.clear= calls in a run, in all. The same description again
  is not written.
- At most 32 KB for a description, as JSON.
- =refresh= no faster than every 10 seconds, and only while the card can be seen.
- A tap on one item starts at most one run in 2 seconds; one more quick tap waits for that.
- At most 6 widgets for one script.
- All run limits stay: 60 seconds, 64 MB, the watchdog.

*** What a backup holds

- A backup holds where each widget is, not what it shows.
- The state scopes (=widget=, =widget.meta=, =widget.placed=) are in =Stores.THIS_PHONE=. So they
  don't go into a backup file, a restore keeps this phone's, and a new phone starts them empty.
- An imported script arrives switched off. Its card says "Script is off", and a tap opens Scripts.
  (The design had a Turn on button.)

** 7. Performance and battery

- *No main-thread work.* Scripts run in =:script=. The main process reads a widget's state on an
  IO thread, only when that widget's number moves. A state equal to the one in use draws nothing
  again.
- *The page draws at once.* On a cold start the cards come from stored state. No script has to run
  first. A card drawn again (home came back) starts with the state it read last
  (=WidgetStates.lastRead=), so it shows in its look at once.
- *Cheap redraws.* The checked description is an =@Immutable= class. Cards have stable keys. A card
  redraws only when its own state changes.
- *Tickers.* One shared ticker, by the minute: the header's =rememberNow=. A ticker by the second
  runs only for a clock, a countdown or a playing track that shows seconds, and only while the
  card can be seen. Nothing moves for ever: the loading shape, a wave and the seconds stop when
  the card is out of sight.
- *Bounded runs.*
  - =@every=: 15 minutes at the fastest. This is WorkManager's floor.
  - =refresh=: 10 seconds at the fastest, only while the card can be seen, never two at once for
    one widget.
  - Showing the page runs only widgets older than their =staleAfter=.
  - Two runs of one script never overlap: there is one queue of refresh runs per script, and
    every run in =:script= takes one lock ([[src:script/ScriptWorker.kt::internal object ScriptRun][ScriptRun]]).
- *Caching.* Scripts use =http.cached=. Pictures use the log's picture cache on disk (50 MB at
  most), decoded for the card's size.
- *Nothing new in the background.* When home is not on screen, only a script's own timers and
  events run. They fill a script's first widget only: a further widget runs only from the page.
- *Memory.* The main process holds state for placed widgets only, each at most 32 KB.
- *Tap speed.* A tap with =args= takes as long as a button under a log line: WorkManager starts the
  run in =:script=. A tapped switch shows "working" at once. Shortcuts and built-in widgets react
  in the main process, with no run.

*** 1. =stat=: a big number                                      :first:built:

- Shows :: One value, large. A label under it. Optionally a change with an arrow, up to three
  smaller values, and a bar.
- Fields :: =value= (text or number, needed, up to 40). =label= (up to 60, may have styles).
  =unit= (up to 12). =delta= (text such as "+2.4%", up to 16) with =trend= (=up=, =down= or
  =flat=). =more=: up to 3 of ~{ value, label }~, each up to 24. =progress= (0 to 1), with
  =moving= (true) to draw it as a wave, for something in progress. =points= (numbers, the last
  60): a soft line under the value, from edge to edge. =scene=: one of Kolahal's own shaders, its still
  the card's ground, under a scrim (=StatScenes=: no shader on text or played once). The value's digits roll
  to a new value (=RollingText=).
- When small :: 1×1 shows the value and the label. The smaller values and the title are left out.
- Data :: Any script.
- Refresh :: The usual. =refresh= suits a live score.
- Taps :: The card.

*** 2. =text=: a few lines                                       :first:built:

- Shows :: Text of up to 500 characters, with its line breaks, and a caption under it (an
  author, a source).
- Fields :: =text= (needed, up to 500). =caption= (up to 60). Both may have styles.
- When large :: The text is bold, as the mockup has it: there it is the card's main thing.
- When small :: Fewer lines, cut with "…".
- Data :: Any script. Built-in: Notes (phase 2).
- Taps :: The card.

*** 3. =list=: rows                                              :first:built:

- Shows :: Rows, as many as fit, then "+3 more". Each row has a title and can have a second line,
  a text at its end, an icon and a color. When every row fits, the rows grow to share the card's
  height evenly, up to 56 dp: three days of a forecast fill a 2×2 card. Rows under a =lead= keep
  their height.
- Fields :: =items= (needed, may be empty; the first 12 are kept): each ~{ title, detail,
  trailing, icon, color, tap, done, range }~, with only =title= needed. A row's =title= (up to 80),
  =detail= (up to 120) and =trailing= (up to 24) may have styles. =empty=: what to say with no rows
  ("Nothing new"). =lead= ~{ value, unit, label }~: a big line over the rows (the Reminders card's
  next reminder). A small or a wide card shows the lead alone. (=lead= was not in the design.)
- Phase 2 adds :: =done= (true or false) on an item draws a checkbox, for todos and habits.
- 0.5.16 adds :: =range= ~{ low, high, value }~ on an item draws a 4 dp bar from its low to its
  high, between its title and its =trailing= text, with a dot at =value=. The bars of the rows shown
  share one scale and one column, so the forecast's days compare at a glance. Where a row is
  narrow, its icon gives way first, then the bar; the texts stay.
- When small :: 2×2 shows 3 rows without their second line.
- Data :: Any script. Built-in: Todos, Reminders (phase 2).
- Taps :: Each row, and the card.

*** 4. =progress=: a ring, bars, rings, a gauge or stages        :first:built:

- Shows :: How far along something is. A ring with a text in its middle, or up to four bars on

- Fields :: =value= (number) and =max= (above 0; 1 by default). =text= (what the middle says:

  label, value, max, text, color }~ for bars, on one scale: the widget's =max=, or the largest
  value. =value= or =items= is needed. =moving= (true) draws the wave, for something in progress.
- Gauge :: =style= =gauge=: a thick arc from =min= (0) to =max=, filled to the value with a knob,
  the value large inside, =unit= with it, and =label= as the word for the value in its zone's
  color. =zones=: up to 5 of ~{ from, color }~, rising; without them the arc is in the card's
  color. Bold draws the arc with the value in its narrow type; Shape puts the arc in the clover.
- Rings :: =style= =rings=: =items= as up to 4 rings inside each other, each in its color with a
  dim track; an item's =moving= makes that ring a wave. 4×2: each ring named beside them, its

- Strict by style :: A field that only another style draws is an error, as an unknown one is: =min=,

*** 5. =chart=: a line or bars                                   :first:built:

- Fields :: =points= (numbers, needed; the last 60 are kept). =style=: =line=, =bars= or =dots=.

- Dots :: Points that are all 0 or 1 are days done (a filled dot) and missed (a ring), so no state

*** 6. =countdown=: time to a moment                             :first:built:

  than 48 hours away. =reached=: what to say on the day.
- Kolahal ticks :: The script gives the moment once. No run is needed as time passes.
- Data :: Any script. (The design had Reminders use it for the next reminder; Reminders is a
  =list= with a =lead=.)
- Taps :: The card.

*** 7. =buttons=: a grid of buttons                              :phase2:built:

- Shows :: Up to 8 buttons, each with a label and an icon.
- Fields :: =items= (needed; more than 8 is an error): each ~{ label, icon, color, tap }~, with

- Data :: A script: every button runs the script again, or opens a link (the ~{ app }~ action is

- Taps :: Each button.

*** 8. =toggles=: switches                                       :phase2:built:

- Shows :: Up to 6 switches, each with a label, an icon and a state.
- Fields :: =items= (needed): each ~{ label, icon, on, tap }~, with =label=, =on= and =tap= needed.

- Data :: A script that can read and change the thing: Do Not Disturb (=@uses dnd=), the work
  profile (=@uses work=), or its own values in =store=.
- Refresh :: A short =staleAfter= (60 seconds), because the thing can change elsewhere.
- Taps :: Each switch ([[*Toggles][how]]).

*** 9. =clock=: the time in several places                       :phase2:built:

- Shows :: Up to 4 places, each with its time, and "tomorrow" or "yesterday" when the day differs.

- Fields :: =zones= (needed; the first 4 are kept): each ~{ zone, label }~. =zone= is a time
  zone name such as =Asia/Kolkata=; an unknown one is an error. =label= is up to 24.

- Taps :: The card.

*** 10. =agenda=: events by day                                  :phase2:built:

  font size (it grows with a larger one): the heading's 16 and the event's line of 28. So every event keeps its 44 dp tap, and a 4×2 card
  shows two events of today and one of tomorrow, as the mockup has them. "+3 more" is the line

- Fields :: =events= (needed; the first 20 are kept): each ~{ title, starts, ends, allDay, where,

- Data :: Built-in: the phone's calendar. A script: any source of dated items, such as matches or

** Backups

- *Placement travels.* The backup's ="widgets"= list has an entry for each widget: its provider or
  source (=script:weather=, =script:weather#2=, =builtin:battery=), the profile, the height, the
  location, the order, the width, the look, the column and the top
  ([[src:widgets/WidgetModel.kt::fun export][WidgetCodec.export]]). The design had a built-in's
  settings there too; the built-in widgets keep theirs elsewhere (the Shortcuts list in home's
  preferences, =widgets.agenda-days= in the settings).
- *They come back by themselves.* App widgets need "Add again", because their ids belong to one
  phone. A widget Kolahal draws is placed as it comes, where it was if that place is free, else in
  the first free space. An entry whose script is missing is placed too (the design had it skipped
  and named): its card says "Script removed".
- *The script arrives off*, as every imported script does. Its card says "Script is off".
- *The placed list wins.* A backup carries only the access you switched off. So after the import,
  the =widget= item and the =widget.placed= rows follow the placed list (=syncAccess=).
- *State does not travel.* It is a cache and may hold private text. Options (a further widget's
  too) and script stores travel. Secrets never do.
- *Older versions are safe.* They read only entries with a provider that has a =/=. They skip the
  new ones.
- *Shortcuts' commands* are listed for review after an import ([[src:widgets/Shortcuts.kt::fun review][Shortcuts.review]]).

* Open questions

Each had a recommended answer, and the plan assumed it. The code has answered all but one; the
answer follows each.

1. *Where do widgets show in the first build?*
   Decided: only on Kolahal's widgets page. Widgets for other launchers are not planned.

2. *May a script put a terminal command behind a tap?*
   Recommended: no. A tap runs the same script again, and that run may use =launcher.run= under
   its rules. Commands you pick yourself go in the built-in Shortcuts widget.
   Answered: no, as recommended. A tap has only =args= or =url=.

3. *Kolahal's own data (todos, agenda, now playing, battery): built-in widgets, or new script
   functions?*
   Recommended: built-in widgets first. They are live, need no new access items, and can do what
   scripts may not (mark a todo done, control media). Script functions come in phase 3.
   Answered: both, in that order. Seven built-in widgets, then =todos=, =notes=, =reminders=,
   =calendar= and =feeds= for scripts.

4. *One widget for each script, or several?*
   Recommended: one in the first build. It is keyed by script name, as a status line is. Two
   cities then need two scripts. Several widgets from one script, each with its own options, is
   phase 3. The stored key leaves room for it.
   Answered: several, up to 6, each with its own options. The first widget's key is still the
   script's name (=weather=); a further one's is =weather#2=.

5. *Should Shortcuts be in the first build?*
   Recommended: phase 2. It needs its own small editor. It does not depend on scripts, so it can
   move to the first build if it is the widget you want most.
   Answered: phase 2, with its editor on the Widgets screen.

6. *Which typeface do the cards use?*

   Recommended: 10 seconds, as for a status line, and only while the widget is in view.

10. *Does a widget's content go into backups?*

    Answered: no. Where it is placed, its look and its own options do.

    Answered: yes. Nothing in the widget code stops it, and no ready-made widget does it.
