Kolahal 0.5.6, package `com.mtwabpin.kolahal`, Android 9 or newer. It installs over 0.5.5 and keeps your data and settings.

- **kolahal-0.5.6.apk**: the full build.
- **kolahal-0.5.6-play.apk**: the Play build, the same app as on Google Play: no screen lock (`lock`, double-tap), no calls in the log and no `update`, and it finds people with Android's contact picker instead of reading your contacts. Play Protect may block either APK when sideloaded in India and some other countries, as both have notification access: install with scanning off, as the install guide says. Both APKs use the same package and key, so either installs over the other.

## Fixed

- **A command you turned off no longer breaks Kolahal's own buttons.** The header's todo and unlock counts, the quick actions, setup fixes and "tap to allow" lines still run it. Typed lines, gestures and scripts still can't.
- **A feed can no longer use up the launcher's memory** with entities declared in its own XML (a "billion laughs" feed). Such a feed now fails to load at once, or its entities read as nothing.
- **A backup can no longer make home crash at every start.** A number or a switch among the settings (only an edited file has one) is left out of a restore, and one that is there anyway is dropped when Kolahal starts.
- **Script secrets survive a passing Keystore error.** Before, any error while reading the key deleted it, and every secret read as not set. Now the key is replaced only when the Keystore can't read it any more.
- **Typing is lighter**: a key press no longer redraws all of home.
- **A backup file can do less on import.** Restored log lines no longer open an app's screen or dial a number on a tap, restored feed items keep only web links, and the import result lists aliases that run code or change settings (`lua`, `js`, `=`, `config` and the like), next to the search address and gestures it already listed. An alias can have an app's name, so typing that name would run it.
- **Lua scripts are held tighter.** An error in Kolahal's own functions always reaches a script as plain text, and Java objects can do nothing inside Lua, even if one ever got there. Scripts work as before.
- **No more hitches while typing `activity`, `shortcuts` or `open app:`.** The lists they suggest from (an app's screens, its shortcuts, the apps that have shortcuts) now load in the background and show a moment later.
- **Apps are there right after a restart.** Kolahal keeps the list of apps as last read and shows it at once, while it reads them again. Before, for up to a second after a reboot or an update, app names weren't suggested and opening one said "Command not found". Private space apps aren't kept in that list.
- **Moving to a new phone with Android's transfer** no longer carries over what belonged to the old one. Calls on the new phone are logged from the start (before, they could stay out of the log for a while), and the first check of your apps doesn't log every app as installed or removed.
- **Failures you couldn't see now show in the log.** If setting reminders again after a restart, or scheduling scripts or feeds, fails, an error line says so (at most once a day for each). Before, a reminder could just not fire. A backup import names the font, widgets or script timers it couldn't restore, instead of reporting success.
